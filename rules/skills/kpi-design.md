# /kpi-design スキル

**用途:** 目標管理指標の体系（KGI→CSF→KPI）とOKR（Objectives & Key Results）を設計し、「測れる戦略」に変換する。ダッシュボード設計・レビューサイクルまで一気通貫で構築する。

---

## 発動条件

- 「KPIを設計したい」「目標管理の仕組みを作りたい」
- 「OKRを導入したい」「チームの目標を数値化したい」
- 「何を測ればいいかわからない」「指標がバラバラで管理できていない」
- 「AI導入の効果をどう測るか定義したい」

---

## フレームワーク構造

```
KGI（Key Goal Indicator）
  └─ 最終目標。事業・組織全体の成否を測る1〜2個の指標
      例：年間売上 ○億円 / 顧客満足度スコア ○点

CSF（Critical Success Factor）
  └─ KGI達成のために「必ず成功させなければならない要因」3〜5個
      例：新規顧客獲得数 / 解約率抑制 / 業務コスト削減率

KPI（Key Performance Indicator）
  └─ CSFを測定・管理するための具体的指標（CSFごとに2〜4個）
      例：月間新規リード数 / 商談化率 / 初回解約率

KDI（Key Daily Indicator）
  └─ 現場が毎日モニタリングするアクション指標（任意）
      例：架電件数 / 日次ログイン率 / 日報記入率
```

---

## ヒアリング

```
KPI体系を設計します。以下を教えてください。

1. 組織の最終目標（KGI候補）
   例：売上 / 利益率 / 顧客数 / 稼働率

2. 現在の課題（何がうまくいっていないか）

3. 対象範囲
   例：会社全体 / 事業部 / チーム / AI導入プロジェクト

4. 計測期間
   例：月次 / 四半期 / 年次

5. 現在すでに使っている指標（あれば）

6. OKRも設計するか
   YES → 四半期ベースのO（目標）とKR（成果指標）を設計
   NO  → KGI/CSF/KPI体系のみ
```

## プロセスA：KGI→CSF→KPI体系設計

### Step 1：KGI設定

```
【KGI（最終目標指標）】

KGI①：〇〇  目標値：〇〇  期間：〇〇
  測定方法：〇〇  データ取得元：〇〇

KGI②：〇〇（必要であれば）
```

### Step 2：CSF特定（イシューツリーと連携）

KGI達成を阻む要因を分解し、「ここを押さえれば達成できる」3〜5要因を特定。

```
【CSF（重要成功要因）】

CSF①：〇〇（KGIとの連鎖：〇〇が上がるとKGIが○%改善）
CSF②：〇〇
CSF③：〇〇
```

### Step 3：KPI設計（CSFごと）

```
【KPI一覧】

CSF①「〇〇」を測るKPI：
  KPI①-1：〇〇  目標値：〇〇  頻度：〇〇
    先行指標か遅行指標か：〇〇
    データ取得方法：〇〇
    責任者：〇〇

  KPI①-2：〇〇（同形式）

CSF②「〇〇」を測るKPI：
  （同形式）
```

**先行指標 vs 遅行指標の設計原則：**
- 遅行指標のみで管理すると「気づいた時には手遅れ」になる
- 各CSFに先行指標（行動を測る）と遅行指標（結果を測る）を最低1つずつ設ける

### Step 4：KPI全体マップ出力

```
【KPI全体マップ】

KGI：〇〇（目標：〇〇 / 現状：〇〇）
 │
 ├─ CSF①：〇〇
 │   ├─ KPI①-1：〇〇（先行）目標〇〇
 │   └─ KPI①-2：〇〇（遅行）目標〇〇
 │
 ├─ CSF②：〇〇
 │   ├─ KPI②-1：〇〇（先行）目標〇〇
 │   └─ KPI②-2：〇〇（遅行）目標〇〇
 │
 └─ CSF③：〇〇
     └─ KPI③-1〜2：〇〇
```

## プロセスB：OKR設計

### OKRの原則

```
O（Objective）：定性的・感情が動く目標。「〇〇な状態になる」
KR（Key Results）：Oを達成したことを証明する定量指標。3〜5個。
  - 達成可能だが挑戦的（60〜70%達成で合格ライン）
  - 測定可能な数値で書く
  - アクションではなく「結果」を書く
```

```
【OKR設計（四半期）】

O：「〇〇な状態になる」
   （この目標が達成されると何が変わるか：〇〇）

KR①：〇〇を〇〇から〇〇に引き上げる
KR②：〇〇件を達成する
KR③：〇〇率を〇〇%以下に抑える
KR④：〇〇スコアを〇〇以上にする

レビュー頻度：週次チェックイン / 月次レビュー / 四半期振り返り
```

## プロセスC：ダッシュボード設計

```
【ダッシュボード設計】

■ 経営層向け（月次・週次）
  表示指標：KGI / 主要CSF進捗 / 前月比
  形式：サマリー1枚・信号機表示（🟢🟡🔴）

■ 現場管理者向け（週次・日次）
  表示指標：担当CSFのKPI / 進捗率 / 異常値アラート
  形式：KPI別グラフ・目標値との乖離

■ 担当者向け（日次）
  表示指標：KDI（日次アクション指標）
  形式：チェックリスト形式

推奨ツール：Googleスプレッドシート（QUERY関数）/ Looker Studio / Notion
```

---

## プロセスD：レビューサイクル設計

```
【PDCAサイクル設計】

日次：KDI確認（現場担当者）→ 異常あれば即エスカレーション
週次：KPI進捗確認（管理者）→ 乖離がある場合アクション修正
月次：CSF達成度評価（経営・部門長）→ 施策の継続・変更・中止判断
四半期：KGI達成度 + OKR振り返り → 次期KPI目標値の見直し
年次：体系全体の見直し → CSF・KPIの追加・削除
```

## AI導入プロジェクトへの適用例

```
KGI：対象業務の工数を12ヶ月で40%削減

CSF①：先行チームでの定着（利用率80%以上）
  KPI：週次利用率 / 1人あたり月間活用件数

CSF②：全員展開の成功（展開完了率）
  KPI：研修完了率 / 操作自走率

CSF③：業務品質の維持（品質劣化ゼロ）
  KPI：エラー率 / 修正件数

CSF④：ROI実現（投資回収）
  KPI：月間削減時間 × 時給単価 / コンサル費用比
```
