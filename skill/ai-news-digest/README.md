## このスキルが何をやるか
https://wool-echo-e93.notion.site/05-AI-ai-news-digest-34059cb966a28154987ddb95042ef705

1. HackerNews APIから過去24時間のAI関連トップ10記事を取得
2. 各記事の要点を3行に要約
3. Markdownレポートとして生成
4. 04_Memory/ai-news-YYYY-MM-DD.md に自動保存
5. ターミナルにも全文表示

外部APIキー不要。HackerNews APIは無料・認証なし。Claudeの内蔵Webアクセスで完結します。

## 1つだけじゃ足りない — ソースを増やす

ai-news-digestはHackerNewsを1つだけ見てる。これで出発して、慣れたら情報源を増やしてくのが王道。

私の場合、最終的に7つのソースDBに分散させた。ネタが枯れる最大の原因は、情報源が自分の頭の中だけになっていること。



この7つから毎週、GitHub Actionsが自動で最新データを引っ張ってくる。面談で「Claude Codeの初期設定がわからない」って声が3件あれば、それはもう記事のネタになる。受講生が「月10万超えました」って報告してくれたら、それもネタ。

<aside>
✨ 自分の頭をひねってネタを出す必要がない。ソースDBに情報が入れば、ネタは自動で生まれる。

</aside>

## 差が出るのは「何をAIに読み込ませるか」

APIを叩くだけなら誰でもできる。

**差が出るのは、何をAIに読み込ませるか。**

私の場合、voice-guideというMarkdownファイルを作ってる。中身はこんな感じ👇

- **基本トーン**: カジュアルでありながら知的。友人と深夜に語り合うような親密さ
- **勝ちパターン**: 断定→理由→救済→一手
- **AIっぽさ排除ルール**: 7つの検出トリガーと変換テーブル
- **媒体別の温度設定**: Xは高め、noteは中、LINEは中高

これをAIに読み込ませた上で、ソースDBのデータと組み合わせてコンテンツを生成させる。

voice-guideがあるのとないのとでは、出力の質がまるで違う。ないと「〜は重要です」「さらに〜」「また〜」が連打される、どこかで見たことのある文章が出てくる。つまり、誰が書いても同じになる。

<aside>
🧬 voice-guideは「自分の声のDNA」をAIに移植するファイルだと思えばいい。

</aside>

## フィードバック学習——ここが「閉じる」ポイント

ネタが自動で出る。それだけなら「自動生成ツール」で終わる。

**閉ループが「ループ」になるのは、出力の結果が次のインプットに戻るから。**

![フィードバック学習で循環が完成する](attachment:22427ff8-3851-496c-85ed-db4972daff13:loop-03.jpg)

フィードバック学習で循環が完成する

毎日22時に「フィードバック学習」というワークフローが走る。投稿したコンテンツのパフォーマンスデータ（インプレッション、エンゲージメント、スキ数、クリック率）を収集して、「何が刺さって、何がスベったか」を分析する。

分析結果はNotion DBに蓄積される。翌日のコンテンツセッションが走るとき、このフィードバックデータも一緒に読み込まれる。

**つまり——**

> 「昨日、数字を入れたタイトルのX投稿がインプレッション3倍だった」→「今日のネタ生成でも、数字入りのフック設計を優先的に提案する」
> 

3月前半にバズったのは数字系（H5型）のフックだった。3月後半になると、システムが勝手にH5型の提案比率を上げてきた。自分が指示したわけじゃない。データが指示したんだ。

## 正直、最初は全然動かなかった

最初の2週間は地獄だった。

- GitHub Actionsがvoice-guideを読まないまま走って、AIっぽさ全開の出力が量産された
- Notion APIで日本語を送ると404エラー。Unicodeエスケープが必要だと気づくまで3時間溶けた
- フィードバック学習が、パフォーマンスデータの取得に失敗して空回り。原因はNotion DBのIDが3ワークスペースで混在していたこと

151コミットの大半は、こういうバグ修正と試行錯誤。最終的に安定したのは3月の最終週。そこからようやく「寝てる間にネタが5件並んでる」状態になった。

![10本のワークフローが噛み合って1つの閉ループに](attachment:498fd970-697d-45a7-99b4-9dab3aa9292b:loop-04.jpg)

10本のワークフローが噛み合って1つの閉ループに

全部を最初から作る必要はない。私もコンテンツセッション（ネタ生成）から始めて、うまく回り始めてからフィードバック学習を足した。

<aside>
🎯 **最初の1本は「ネタの自動生成」だけでいい。**それがai-news-digestです。そこが回り始めたら、計測と学習を足していけばいい。

</aside>

## これを自分で組むなら、何から始めるか

10本のワークフローをいきなり組むのは無理。でも、閉ループの「最小構成」はシンプル。

![最小構成の閉ループ（3ステップ）](attachment:367c2740-9244-433a-b5c4-3e2dcfd12ee4:loop-05.jpg)

最小構成の閉ループ（3ステップ）

### ステップ1: voice-guideを作る

自分の声のルールをMarkdownで書き出す。最低限、以下の3つ。

- 基本トーン（カジュアル？フォーマル？誰に向けて？）
- 禁止表現（「〜は重要です」みたいなAI臭い表現リスト）
- 勝ちパターン（自分の記事で反応が良かった構成パターン）

### ステップ2: ソースを1つ決める

7つも要らない。1つでいい。このai-news-digestスキルはHackerNewsがソース。これで最初は十分。

### ステップ3: Claude APIでネタ生成を回す

voice-guide + ソースデータをClaude APIに渡して、ネタ候補を出させる。最初はGitHub Actionsじゃなくて、手動で回せばいい。

この3ステップで「半自動の閉ループ」が回り始める。あとは、使いながら自動化の範囲を広げていけばいい。

## 「努力で続ける」をやめろ

コンテンツ制作を「毎日頑張って書く」で乗り切ろうとしている人が多すぎる。

意志力は有限だ。モチベーションは波がある。忙しい日は書けない。体調が悪い日も書けない。

**でも仕組みは、自分が寝ていても動く。**

3月、自分はシステム構築に77コミットを費やした。その間、コンテンツの投稿本数は目標を下回った。短期的にはマイナス。

でも今、毎朝5件のネタがNotionに並んでいる。「今日は何を書こう」と悩む時間がゼロになった。

<aside>
🧠 **努力を否定しているんじゃない。努力の向け先を変えろ**って話。コンテンツを書く努力じゃなくて、コンテンツが生まれる仕組みを作る努力をしろ。1回作れば、あとは回る。

</aside>
