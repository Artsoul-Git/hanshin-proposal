1. ライモBizミニアプリの仕組み（前提知識）

ライモBizツールズのミニアプリは、HTML/CSS/JavaScript のコードをライモBizのコード入力欄に貼り付けると動くWebアプリです。プラットフォームがサンドボックス環境として機能します。

コード修正の方法
修正規模方法備考
大規模コード全体を生成し直して全置換Claude Codeで全コード出力 → 貼り替え
細かい修正置換ボタン（改修前/改修後コードを貼り付け）軽微な変更向け。出力コスト節約
機能追加「改修用プロンプト」機能を使うライモBiz内のAIが差分コードを生成

4. パターン③（推奨）のアーキテクチャ詳細
✅ このアーキテクチャの最大のメリット：ライモBizには個人情報が一切渡らない。マスキング・AI処理・復元はすべてGAS側で完結するため、セキュリティが高い。
5. 唯一の事前検証ポイント：ライモBiz → GAS への fetch() 通信

このアーキテクチャの実現可否は「ライモBizのサンドボックス内のJavaScriptから、外部URL（GAS Web App）へのHTTPリクエストが通るか」一点にかかっています。

ℹ️ GAS側はCORSを許可できます。問題はライモBizのサンドボックスが外部へのfetch()を許可しているかどうかです。
検証手順（所要時間：約30分）
STEP 1
GASテスト用Web Appを用意
下記のGASコードをGoogleスプレッドシートのApps Scriptに貼り付け、「ウェブアプリとしてデプロイ」→「全員」に公開してURLを取得する。
STEP 2
ライモBizにテストアプリを新規作成
ライモBizで新規ミニアプリを作成し、下記のテスト用HTMLコードを貼り付ける（既存アプリは変更しない）。GAS Web AppのURLを入力欄に入力してボタンをクリック。
STEP 3：成功パターン
「接続成功」と表示される
→ パターン③（ハイブリッド）で確定。本番開発に進む。
STEP 3：失敗パターン
CORSエラー / 接続失敗
→ ライモBizのサンドボックスが外部通信をブロック。パターン②（GAS単独）に切り替えてUIをGAS Web Appで作る。
GAS側テストコード（Apps Scriptに貼り付け → デプロイ）
// GAS Web App テスト用（全員アクセス可能でデプロイ） function doPost(e) { const received = JSON.parse(e.postData.contents); const result = { status: 'success', message: 'GAS Web Appへの接続成功！', received: received, timestamp: new Date().toISOString() }; const output = ContentService.createTextOutput(JSON.stringify(result)); output.setMimeType(ContentService.MimeType.JSON); return output; } // GETでもアクセスできるようにしておく（デプロイ確認用） function doGet(e) { return ContentService.createTextOutput('GAS接続OK'); }
ライモBiz側テスト用HTMLコード（新規ミニアプリに貼り付け）
<!-- HTML部分 --> <div style="padding:20px; font-family:sans-serif;"> <h3>GAS接続テスト</h3> <label>GAS Web App URL：</label><br> <input id="gasUrl" type="text" placeholder="https://script.google.com/macros/s/..." style="width:100%;padding:8px;margin:8px 0;"> <button onclick="testConnection()" style="padding:10px 20px;background:#2B6CB0;color:white;border:none;border-radius:6px;cursor:pointer;"> 接続テスト実行 </button> <div id="result" style="margin-top:16px;padding:12px;border-radius:6px;display:none;"></div> </div> <!-- JavaScript部分 --> <script> async function testConnection() { const url = document.getElementById('gasUrl').value.trim(); const resultDiv = document.getElementById('result'); resultDiv.style.display = 'block'; resultDiv.style.background = '#EBF8FF'; resultDiv.textContent = '接続中...'; try { const res = await fetch(url, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ test: 'hello from ライモBiz' }) }); const data = await res.json(); resultDiv.style.background = '#F0FFF4'; resultDiv.style.border = '1px solid #9AE6B4'; resultDiv.innerHTML = '✅ <strong>接続成功！</strong><br>' + JSON.stringify(data, null, 2); } catch(err) { resultDiv.style.background = '#FFF5F5'; resultDiv.style.border = '1px solid #FC8181'; resultDiv.innerHTML = '❌ <strong>接続失敗</strong><br>' + err.message; } } </script>
6. 検証結果による最終方針
検証結果採用アーキテクチャ次のアクション
✅ 接続成功 パターン③ ハイブリッド
ライモBizフロント + GASバックエンド		 まる様用のライモBizミニアプリ本番コードを作成
GAS側はmasking.gs + ai_generator.gsを実装
❌ 接続失敗 パターン② 改良版
GAS Web App + Sheets（UIもGASで作る）		 GAS doGet()でスマホ対応HTMLを返すUIを設計
AppSheetでUIを代替する方法も検討
※ 検証は新規ミニアプリを作成して実施（既存のMyミニアプリは変更しない）。GAS Web AppのURLは毎回デプロイごとに変わるため、本番では固定URLになるよう「デプロイを管理」から同じデプロイを更新する。
