# /seminar-dna スキル
**セミナー事業部 — セミナーの型を抽出・命名・ライブラリ化するメタスキル**

**用途:** セミナーの文字起こし・参照資料からセミナーの「型（DNA）」を抽出・命名・テンプレート化し、任意のテーマ・ゴール・ターゲットに対して同じスタイルのセミナーを再現できるパターンライブラリを構築する。

**保存先:**
- パターン定義: `rules/seminar-patterns/<パターン名>.md`
- 台本テンプレート: `rules/seminar-patterns/<パターン名>_template.md`
- パターン一覧: `rules/seminar-patterns/INDEX.md`

---

## このスキルの設計哲学

> **セミナーの「うまさ」は偶然ではなく型に宿る。その型を言語化すれば、テーマが変わっても同じ熱量・説得力・体験が再現できる。**

- 文体・話し口調・流れは著作権の対象外。抽出・再設計は合法
- 「何を話すか」ではなく「どう設計するか」を型として保存する
- パターンに名前がつくと呼び出せる。名前がない型は使われない
- 1つのパターンから複数のテーマ・ターゲット向けセミナーを量産できる

---

## 2つのモード

| モード | 呼び出し方 | 用途 |
|--------|-----------|------|
| `extract` | `/seminar-dna`（素材を渡す） | 文字起こし・参照資料からDNAを抽出して命名・保存 |
| `apply` | `/seminar-dna apply <パターン名>` | 保存済みパターンを使って新しいセミナーを生成 |

モードが不明な場合は、ユーザーに確認してから進む。

---

## extractモード（型の抽出・命名）

### STEP 1: 素材の受け取り・読み込み

ユーザーからファイルパスまたはテキストを受け取る。

```
対応素材:
- セミナーの音声文字起こし
- セミナーの台本・レジュメ・スライド構成メモ
- 参加者が体験したメモ・参加録
- 複数素材の組み合わせ
```

**読み込みルール:**
- 大きいファイルは `offset` / `limit` を使って分割読み込み
- 一度に全部読もうとしない（コンテキスト圧迫防止）
- 読み込み完了後、素材の種別・セミナーの大まかなテーマをユーザーに確認

---

### STEP 2: DNA 7軸分析

素材全体を読み込んだ後、以下の7軸でセミナーの構造を分析する。

```
【DNA分析フレーム】

① オープニングDNA
   - 冒頭フックの種類（問いかけ型・共感型・数字型・物語型・宣言型）
   - 自己紹介のタイミングと長さ
   - 信頼を築くまでのプロセス

② 構造DNA
   - セクション数と各セクションの役割
   - 論理フロー（問題→解決型 / 理論→実践型 / 感情→理性型 など）
   - 転換点（話が切り替わるタイミングと手法）

③ エンゲージメントDNA
   - 聴衆参加の仕掛け（質問・挙手・ワーク・対話の種類と頻度）
   - 笑いや感情開放のタイミング
   - 「あるある」共感の引き出し方

④ 感情カーブDNA
   - 感情の設計（共感→不安→希望→確信→行動 など）
   - テンション上下のリズム
   - 感情のピークをどこに置くか

⑤ コンテンツ比率DNA
   - 理論：体験談：数字：問いかけ の配分（目安で10段階）
   - 具体事例の出し方（先出し型・後出し型・交互型）
   - 専門性の見せ方

⑥ クロージングDNA
   - CTAの種類と数（1つに絞るか・段階的か）
   - 「今すぐ動く理由」の作り方
   - 余韻・反芻の設計

⑦ 話し言葉DNA
   - 口調・文体（断定型・問いかけ型・語りかけ型）
   - キーフレーズのパターン（反復・体言止め・感嘆など）
   - 「間」の使い方
   - テンポ（ゆっくり説得型・テンポよく熱血型・対話型）
```

分析完了後、結果を以下の形式でまとめる：

```
[DNA分析サマリー]
セミナーテーマ: ○○
素材: ○○（文字起こし○○字）

① オープニングDNA: ○○
② 構造DNA: ○○（セクション数：○個）
③ エンゲージメントDNA: ○○
④ 感情カーブDNA: ○○
⑤ コンテンツ比率DNA: 理論○：体験○：数字○：問いかけ○
⑥ クロージングDNA: ○○
⑦ 話し言葉DNA: ○○

このスタイルの「型」として命名の候補:
  A. [候補1]
  B. [候補2]
  C. [候補3]

どれにしますか？（または別の名前を指定してください）
```

---

### STEP 3: パターン命名

**命名ルール:**
- 5〜15文字程度。「○○型」で終わる
- 型の「最大の特徴」を1〜2語で表す
- 他のパターンと見分けがつく名前にする
- 難しい専門用語は使わない

**命名例（参考）:**
| 名前 | 特徴 |
|------|------|
| 共感ファースト型 | 課題共感から始めて解決策を積み上げる |
| 問題解体型 | 複合課題を細分化して1つずつ潰す |
| ストーリー旅型 | 物語の起承転結に沿って体験させる |
| 証拠積み上げ型 | 数字・事例・論理を重ねて確信に導く |
| 対話引き込み型 | 問いかけで聴衆を思考させながら展開 |
| 熱血実演型 | 実演・体験ワーク中心、即使えるを体感させる |

ユーザーが命名を承認したら STEP 4 へ進む。

### STEP 5: 台本テンプレート生成

**保存パス:** `rules/seminar-patterns/<パターン名>_template.md`

テンプレートは「固定パーツ」と「変数プレースホルダー」で構成する。

```
変数プレースホルダー:
  {{テーマ}}      ← セミナーのテーマ・業種
  {{ゴール}}      ← 参加者に達成してほしいこと
  {{ターゲット}}  ← ターゲット受講者の属性
  {{事例}}        ← 具体的な成功事例・数字
  {{CTA}}         ← 最終的なアクション
  {{あるある}}    ← ターゲットに刺さる共感ネタ
  {{ROI}}         ← 数字で表す価値・効果
```

テンプレート構成：
```markdown
# 【{{テーマ}}】セミナー台本テンプレート（<パターン名> スタイル）

**対象:** {{ターゲット}}
**ゴール:** {{ゴール}}
**想定時間:** ○分

---

## オープニング（○分）
> [固定構造の説明]

---（以下、DNA定義に基づいたセクション構成が続く）---
```

## applyモード（パターンを使ってセミナーを生成）

### STEP A1: パターン選択・確認

```bash
# 保存済みパターン一覧を表示
Read rules/seminar-patterns/INDEX.md
```

パターン一覧を提示し、ユーザーに選ばせる。
または `/seminar-dna apply <パターン名>` で直接指定された場合はそのパターンを使う。

---

### STEP A2: ヒアリング（1回で聞き切る）

```
「<パターン名>」スタイルでセミナーを設計します。以下を教えてください。

■ 変数情報（必須）
1. テーマ: このセミナーで扱う具体的なテーマ・業務領域
2. ゴール: 参加者にこのセミナーを終えて何を達成してほしいか（1文で）
3. ターゲット: 誰に向けたセミナーか（職種・業種・知識レベル）

■ 調整情報（任意）
4. 所要時間: （例：60分 / 90分）デフォルト: 60分
5. 強調したいポイント: DNA定義の中で特に強めたい軸があれば
6. 使える具体事例・数字があれば（なければKaiが汎用的な数値で設計）
7. CTA（最後に取ってほしいアクション）があれば
```

---

### STEP A3: 台本生成

テンプレートの変数を埋め、パターン定義に従って台本を生成する。

**生成物:**
```
- セクション構成（全体アウトライン）
- 各セクションの詳細台本（話し言葉）
- エンゲージメント仕掛けの具体的な設計
- CTA設計
```

生成後に `/seminar-slide` との連携オプションを提示する：

```
台本ができました。
→ スライドに変換しますか？（/seminar-slide に引き渡せます）
→ トークスクリプトのみ保存しますか？
```

---

### STEP A4: 適用実績の記録

パターンファイルの「適用実績」テーブルに1行追加する。

```markdown
| YYYY-MM-DD | {{テーマ}} | {{ターゲット}} | <生成ファイルパス> |
```

## 品質チェックリスト

### extract完了時
- [ ] 7軸DNA分析がすべて埋まっているか
- [ ] パターン名が5〜15文字・他と区別できるか
- [ ] テンプレートに変数プレースホルダーが正しく設定されているか
- [ ] INDEX.mdが更新されているか
- [ ] 著作権に触れる表現（verbatim copy・固有名詞）がパターン定義に含まれていないか

### apply完了時
- [ ] パターンの7軸DNAがすべて台本に反映されているか
- [ ] 変数プレースホルダーが残っていないか（すべて埋まっているか）
- [ ] 感情カーブDNAに従った構成になっているか
- [ ] CTAが1つに絞られているか
- [ ] 適用実績テーブルが更新されているか
