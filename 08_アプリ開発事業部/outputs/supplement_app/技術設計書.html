フロントエンド（HTML/CSS/JS）は一切変更せず、API接続先だけを切り替えることで、開発環境と本番環境を分離します。

切り替えの仕組み（config.js 1ファイルだけ）

フロントエンドの config.js に接続先URLを書くだけ。URLを変えればどちらの環境でも動く。

// config.js — これ1ファイルを変えるだけで環境が切り替わる // ======= 開発環境 ======= const CONFIG = { API_BASE: 'https://script.google.com/macros/s/AKfyc.../exec', // GAS URL APP_NAME: '[APP_NAME]', ENV: 'dev' }; // ======= 本番環境（Xserverに切り替え時） ======= // const CONFIG = { // API_BASE: 'https://your-domain.com/api', // XserverのPHP URL // APP_NAME: '[APP_NAME]', // ENV: 'prod' // };
フロントエンドのAPI呼び出し（共通）
// app.js — CONFIG.API_BASE に投げるだけ。環境を意識しない書き方 async function saveDailyLog(data) { const res = await fetch(`${CONFIG.API_BASE}?action=saveDailyLog`, { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(data) }); return res.json(); }
✅ この設計により、フロントエンドのHTML/CSS/JSは開発〜本番で完全に同一ファイルを使える。Xserver移行時の修正作業はほぼゼロ。

4. MySQL スキーマ（Xserver 本番用）

Google Sheets の6シートをそのままMySQL 6テーブルに対応させます。カラム構成は変えないため、移行時のデータ移行が簡単です。

-- ② 日次記録 CREATE TABLE daily_log ( log_id VARCHAR(30) PRIMARY KEY, user_id VARCHAR(20) NOT NULL, log_date DATE NOT NULL, weight DECIMAL(5,1), mood TINYINT, -- 1〜5 cond TINYINT, -- 1〜5（conditionは予約語のため） taken BOOLEAN DEFAULT FALSE, memo VARCHAR(200), created_at DATETIME DEFAULT CURRENT_TIMESTAMP, UNIQUE KEY uk_user_date (user_id, log_date), FOREIGN KEY (user_id) REFERENCES users(user_id) ); 計算アルゴリズム（biorhythm.js）
// biorhythm.js — 生年月日から3つのサイクルを計算 function calcBiorhythm(birthdate, targetDate) { const msPerDay = 86400000; const days = Math.floor((targetDate - birthdate) / msPerDay); // 3つのサイクル（標準バイオリズム周期） const physical = Math.sin(2 * Math.PI * days / 23); // 体力（23日） const emotional = Math.sin(2 * Math.PI * days / 28); // こころ（28日） const vitality = Math.sin(2 * Math.PI * days / 33); // エネルギー（33日） return { physical: { score: Math.round((physical + 1) * 50), phase: getPhase(physical) }, emotional: { score: Math.round((emotional + 1) * 50), phase: getPhase(emotional) }, vitality: { score: Math.round((vitality + 1) * 50), phase: getPhase(vitality) } }; } // -1〜1の値を4フェーズに変換 function getPhase(value) { if (value > 0.5) return 'peak'; // 好調期 if (value > 0) return 'rising'; // 上昇期 if (value > -0.5) return 'falling'; // 調整期 return 'low'; // 充電期 } // フェーズ別メッセージ（体重増加への言い訳を科学的に提供） const MESSAGES = { physical: { peak: '⭐ 体力絶好調！運動しやすい最高の時期です', rising: '🌱 体力が上がってきています。軽めの運動がおすすめ', falling: '🍃 体が休みたがっています。無理は禁物', low: '💙 充電期間中。サプリで栄養をしっかり補給して' }, emotional: { peak: '⭐ 気分爽快！前向きな気持ちが続いています', rising: '🌱 気持ちが前向きになってきています', falling: '🍃 少し感情が揺れやすい時期。食欲に注意して', low: '💙 メンタル充電中。焦らずゆっくりいきましょう' }, vitality: { peak: '⭐ エネルギーMAX！サプリの効果を感じやすい時期', rising: '🌱 エネルギーが回復してきました', falling: '🍃 エネルギーが落ち着く時期。体重増加もリズムのひとつ', low: '💙 次の好調期に向けて体が準備しています' } };

6. API エンドポイント設計

GAS（開発）とPHP（本番）で同じエンドポイント仕様を実装します。フロントエンドはどちらのバックエンドかを意識しません。

POST?action=login
トークン認証。token を受け取り、ユーザー情報を返す。
POST?action=setupProfile
初期設定保存。体重・目標・誕生日等。
POST?action=saveDailyLog
日次記録の保存。同日の記録は上書き。
GET?action=getDailyLogs
過去N日分の記録取得。グラフ用。
GET?action=getReports
週次レポート一覧取得。最新5件。
GET?action=openReport
レポート開封記録（opened_atを更新）。
GET?action=getContent
コンテンツ一覧取得。カテゴリフィルター対応。
GET?action=getBiorhythm
今日のバイオサイクル計算結果取得。
POST?action=createUser 🔒
【管理者】新規会員登録 + 招待メール送信。
GET?action=getUsers 🔒
【管理者】会員一覧取得。
POST?action=approveTestimonial 🔒
【管理者】体験談承認 + クーポン送信。
POST?action=generateReports 🔒
【管理者】全会員の週次レポート一括生成・送信。

🔒 = 管理者トークン必須

7. GitHub → Xserver 移行手順

Phase 1〜2をGitHub + GASで動かし、本番移行の準備ができたら以下の手順でXserverに切り替えます。

Xserverでデータベースを作成
Xserverのサーバーパネル → 「MySQL設定」→「MySQLデータベース追加」。DBユーザーとパスワードも設定。
テーブルを作成（SQLを実行）
phpMyAdmin（Xserverに標準搭載）で上記の CREATE TABLE SQL を全て実行。完了したら「テーブル一覧」で6テーブルを確認。
config.php をアップロード（gitには入れない）
api/config.php にDB接続情報を記述。このファイルは .gitignore に必ず追加してGitHubには上げない。
<?php
define('DB_HOST', 'localhost');
define('DB_NAME', '[データベース名]');
define('DB_USER', '[ユーザー名]');
define('DB_PASS', '[パスワード]');
define('GEMINI_API_KEY', '[APIキー]');
define('LINE_TOKEN', '[LINEトークン]');
define('ADMIN_TOKEN', '[管理者トークン]'); // 自分で決める
PHPファイルをXserverにアップロード
Xserverのファイルマネージャー（または FTP）で api/ フォルダ内のPHPファイルをアップロード。
Google Sheetsのデータをエクスポート → MySQLにインポート
管理者画面のCSVエクスポート機能 → phpMyAdminの「インポート」からCSV読み込み。開発中のデータを本番DBに移行。
config.js の API_BASE を Xserver の URL に変更
// config.js の1行を変更するだけ
API_BASE: 'https://your-domain.com/api',
フロントエンドのHTML/CSS/JSをXserverにアップロード
GitHubの全ファイルをそのまま public_html/ にアップロード。config.jsだけ書き換え済みのものをアップ。
動作確認 → ドメイン設定
Xserverの一時URLで全機能テスト完了後、本番ドメインをDNS設定。SSL証明書はXserverの「無料独自SSL」を有効化。
✅ 移行作業の実質的な工数は「config.php 作成（30分）+ SQLインポート（1時間）+ ファイルアップロード（30分）」のみ。フロントエンドの修正はゼロ。
