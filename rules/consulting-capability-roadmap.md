### 🔷 長期課題（9.8点へ・技術的投資が必要）

| 能力 | 概要 | 現在の制約 |
|------|------|----------|
| 業界別ベンチマークDB | 業種別の粗利率・人件費比率・成長率の相場 | 公開データのみ・非公開DBへのアクセス不可 |
| 財務諸表の自動読み込み分析 | PDFや画像の決算書を読んで分析する | PDF読み込みは可能・構造化分析の精度向上が必要 |
| 過去案件ナレッジの蓄積 | Kaiが支援した案件の成功・失敗パターンを記憶する | `memory/` への案件ナレッジ蓄積の仕組みが必要 |
| リアルタイム業界ニュース統合 | 市場変化を自動検知してアドバイスを更新する | 定期的な `/research` 実行で代替可能 |

### ❌ 永続的な制約（AIには代替不可）

| 能力 | 理由 |
|------|------|
| 法的判断・コンプライアンス保証 | 法的責任はライセンス保有の専門家のみ |
| 非公開情報・内部資料へのアクセス | ユーザーが提供した範囲のみ参照可能 |
| 物理的な現場実装・チェンジマネジメント | 人間の存在が必要 |
| 署名・捺印が必要な書類の発行 | 法的効力は人間が持つ |
| クライアントとの信頼関係・ブランド | Kaiはツール。上村が持つもの |

## 9.5点到達のための実装優先順位

### Priority 1：イシューツリー分析（最も汎用性が高い）

```
/issue-tree スキル（新設）

問題を「So What?」「Why So?」「How?」で分解し、
本当に解くべき課題（クリティカルイシュー）を特定する。
MECEチェック付きで論理の漏れを自動検出。

→ /marketing・/profit-plan・/sme-ai-proposal すべての前処理として機能
```

### Priority 2：ステークホルダー分析

```
/sme-ai-proposal への統合

「誰が意思決定するか」「誰が反対するか」「誰を先に動かすか」を
影響力×関心度マトリクスで整理し、攻略シナリオを設計する。

→ 特にAI導入支援提案でクリティカルな要素
```

### Priority 3：案件ナレッジの蓄積ルール整備

```
memory/ への案件ログ記録ルール

クライアント支援完了後、以下を記録：
- 業種・規模・課題のパターン
- 刺さった提案アプローチ
- 失敗したアプローチと理由

→ 積み重ねるほどKaiの「経験値」が上がる構造
```

## 結論：「コンサルファームの代替」の正しい定義

Kaiは「フルサービスのコンサルファーム」にはなれないが、
**「中小企業・スタートアップが大手ファームに頼む案件の80%を、1/100のコストと1/10の時間で解決できるパートナー」** にはなれる。

大手ファームが強いのは：大企業のM&A・規制対応・組織変革・IPO準備
Kaiが代替できるのは：戦略立案・事業計画・市場調査・提案書・財務モデル・マーケティング設計

**これは「劣化版コンサル」ではなく「中小企業向けの最適解」。**
