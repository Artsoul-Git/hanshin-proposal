# company-setup スキル — AI組織ゼロベース設計

## 目的

どんな業種・業態のオーナーとも、**ゼロから対話して** そのオーナー専用のAI組織（憲法・ルール・スキル・管理フォルダ）を設計・構築する。

- アートソウル固有の情報はハードコードしない
- オーナーが変わっても・業種が変わっても同じスキルで対応する
- 作成物はそのままプロジェクトルートに配置して即日運用できる品質にする

---

## 起動時の挨拶（必ず最初に表示）

```
こんにちは。company-setup スキルを起動しました。

これからあなた（オーナー）の事業・コンセプト・課題をヒアリングして、
専用のAI組織設計一式を作成します。

所要時間：
  ・ファイル記入モード → 記入15〜30分 ＋ Kai生成10分
  ・壁打ちモード      → 対話30〜60分（記入不要）

まず5つの基本情報を教えてください。
```

---

## Step 1：基本情報の収集（起動直後）

以下の5項目をオーナーに聞く。一度に全部聞いて構わない。

```
【基本情報 5項目】

① 事業・会社名（正式名称 または 仮称）
② 主な業種・業態
   例：障害福祉 / 歯科クリニック / 製造業（金属加工）/ 士業（税理士） / EC / 飲食 など
③ ターゲット顧客・利用者
   例：障害者（手帳所持）/ 地域患者 / BtoB中小企業 / 個人消費者 など
④ 規模感（現在）
   例：スタッフ5名・利用者30名 / 従業員12名・年商2億 など
⑤ 現在の最大の課題・悩み（3つ以内で）

これらをまとめて教えていただくか、
「壁打ちモードで一緒に整理したい」とお伝えください。
```

## Step 3：進行モードの選択提示

ヒアリングシートを保存したら以下を提示する：

```
ヒアリングシートを生成しました。
保存先：setup_[事業名]_[日付]/hearing_sheet.md

進め方を選んでください：

  A) ファイル記入モード
     → シートのB〜C欄を記入してから「記入しました」と送ってください。
        Kaiがシートを読んで設計に入ります。

  B) 壁打ちモード
     → このまま会話で一緒に整理します。
        記入不要。Kaiが質問しながら情報を引き出します。
        （所要時間の目安：30〜60分）

どちらにしますか？
```

---

## Step 4A：ファイル記入モード

「記入しました」「Aで」などの合図を受け取ったら：

1. `hearing_sheet.md` を Read で読み込む
2. B-1〜B-6 の空欄率を確認する
3. **空欄が3項目以下** → Step 5（設計フェーズ）に進む
4. **空欄が4項目以上** → 未記入箇所だけ壁打ちで補完する（「B-2のオペレーション現状だけ教えてください」）

---

## Step 4B：壁打ちモード

B-1〜B-6の内容を**自然な会話**で聞き出す。

### 壁打ちの進め方

- 一度に聞くのは**1〜2項目**まで（情報過多にしない）
- オーナーの回答に対して**深掘り質問**を1つ加える
- 「なぜそれが課題なのですか？」「その業務は誰がやっていますか？」
- 全項目が埋まったら「情報が揃いました。設計に入ります」と宣言してStep 5へ

### 壁打ち中のKaiの役割

- 単なる質問者ではなく、**業種知識・AI事例をもとに仮説を投げる**
  例：「障害福祉の場合、記録業務が月に××時間かかることが多いです。御社はどうですか？」
- オーナーが気づいていない課題を**さりげなく提示する**
- 矛盾があれば「〇〇とおっしゃっていましたが、△△と少し矛盾があるように見えます。どちらが優先ですか？」と確認

---

## Step 5：AI組織設計（生成フェーズ）

情報が揃ったら設計を開始する。以下の成果物を順番に生成・保存する。

### 生成順序と保存先

```
setup_[事業名]_[日付]/
├── hearing_sheet.md          （既存・更新）
├── CONSTITUTION.md            ← Step 5-1
├── CLAUDE.md                  ← Step 5-2
├── rules/
│   ├── self-validation-protocol.md  ← Step 5-3
│   └── kai-style-guide.md           ← Step 5-4（空テンプレ）
├── skill/
│   └── project-intake/
│       └── SKILL.md           ← Step 5-5
├── 01_経営管理/
│   ├── 構造改革ロードマップ.md ← Step 5-6
│   └── 自律レベル記録.md       ← Step 5-7
└── 05_クライアント案件/
    └── 00_Kaiスターターパック_テンプレート.md  ← Step 5-8
```

### 各ファイルのカスタマイズ方針

#### CONSTITUTION.md
- §1 ミッション：オーナーの言葉から抽出した「なぜこの事業をするか」を入れる
- §3 判断権限マトリクス：業種固有の「絶対に確認が必要なこと」を追加
  例：医療→患者情報の外部共有、福祉→個人支援計画の変更、など
- §4 データ取り扱い：業種の規制・個人情報ルールを反映

#### CLAUDE.md
- プロジェクト概要は実際の事業内容で記述
- スキル一覧は実際に必要なスキルのみ記載（不要なものは省く）
- AIパートナー名：デフォルト「Kai」だが変更可

#### skill/project-intake/SKILL.md
- ルーティング先早見表をその事業のスキル構成に合わせる

#### 01_経営管理/構造改革ロードマップ.md
- Phaseタイムラインを現在の規模・課題に合わせて調整
- L1-L4自律レベルの基準も業種リスクに応じてカスタマイズ

## Step 6：Kai自己検証

`rules/self-validation-protocol.md` に基づき、生成した全ファイルを検証する。

### 検証チェックリスト

```
【company-setup 自己検証】

C1. 根拠チェック
  ✅/⚠️ ヒアリングシートに根拠のない数値・固有名詞が入っていないか
  ✅/⚠️ 業種固有の規制・リスクが CONSTITUTION に反映されているか

C2. 整合性チェック
  ✅/⚠️ CLAUDE.md のスキル一覧と実際に生成した skill/ が一致しているか
  ✅/⚠️ ミッション文がオーナーの言葉と矛盾していないか

C3. 構成チェック
  ✅/⚠️ 最低限必要な7ファイルが全て生成されているか
  ✅/⚠️ 各ファイルの「アートソウル固有情報」が削除・汎用化されているか

オーナー固有チェック
  ✅/⚠️ オーナーが「絶対に任せてはいけない」と言ったことが CONSTITUTION §3 に入っているか
  ✅/⚠️ 業種の「あるある失敗パターン」への対策が設計に含まれているか
```

問題があればその場で修正してからオーナーへ提示する。

## 注意事項

- **情報のハードコード禁止**：アートソウル・上村・artsoul.jp などは生成物に入れない
- **架空情報の禁止**：オーナーが言っていない数値・事例を入れない
- **個人情報の匿名化**：スタッフ名・顧客名は「担当者A」「利用者B」形式に
- **CONSTITUTION 改訂は確認後**：生成後にオーナーが内容を確認・承認してから git commit を促す
