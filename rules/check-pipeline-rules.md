# チェックパイプライン運用ルール v1.0

作成：有限会社アートソウル / Kai  
最終更新：2026-05-10

---

## 1. パイプライン全体図

```
専門スキル（成果物作成）
    ↓
[自動 / 手動] fact-check（法務部）
    ↓ 合格のみ通過
[自動 / 手動] persona-review（ペルソナ品質部）
    ↓ 合格のみ通過
Kai 最終確認レポート生成
    ↓
上村へ提出
```

### 既存の self-validation との役割分担

| スキル | タイミング | 役割 | 視点 |
|--------|----------|------|------|
| `self-validation-protocol` | 作成中〜完成直後 | Kai内部の品質チェック | 構成・整合・上村修正予測 |
| `fact-check` | 完成後（self-validation通過後） | 外部事実との照合・法的リスク | 独立した批判的検証者 |
| `persona-review` | fact-check通過後 | ターゲット視点での伝達品質 | ペルソナ読者 |

**実行順序：** self-validation → fact-check → persona-review → 上村提出

## 2. 自動起動の対象（クライアント向け成果物）

以下の成果物は各作成スキルの完了時に **fact-check → persona-review を自動起動** する：

| 成果物 | 作成スキル | 自動チェック |
|--------|----------|------------|
| 提案書 HTML | `/sme-ai-proposal` | fact-check → persona-review |
| Brain記事 | `/write-brain-article` | fact-check → persona-review |
| AI組織設計一式 | `/company-setup` | fact-check のみ（内部文書のためpersona-reviewは手動） |
| セミナー資料 | 各スキル | fact-check → persona-review |

## 3. 手動呼び出しの対象（内部文書）

以下は手動で呼び出す：

| 成果物 | 手動呼び出しコマンド |
|--------|-------------------|
| マニュアル・ガイド | `/fact-check [パス]` または `/persona-review [パス]` |

## 4. 差し戻しルール（無限ループ防止）

### CHECK_COUNTの管理

各チェックセッションで `CHECK_COUNT` を追跡する。
ファイルそのものには埋め込まない（メタ情報として会話コンテキストで管理）。

```
CHECK_COUNT = 0  通常チェック実行
CHECK_COUNT = 1  1回目差し戻し済み → 指摘箇所のみ再チェック
CHECK_COUNT = 2  2回目差し戻し済み → Kai直接修正 → 自己再チェック
CHECK_COUNT = 3  エスカレーション → ループ停止 → 上村判断
```

### ループ停止の条件（いずれか1つ）

- CHECK_COUNT が 3 に達した
- 「解決に外部情報・上村の判断が必要」とKaiが判断した
- エスカレーション後、上村から「このまま進めてよい」の指示が出た

### エスカレーション後の処理

上村から「進めてよい」の指示が出た場合：
- CHECK_COUNT をリセット（0に戻す）
- 残課題を成果物の末尾または別ファイルに明記して進める
- ログにエスカレーション理由と上村の判断を記録する

## 5. ログ管理ルール

### フォルダ構造

```
logs/
├── 2026-05/
│   ├── fact-check_20260510_1430_まるv11.md
│   ├── persona-review_20260510_1445_まるv11.md
│   └── ...
├── 2026-06/
│   └── ...
└── archive/
    └── 2026-02/  ← 90日経過したものを移動
```

### 命名規則

```
[スキル名]_[YYYYMMDD]_[HHMM]_[成果物名略称].md

例：
fact-check_20260510_1430_まるv11.md
persona-review_20260510_1445_まるv11.md
fact-check_20260601_0930_Brain記事_GAS入門.md
```

### ログの保存タイミング

- 合格・差し戻し・エスカレーション、いずれの判定後も必ず保存する
- 差し戻し後の再チェックは**新規ログ**として保存する（上書きしない）

### 90日アーカイブルール

- 90日を超えたログフォルダ（`YYYY-MM/`単位）を `archive/` 配下に移動する
- アーカイブは削除ではなく移動。削除する場合は上村確認が必要（CONSTITUTION §3）
- アーカイブのタイミング：月1回、月初のセッションで確認・実行

### ログに含める必須項目

```markdown
# [スキル名] ログ
日時：YYYY-MM-DD HH:MM
対象：[ファイルパス]
判定：合格 / 差し戻し[n回目] / エスカレーション
CHECK_COUNT：[n]

## 結果サマリー
[各軸の結果]

## エビデンスURL（fact-checkのみ・あれば）
- [項目]：[URL] ※[YYYY-MM-DD]時点の情報

## 差し戻し・改善内容
[あれば記載]

## エスカレーション記録
[あれば：問題内容・上村の判断・対処方針]
```

## 6. Kai最終確認レポート

fact-check と persona-review が両方合格した後、Kaiが以下のレポートを生成して上村に提出する：

```
【Kai最終確認レポート】
成果物：[ファイル名・バージョン]
提出日時：[YYYY-MM-DD HH:MM]

チェック履歴：
  ① self-validation：済（[日時]）
  ② fact-check：合格（[日時] / [n]回目）
  ③ persona-review：合格（[日時] / [n]回目）

主な修正内容（パイプライン通過中に行ったもの）：
  - [修正1]
  - [修正2]

残課題・注記（あれば）：
  - [エスカレーションで保留にした項目など]

上村確認ポイント：
  - [特に目を通してほしい箇所があれば]

以上、確認をお願いします。
```
