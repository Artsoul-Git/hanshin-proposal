# /skill-craft スキル
**セミナー事業部 × 開発部 共用 — 知識資産をスキルに変換するメタスキル**

**用途:** 文字起こし・書籍・インタビュー・ノウハウ素材を受け取り、
① 著作権セーフな概念抽出 → ② スキル定義ファイル生成 →
③ CLAUDE.md 更新 → ④ HTML マニュアル生成 → ⑤ 総合マニュアル連携
まで一気通貫で自動実行する。

**保存先:**
- スキル定義: `rules/skills/<スキル名>.md`
- HTML マニュアル: `07_マニュアル/<スキル名>完全ガイド.html`

---

## このスキルの設計哲学

> **ノウハウは型になった瞬間に、何度でも呼び出せる資産になる。**
> 素材から概念だけを抽出し、会社の要件で武装させて、即戦力のスキルにする。

- 著作権はアイデアを守らない。表現を守る。→ 概念・構造・フローの抽出は合法
- スキル定義は「担当者の採用・育成」と同じ。要件を叩き込んでから現場に出す
- マニュアルは最後の 1 ステップではなく、スキルの一部
- 総合マニュアルとの連携なしに「完成」と言わない

---

## フロー

### STEP 1: 素材の受け取り・読み込み

ユーザーからファイルパスまたはテキストを受け取る。

```
対応素材:
- テキストファイル（音声文字起こし・書き起こし）
- Markdown / HTML ドキュメント
- 会話ログ・インタビュー記録
- 書籍・記事の抜粋（ユーザーが貼り付けたもの）
```

**読み込みルール:**
- ファイルサイズが大きい場合は `offset` / `limit` を使って分割読み込みする
- 一度に全部読もうとしない（コンテキスト圧迫防止）
- 読み込み完了後、素材の「種別」と「大まかなテーマ」をユーザーに確認する

---

### STEP 2: 著作権セーフな概念抽出

**絶対に行わないこと:**
- 文章をそのままコピー（verbatim copy）
- 著者固有の言い回し・比喩をそのまま使用
- 固有名詞（社名・人名・商品名）をスキル定義に埋め込む

**抽出するもの（概念・構造のみ）:**

```
抽出軸:
① What（何を教えているか）
   → フレームワーク・ステップ・チェックリストの構造

② Why（なぜそれが重要か）
   → 問題・障壁・課題の本質

③ How（どうやるか）
   → 手順・判断基準・優先順位の考え方

④ 著者固有の造語・用語
   → 同じ意味で自社の言葉に言い換える（例：著者用語→業界標準語）
```

**抽出メモを一時的に作成:**

```
[抽出メモ]
素材テーマ: ○○
主な概念・フレームワーク:
  - (1) ...
  - (2) ...
再利用できる手順・ステップ:
  - ...
自社顧客（中小企業経営者・現場担当者）に刺さる要素:
  - ...
既存スキルとの関連:
  - /seminar-slide との連携可能性: ...
  - /course-build との重複チェック: ...
```

---

### STEP 3: スキル設計ヒアリング（1 回で聞き切る）

```
スキルを設計します。以下を確認させてください。

■ スキル基本情報
1. スキル名（/コマンド名）: 例 /course-build, /talk-script
2. 用途（1 行で）: 「〇〇を受け取り、〇〇を生成する」
3. 主な使用シーン: どんな時に呼び出すか
4. 想定ユーザー: 上村さん自身 / 特定の担当者 / 外部クライアント

■ 設計方針
5. 既存スキルとの連携: 入力に使うスキル・出力先のスキル
6. 会社固有の要件: 顧客層（中小企業経営者・現場担当者等）の特性をどう組み込むか
7. HTML マニュアルのファイル名: 例 skill-craft完全ガイド.html
8. 既存スキル定義を参考にするか: YES/NO（どれを参考にするか）
```

---

### STEP 4: スキル定義ファイル生成

**保存パス:** `rules/skills/<スキル名>.md`

**必須セクション構成:**

```markdown
# /<スキル名> スキル
**[担当部署] — [役割の一言説明]**

**用途:** [1〜2 文で何をするスキルか]
**保存先:** [出力ファイルのパス]

---

## この担当者の設計哲学（または役割定義）
> [スキルの核となる考え方 1〜3 行]

---

## 会社の顧客プロファイル（必ず念頭に置くこと）
[中小企業経営者・現場担当者・AI推進担当者の特性表]

---

## フロー
### STEP 1: [ステップ名]
...（以下各ステップ）

---

## 品質チェックリスト
### 設計チェック
- [ ] ...

### 顧客視点チェック
- [ ] ...

---

## 関連スキル
- [スキル名]: [役割]
```

**会社固有要件（すべてのスキルに必須）:**

```markdown
### 主要顧客層
| 層 | 特徴 | このスキルでの対応 |
|----|------|-----------------|
| 中小企業 経営者 | ROI で判断・時間がない | 〇〇で対応 |
| 現場担当者（事務・営業） | AI 苦手意識あり | 〇〇で対応 |
| AI 推進担当者 | 社内説得に苦労 | 〇〇で対応 |
```

---

### STEP 5: CLAUDE.md 更新

スキルテーブルに 1 行追加する。

**追加位置のルール:**
- テーマが近い既存スキルの直後に追加する
- テーマが全く新しい場合は関連グループの末尾に追加
- 説明文は 50 字以内・体言止め

```markdown
| `/[スキル名]` | [50 字以内の説明] |
```

---

### STEP 6: HTML マニュアル生成

**保存パス:** `07_マニュアル/<スキル名>完全ガイド.html`

**デザイン仕様（必ず既存マニュアルと統一すること）:**

```
カラー:
  - サイドバー背景: #1A365D（navy）
  - アクセント・見出し下線: #ED8936（orange）
  - 本文背景: #FAFBFC
  - カード背景: white

レイアウト:
  - サイドバー: fixed, 230px, #1A365D
  - メインコンテンツ: margin-left: 230px
  - コンテナ: max-width 920px, white card, box-shadow
  - フォント: "Yu Gothic UI", "Hiragino Sans", "Meiryo"

必須サイドバー要素:
  - ロゴ（会社名）
  - 総合マニュアルへの戻りリンク: href="総合マニュアル.html"
  - 目次リンク（セクションアンカー）

必須コンテンツ要素:
  - cover div（グラデーション背景・タイトル・タグライン）
  - meta-grid（スキル数・対象・ファイルパス等の統計）
  - 変更履歴テーブル
  - TOC（目次）
  - 各セクション（h2・h3・table・prompt-box・tip・warn・ok）
  - copy-btn（コードブロックのコピーボタン）
```

**必須コンテンツ構成:**

```
Section 1: [スキル名] とは（概要・できること）
Section 2: 呼び出し方（トリガーフレーズ・サンプルプロンプト）
Section 3: フロー詳解（各ステップの解説）
Section 4: [スキル固有のノウハウセクション]
Section 5: よくある失敗と回避法
Section 6: 関連スキルとの連携マップ
```

---

### STEP 7: 総合マニュアル連携

**対象ファイル:** `07_マニュアル/総合マニュアル.html`

**4 箇所を必ず編集する:**

#### 編集箇所 1: サイドバー（スキルリファレンスセクション）

```html
<!-- スキル名がリストに続く形で追加 -->
<a class="sb-link" href="<スキル名>完全ガイド.html" target="_blank"><スキル表示名>↗</a>
```

#### 編集箇所 2: 目次（TOC）

```html
<li class="sub-item">
  <a href="<スキル名>完全ガイド.html" target="_blank">
    ↗ [スキル表示名]（[キャッチコピー]）
  </a>
</li>
```

#### 編集箇所 3: 本文 PART 1 の .lead ブロック（既存があれば更新）

```html
<div class="lead" style="margin:16px 0;">
  [スキルの説明]<a href="<スキル名>完全ガイド.html" target="_blank">▶ 完全ガイドはこちら</a>
</div>
```

#### 編集箇所 4: 変更履歴テーブル

```html
<tr>
  <td>v[N+1]</td>
  <td>[YYYY-MM-DD]</td>
  <td>[スキル名]スキル新設・HTMLマニュアル追加・CLAUDE.md更新。</td>
</tr>
```

## 品質チェックリスト

### 著作権チェック
- [ ] verbatim copy が一切ないか
- [ ] 著者固有の表現・用語を言い換えているか
- [ ] 固有名詞（社名・人名）がスキル定義に混入していないか

### スキル定義チェック
- [ ] 会社の顧客プロファイル（3 層）が組み込まれているか
- [ ] 既存スキルとの重複・矛盾がないか
- [ ] 品質チェックリストが含まれているか
- [ ] 関連スキルのリンクが書かれているか

### マニュアル品質チェック
- [ ] デザインが既存マニュアルと統一されているか（navy/#1A365D・orange/#ED8936）
- [ ] 総合マニュアルへの戻りリンクがサイドバーにあるか
- [ ] copy-btn（コピーボタン）が全プロンプトボックスにあるか

### 連携チェック
- [ ] CLAUDE.md のスキルテーブルに追加したか
- [ ] 総合マニュアルのサイドバー・目次・本文・変更履歴の 4 箇所すべてを更新したか
