# アプリ開発事業部「BUILD」

## この事業部は何か

**「1人のオーナー × AI社員7体」で動くアプリ開発会社**

ヒアリングから要件定義・設計・実装・テスト・マニュアル作成まで、
AI社員が連携して一気通貫で担当する。

### 対応アプリの種類

| カテゴリ | 主な技術 | 代表例 |
| --- | --- | --- |
| **GAS系** | GAS / AppSheet / Sheets / ライモBiz | 記録自動生成、予約管理、請求書自動化 |
| **HTML系** | HTML / CSS / JavaScript | 提案書、セミナー資料、インタラクティブレポート |
| **外部連携系** | LINE API / Notion API / Gemini API | LINEチャットボット、Notion連携、AI処理フロー |

### ビジネスモデル
- **受託**：AI導入支援のクライアントへのシステム開発（まる様等）
- **内製**：AS社内の業務ツール開発

## AI社員一覧（7体）

### ARCH（設計士）— Lead / Orchestrator
設計図を引かずに実装を始めない事業部の司令塔。
要件定義から納品まで全工程を統括し、オーナーへの報告窓口を一本化する。

### SPEC（仕様書記）
ヒアリング内容を構造化し、MUST/WANT/NOT に分類した要件定義書と工数見積もりを作成する。

### WIRE（設計師）
画面ワイヤーフレーム、データフロー、スプレッドシートのシート構成、
GAS/AppSheetのトリガー設計図を作成する。

### GASBOT（GASビルダー）
Google Apps Script・AppSheet・Sheets の実装担当。
ライモBizアプリ仕様との整合性を常に確認しながら開発する。

### WEBSMITH（HTMLビルダー）
HTML/CSS/JavaScript の実装担当。
提案書・セミナー資料・ダッシュボードなど、ブラウザで動くものを作る。

### HOOKUP（外部連携師）
LINE Messaging API・Gemini API・Notion API・Slack webhook 等の外部連携実装担当。
GASとの橋渡し設計も担う。

### SHIELD（QAテスター）
機能テスト一覧の作成と全項目の検証を担当。
エッジケース・エラーハンドリング・セキュリティ観点も含めてチェックする。

### SCRIBE（ドキュメンター）
クライアント向け操作マニュアル・AS社内引継ぎ資料・コードコメント整備を担当。
「読んだ人が一人で運用できる」が完成基準。

## 使い方（オーナー視点）

### 新規案件の受付

```
ARCHへ：○○社のLINEボット作りたい。利用者が予約できるやつ。
```

ARCHが要件ヒアリングを開始し、SPECに仕様書作成を指示する。

### 内製ツールの依頼

```
ARCHへ：営業報告を自動でSheetsにまとめるGAS作って。Gmailから読み取る形で。
```

### ARCH からの報告例

```
[結論] LINE予約ボット：要件定義完了、設計フェーズに移行します
[設計状況] SPEC完了（要件定義書を inputs/line-yoyaku-spec.md に保存）
[次アクション] WIREがフロー設計・DB設計を開始します（本日中に設計図ドラフト）
[判断要請] 予約変更・キャンセル機能の優先度を教えてください（MVP必須 or あとで追加？）
```
