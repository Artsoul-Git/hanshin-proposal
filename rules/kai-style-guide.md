## 🟢 全成果物に適用する共通ライティングルール

> 詳細は `rules/seminar-talkscript-guide.md` §1・§7 を参照。  
> ここでは「他のスキルで参照するための概要」のみ記載する。

### 文体・トーン（すべての成果物に適用）

| 項目 | 設定 |
|------|------|
| フォーマリティ | カジュアル丁寧（礼儀正しいが肩の力は抜けている） |
| エネルギー | 標準ベース、要所でグッと上げる |
| 一人称 | 私 / 聴衆・読者呼称: 皆さま |
| 文末 | です・ます |
| 文の長さ | 一文短め。冗長禁止 |
| 語彙 | 専門用語あり（初出で短い注釈） |

### 共通禁則（すべての成果物に適用）

- **陳腐なAI表現禁止**：「AIの時代が来ました」「革新的な」「パラダイムシフト」
- **テンプレ比喩禁止**：「羅針盤」「エンジン」「地図」など使い古された比喩
- **過剰な決めつけ禁止**：「必ず〜できます」「絶対に変わります」
- **冗長・単調禁止**：同じ文型の繰り返し、体言止めの多用
- **固有名詞の無断使用禁止**：根拠のない企業名・人名・数値

### 数字・表記の統一ルール（2026-05-27 制定）

すべての成果物（HTML / Markdown / Word / Excel / スライド / トークスクリプト / メール）で統一する。

| カテゴリ | NG | OK | 理由 |
|---------|-----|-----|-----|
| **箇条書きの単位** | 五箇条 / 三箇条 / 七箇条 | **5か条 / 3か条 / 7か条** | 数字が一目で把握しやすい／「箇」は読みにくい・現代ビジネス文書で避けられる傾向 |
| 同上の応用 | N箇条 | **Nか条**（アラビア数字＋ひらがな「か」） | 同上 |
| **実行段階の通称** | パイロット | **先行運用** / **試験運用** | カタカナ業界用語回避・一般読者に直感的 |

**自己チェック手順：**
1. 成果物生成前に「五箇条」「三箇条」「パイロット」等を grep
2. 該当があれば全置換
3. 「Nか条」「先行運用」のみ許容

### 「Kai」表現の汎用化ルール（2026-05-27 制定・対外成果物）

**クライアント向け成果物（提案書・HTML・スライド・公開ドキュメント）では「Kai」を前面に出さない。**

| NG | OK |
|----|----|
| Kaiコメント / Kaiアドバイス | **ワンポイントアドバイス** |
| Kaiに相談する | （機能名で表現 / 削除） |
| Kai — ストラテジックコンサルタント | **分析サマリー** |
| 🧭 Kai アドバイス | **💡 ワンポイントアドバイス** |
| Kaiが指摘 / Kaiが分析 | （主語省略 or「分析では」「本提案では」） |
| 「K」アバター | **📊** / **🎯** / **💡** など機能を表す絵文字 |

**理由：**
- クライアントはKaiの概念を知らない＝混乱の原因
- 提案書は中立的・機能的な表現の方が信頼性が高い
- 法人案件・政府案件では特に重要

**例外：** 内部メモ・Kei宛社内資料・kai-tasks内ログでは「Kai」を使ってOK。

### Kei思考モード（自動内的対話）— 2026-05-27 制定

**対象：** 分析・提案・企画・戦略立案・大規模成果物生成のすべて

#### 動作

Kaiは以下の場面で **`memory/kei-knowledge.md` を自動参照** し、「Keiならどう問うか」をシミュレートしてセルフレビューする：

- 分析・提案・企画・戦略立案を依頼された時
- 大規模成果物（提案書HTML・羅針盤・リサーチ提案）の生成時
- 数値・推定値を含む提示の前
- 完成と思った成果物の最終チェック前

#### 自動セルフレビュー8項目

1. ペルソナのインサイト・こだわり・満足感情が1人称で言語化されているか
2. ベンチマーク企業の選定理由が論理的か（1〜3社挙げたか）
3. 全数値に出典・推定値は明示されているか
4. 既存資産（取引先・販路・組織）を壊していないか
5. コスト試算が出ているか
6. 構造化（マンダラ・マトリクス・フロー・ガント・Nか条）されているか
7. UX/UI（視認性・コントラスト・印刷適合）が考慮されているか
8. 再現性（スキル化・ルール化）の余地があるか

#### 明示モード起動

ユーザーが「Keiモードで」「壁打ちしながら」と言ったら、内的対話を**可視化**して表示する（対話形式）。

#### 新パターン追加

「これをKei knowledgeに追加して」「次回からこの視点で動いて」「Kei思考に新しいパターン追加」と言われたら、`memory/kei-knowledge.md` に追記＋ `memory/MEMORY.md` 更新。

詳細は `rules/skills/kei-think.md` 参照。

### エビデンスファースト原則（2026-05-27 制定・全リサーチ提案成果物）

**対象：** リサーチ提案・ベンチマーク分析・市場調査・競合分析・提案書を含む全ての分析成果物

#### 4つの鉄則（厳守）

1. **全ての数値に出典を明記する**
   - 市場規模・売上・人口・成長率・シェア・参加者数・取引件数すべて
   - 出典タイトル＋URL＋取得日（取得可能な場合）

2. **推定値・推計値は必ず明示する**
   - 「業界平均から逆算した推計値」「類似事例からの想定値」と書く
   - NG例：「市場規模は約500億円です」（断定）
   - OK例：「市場規模は約500億円と推計（業界レポートXからの試算）」

3. **公開情報で取れない数値は「未公開」「未確認」と書く**
   - 推測で穴埋めしない
   - NG例：「年商はおそらく10億円規模」
   - OK例：「年商は未公開（gBizINFOで決算情報欄空欄）」

4. **リンク取得できる場合は必ず添付**
   - 出典URLを `[タイトル](URL)` 形式で記載
   - WebSearch直後の新鮮なリンクを優先

#### 標準フォーマット：出典・エビデンス一覧

成果物末尾に以下のカテゴリ別アコーディオン構造で配置：

| アイコン | カテゴリ |
|---------|----------|
| 📊 | 市場・統計データ（公的データ・業界レポート） |
| 🏢 | 公式・一次情報（対象企業のIR・公式サイト） |
| 🏆 | ベンチマーク企業の戦略・実績 |
| 🛒 | ECモール出品状況（実調査） |
| 🌏 | 海外・越境EC・インバウンド |
| 📰 | ニュース・業界紙 |
| 🥾 | 競合・周辺市場 |

各セクション末尾に「数値の取り扱いについて：公的データは引用、推計値は実行前に先行運用で検証推奨」と明示。

#### 禁止事項

- 確信なくもっともらしい数字を言う
- 出典なしで「業界では一般的に〜」と書く
- 推定値を「実績値」のように見せる
- リンクを「公式サイト」とだけ書いて URL を省略する

詳細は `rules/skills/research-proposal.md` 参照。

### 図解・可視化ツールの統一ルール（2026-05-27 制定）

マンダラチャート・4象限マトリクス・フロー図・ガントチャートを単独で作る依頼を受けたとき、Kaiは必ず：

1. **単独モード起動前の確認**：
   > 「これらは **目標達成コンパス（羅針盤・モードE）** で統合的に作れます。
   > マンダラ→マトリクス→フロー→ガントとドリルダウン可能で、ワンポイントアドバイスや実行フェーズバッジが付きます。
   > **羅針盤で統合的に作りますか？** それとも単独で作りますか？」
2. ユーザーが「単独で」と明示しない限り、**羅針盤（モードE）** で進行
3. **テンプレ必須**：`08_アプリ開発事業部/outputs/rashinban/rashinban-template.html`（v8.0）をベースに使用
4. **新規HTML/CSS書き起こし禁止**：テンプレ既存機能を再実装しない

詳細は `rules/skills/visualize.md` モードE参照。

### スキル別の適用範囲

| スキル・成果物 | 適用するルール |
|--------------|--------------|
| セミナースライド・トークスクリプト | 全ルール（`seminar-talkscript-guide.md` 参照） |
| アプリ操作説明書・マニュアル | 文体・トーン + 禁則 + ステップ説明ルール（下記） |
| 提案書・ドキュメント | 文体・トーン + 禁則 |
| Brain記事 | `rules/brain-article-rules.md` 参照（独自ルール） |

### アプリ操作説明書・マニュアルの追加ルール

通常のトークスクリプトと異なる部分のみ記載する。

- **ステップ説明**: 「やること → 何ができるか」の2点セットで書く
  - 良い例：「ボタンを押す → 音声ファイルが分割されます」
  - 悪い例：「ボタンを押してください」（結果が見えない）
- **スクリーンショット代替表現**: 画像がない場合、「画面上部の〇〇ボタン」のように場所を言語化
- **CTAは不要**: 説明書にセールス要素を入れない
- **ROI・今動く理由は不要**: マニュアルは中立な情報提供

## ビジュアル・図表化のルール（2026-05-15 追加）

### 方針

HTML成果物（マニュアル・提案書・ガイドブック・セミナースライド）では、テキストだけでは伝わりにくい概念・構造・フローを **SVG / XML / Mermaid 形式の図** で補完する。「読んでわかる」より「見てわかる」を優先する。

### いつ図を入れるか（判断基準）

| 状況 | 対応する図の種類 |
|------|---------------|
| 抽象的な概念の説明（「AとBの違い」「〇〇とは」） | 比較図・概念図 |
| 手順に初心者が迷うポイントがある | 画面モック・注釈付き矢印図 |
| 複数要素の関係性・流れを説明する | フロー図・層構造図 |
| タイムライン・進捗・順序を示す | 横型タイムライン図 |
| 成果物やファイルの保存場所を示す | フォルダツリー図 |

### 使う形式と適用場面

| 形式 | 適用場面 |
|------|---------|
| **インラインSVG** | HTML成果物内の図版。ファイル依存なし・レスポンシブ対応。原則これを使う |
| **Mermaid** | フロー図・ガントチャート・シーケンス図（slides.js系スライド） |
| **ASCII図** | プレーンテキスト・Markdown成果物 |

### インラインSVGの実装ルール

```html
<figure class="svg-fig">
  <svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 W H" width="W">
    <!-- 図の内容 -->
  </svg>
  <figcaption>図の説明（何を表しているか）</figcaption>
</figure>
```

必須CSS（HTML成果物の `<style>` に追加）：
```css
.svg-fig { margin: 22px 0; text-align: center; }
.svg-fig svg { max-width: 100%; height: auto; display: block; margin: 0 auto; }
.svg-fig figcaption { font-size: 12px; color: #718096; margin-top: 8px; font-style: italic; }
```

- `viewBox` を必ず設定し、`width="W"` + CSS `max-width:100%` でレスポンシブ対応
- フォント：`font-family="Yu Gothic UI,Meiryo,sans-serif"`
- カラーパレット：成果物の既存テーマカラーに合わせる
- 吹き出し・線・注釈で「どこを見ればいいか」を必ず明示する
- 外部画像ファイル（.png/.jpg）は使用しない。すべてコードで生成する
- 外部サイトのスクリーンショットは著作権の問題があるため使わない → SVGで画面モックとして再現する

### 配置の優先ポイント

1. セクション冒頭の概念説明の直後（「言葉で理解 → 図で確認」の流れ）
2. 「これが怖い・難しそう」と感じるポイントのトグル内
3. ステップ説明の前（完成形・全体像を先に見せてから手順を示す）

### コードブロックのコピーボタン（標準装備）

HTML成果物にコマンド・プロンプト例・設定コード・テンプレートなど**コピー対象のコードブロック（`<pre>`）が1つでもある場合**、すべての `<pre>` にコピーボタンを自動付与する。

**いつ付ける：** マニュアル・ガイド・セミナー補足資料・提案書補足など、読者が実際にコードや文章をコピーして使う想定のすべての成果物。

**CSS（`</style>` 直前に追加）：**
```css
  /* ── コードブロック コピーボタン ── */
  pre { position: relative; }
  .copy-btn { position: absolute; top: 8px; right: 8px; background: rgba(255,255,255,0.12);
    color: #A0AEC0; border: 1px solid rgba(255,255,255,0.18); border-radius: 5px;
    padding: 3px 11px; font-size: 12px; cursor: pointer; font-family: inherit;
    transition: all 0.2s; }
  .copy-btn:hover { background: rgba(255,255,255,0.22); color: white; }
  .copy-btn.copied { background: #38A169; border-color: #38A169; color: white; }
  /* プロンプト用（薄い背景の pre に使う場合） */
  .pre-prompt .copy-btn { background: rgba(0,0,0,0.06); color: #4A5568; border-color: rgba(0,0,0,0.12); }
  .pre-prompt .copy-btn:hover { background: rgba(0,0,0,0.12); }
```

**JavaScript（`</script>` 直前に追加、または末尾に新規 `<script>` ブロック）：**
```javascript
document.querySelectorAll('pre').forEach(function(pre) {
  var btn = document.createElement('button');
  btn.className = 'copy-btn';
  btn.textContent = 'コピー';
  btn.addEventListener('click', function() {
    var codeEl = pre.querySelector('code');
    var text = codeEl ? codeEl.innerText : pre.innerText;
    text = text.replace(/^コピー\n?|コピー完了！?\n?/g, '').trim();
    function onSuccess() {
      btn.textContent = 'コピー完了！'; btn.classList.add('copied');
      setTimeout(function() { btn.textContent = 'コピー'; btn.classList.remove('copied'); }, 2200);
    }
    if (navigator.clipboard && navigator.clipboard.writeText) {
      navigator.clipboard.writeText(text).then(onSuccess).catch(function() { fallback(text, onSuccess); });
    } else { fallback(text, onSuccess); }
  });
  pre.appendChild(btn);
});
function fallback(text, cb) {
  var ta = document.createElement('textarea');
  ta.value = text; ta.style.position = 'fixed'; ta.style.opacity = '0';
  document.body.appendChild(ta); ta.focus(); ta.select();
  try { document.execCommand('copy'); cb(); } catch(e) {}
  document.body.removeChild(ta);
}
```

**ボタンラベル：** 日本語で「コピー」→「コピー完了！」。英語ラベル禁止（[[feedback-language-options]] 参照）。

## 上村桂右 プロフィール・自己紹介作成のルール（2026-05-22 追加）

> 上村の自己紹介文・プロフィール文・SNSプロフを作成・修正する際は、必ず以下を参照・遵守する。

### ベースファイル

```
knowledge/上村桂右/上村桂右_自己紹介パターン集_v5.md
```

上村の自己紹介・プロフィールはこのファイルがベース。新たに作成・修正する場合は必ずこのファイルの言葉・設計方針を継承する。

### 言葉のルール

| 禁止 | 代替 |
|------|------|
| 「経営者として」（多用禁止） | やってきたことを動詞で列挙する。「動かしてきた側」「経験してきた立場」で文脈から伝える |
| 「小さな事業所」「小さな会社」 | 「中小企業・小規模事業者」「個人事業主」 |
| 「現場」の連呼 | 「実務の感覚」「日々の業務」「動かしてきた側」などで分散する |
| 「経営してきた」（漠然とした動詞） | 「事業の立ち上げから販路開拓、海外メーカーの日本総輸入代理店として全国展開、事業転換・売却まで」と領域を動詞で並べる |

### よろず支援拠点の表記ルール

- **初出**：「経済産業省・中小企業庁が運営する岡山県よろず支援拠点のコーディネーター」（フルネーム必須）
- **2回目以降**：「よろず支援拠点」で可

### 名刺交換・自己紹介の2系統

上村には2つの顔がある。場面に応じて使い分ける。

| 系統 | 名乗り方 | 使う場面 |
|------|---------|---------|
| 会社代表 | 「有限会社アートソウルの上村です」 | 営業・BtoB商談・異業種交流会 |
| よろず支援コーディネーター | 「経済産業省・中小企業庁が運営する岡山県よろず支援拠点のコーディネーター、上村といいます」 | よろず窓口・商工会議所・支援機関関係者 |

### 販促・プロモーション支援の広げ方

販促の話が出たとき、相手の状況に応じて上流支援まで展開できる。

```
業務整理・仕組みづくり
　↓（販促の話が出たら）
販促文章の型づくり・情報共有整理
　↓（「効果が出ない」なら）
商品・サービスの見せ方 → マーケット分析 → プロモーション設計
```

ただし押しつけない。「状況によっては〜から入ることもあります」という形で添える。

### 2026-05-29 [厳禁] 派生ファイル制作時の既存仕様の無確認着手

**状況：** 阪神素地様向けの「rashinban_proposal_drainage.html」を新規作成した際、既存の `rashinban_proposal_1.html` `rashinban_proposal_2.html` に標準実装されていた **「フロータブ用プロンプトアコーディオン（fl-prompt クラス + buildFlowPrompt 関数）」** という重要仕様を把握しないまま着手して、提出後にKeiさんに「ないよ」と指摘されて初めて気付いた。同じセッションで chartLTV のデータ論理破綻（累計と書いてあるのに単調増加しない数列）、KPI数値の10倍楽観、複数のA2A FLAGを「致命的でないため判断保留」とKeiさんに丸投げするミスも併発した。

**修正前：**
- 派生ファイルを「ゼロから設計」して既存ファイルの構造を読まずに着手
- A2A結果の FLAG を「軽微」として保留報告
- 数値の論理整合性を自己チェックせず、A2Aレビューに頼り切り

**修正後：**
- 派生ファイル着手 **前** に同名パターン Glob → 既存ファイル全件 Read → CSS/JS/DOM 継承要素リスト化を **必修ステップ** 化
- A2A結果は `a2a-enforcer` Agent 経由で必ず全件処理
- HTML成果物完了時は `html-validator` Agent で数値整合性・仕様継承漏れを機械的に検査

**ルール（CLAUDE.md「派生制作プロトコル」「A2A結果処理プロトコル」に恒久実装済）：**

1. **派生ファイル着手前の必修3ステップ**
   - Glob で同名パターン全件 → Read で構造把握 → 継承要素リスト化
   - CSS独自class（例: `.fl-prompt`）/ JS独自関数（例: `buildFlowPrompt`）を網羅的に抽出
   - 配色変数・タブ構成・パスワードゲート仕様の継承確認

2. **「気づかなかった」「把握できていなかった」は言い訳にしない**
   - 把握不十分なら `html-validator` Agent を **先に** 呼んで差分を網羅抽出してから着手

3. **A2A FLAG の「逃げ」禁止**
   - 「致命的でないため判断保留」「Kei判断委任」等の単独理由でFLAG非対応にしない
   - 非対応の場合は **理由・リスク・先延ばし条件** の3点セットを必ず明記

4. **数値整合性の自己チェックを A2A前に完了**
   - Chart.jsデータと label の整合（累計が単調増加か等）
   - KPI数値が他セクションと桁が合っているか
   - 仮置数値ボックスと本文の数値が一致しているか

5. **完成報告前の最終ゲート**
   - 派生ファイル → `html-validator` Agent 発動
   - A2Aレビュー → `a2a-enforcer` Agent 経由で全件処理
   - 両ゲート通過後にKeiさんへの提示・公開アクションを実行
