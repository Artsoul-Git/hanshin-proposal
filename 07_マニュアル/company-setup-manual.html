1/company-setup とは何か

このスキルは「AI組織を新規に立ち上げたい」というオーナーとの対話を通じて、そのオーナー専用のAI組織一式（憲法・ルール・スキル・管理フォルダ）をゼロから設計・生成するスキルです。

有限会社アートソウルが持つ「AI導入支援組織」の設計思想をテンプレートとして応用し、業種・業態・規模・コンセプトが異なる任意のオーナーに対して繰り返し使えます。

このスキルでできること

できること説明
AI組織の設計業種・規模に合った判断権限マトリクス・品質ゲートの設計
憲法ファイルの生成CONSTITUTION.mdをオーナーのミッション・制約に合わせて作成
スキル体系の設計その事業に必要なスキルコマンド一覧を設計
管理フォルダ構造の生成案件パイプライン・自律レベル記録・スターターパックの生成
2つの情報収集モードファイル記入 または 壁打ちセッションを選択可能

このスキルを使うタイミング

  • 新しいクライアント企業のAI組織を立ち上げる支援をするとき
  • 自社のAI組織を最初から作り直したいとき
  • 「AI担当者を採用せずにKaiで会社を動かしたい」という経営者に出会ったとき
Kai's Point このスキルは「提案書を作る」ではなく「組織そのものを設計する」ものです。完成後はそのまま Claude Code 上で運用が始まります。提案書より一段上の支援です。

2スキルの起動と基本情報の入力

2-1　起動方法

Claude Code のプロンプトに以下のいずれかを入力します：

/company-setup

または自然言語でも起動できます：

  • 「AI組織をゼロから作りたい」
  • 「この会社のAI体制を設計してほしい」
  • 「company-setupスキルを起動して」

起動すると Kai から以下の挨拶が表示されます：

こんにちは。company-setup スキルを起動しました。

これからあなた（オーナー）の事業・コンセプト・課題をヒアリングして、専用のAI組織設計一式を作成します。

所要時間：
　・ファイル記入モード → 記入15〜30分 ＋ Kai生成10分
　・壁打ちモード　　　→ 対話30〜60分（記入不要）

まず5つの基本情報を教えてください。

2-2　最初の5項目

起動直後にKaiが以下の5項目を聞いてきます。まとめて答えてもOKです。

#項目入力例
①事業・会社名有限会社アートソウル、○○デンタルクリニック、仮称「プロジェクト名」でもOK
②主な業種・業態障害福祉（就労支援）、歯科クリニック、金属加工製造業、税理士事務所、ECサイト など
③ターゲット顧客・利用者障害者手帳所持者、地域住民（20〜60代）、中小製造業、個人事業主 など
④規模感スタッフ5名・利用者30名、従業員12名・年商2億円 など（概算でOK）
⑤現在の最大の課題（3つ以内）記録業務が多い・採用に困っている・提案書の作成に時間がかかる など
ポイント 5項目のうち「わからない」「まだ決まっていない」で構いません。後のヒアリングで補完できます。まず動かすことが大切です。

2-3　ヒアリングシートの生成

5項目を受け取った直後、Kaiは自動的にヒアリングシートを生成・保存します。

setup_[事業名略称]_[YYYYMMDD]/
└── hearing_sheet.md　　# ← ここに保存される
ファイル名の例 事業名「コーデ就労支援」なら → setup_コーデ_20260510/hearing_sheet.md

ヒアリングシートには A〜C の3セクションがあります：

  • A. 事業プロフィール：Step 1 で答えた5項目が自動記入されています
  • B. 詳細ヒアリング（B-1〜B-6）：ここが空白 → ファイル記入 か 壁打ち で埋める
  • C. Kaiへのメモ：追加で伝えたいことを自由に書く欄

32つの進行モード

ヒアリングシートを保存したら、Kaiが2つのモードを提示します。どちらを選ぶかはオーナーの好みや状況次第です。

A) ファイル記入モード
  • ヒアリングシート（B〜C欄）を自分で記入して提出する
  • 自分のペースで書ける（深夜でも移動中でもOK）
  • 整理して書くのが得意な人向け
  • 所要時間：記入15〜30分
B) 壁打ちモード
  • Kaiと会話しながら情報を整理していく
  • 書くのが苦手・考えながら話したい人向け
  • Kaiが業種知識で仮説を出し、オーナーが修正する形で進む
  • 所要時間：対話30〜60分

3-2　Bモード：壁打ちセッションの進め方

壁打ちモードを選ぶと、Kaiが会話形式でB-1〜B-6の内容を引き出していきます。

1「壁打ちモード」または「Bで」と伝える

すると Kai が B-1（ミッション・コンセプト）から質問を開始します。

2一度に1〜2項目ずつ対話する

Kaiは一度に大量の質問をしません。答えに対して深掘り質問を1つ加えながら進みます。

3業種知識でKaiが仮説を出す

Kaiは業種の「あるある」を知っているので、「障害福祉の場合、月末の個別支援計画作成に多くの時間がかかるケースが多いですが、御社はいかがですか？」のように仮説を投げ、オーナーが修正する形で進みます。

壁打ちのメリット 「書くのが苦手」なオーナーはもちろん、「課題はあるけど整理できていない」「ビジョンがぼんやりしている」という場合に特に効果的です。Kaiとの対話を通じて自分のビジネスを再発見することもあります。

4-2　CONSTITUTIONのカスタマイズ内容

CONSTITUTION.md は業種によって以下の部分が大きく変わります：

▶ 障害福祉事業所の場合
  • §3 判断権限「個別支援計画の内容変更は必ず管理者確認」
  • §3「モニタリング記録・サービス等利用計画の外部提出前にオーナー確認」
  • §4 個人情報「利用者名は匿名化（利用者A/Bなど）。支援内容の詳細は外部提示禁止」
  • §5 品質ゲート「障害支援区分・加算種別を正確に把握してから提案書を作成」
▶ 歯科クリニックの場合
  • §3「診療記録・処方内容はAIが生成しない（参照のみ）」
  • §3「患者説明資料は院長の最終確認必須」
  • §4「患者情報はKnowledge/に格納。問診内容の外部提示禁止」
  • §5「保険点数・治療ガイドラインの根拠を必ず明示」
▶ 士業事務所（税理士・社労士など）の場合
  • §3「税務申告書・労務書類の確認は必ず有資格者」
  • §3「クライアント企業の財務情報・給与情報はAIから外部共有禁止」
  • §4「依頼者情報はKnowledge/のみ。コーデ等のシミュレーションデータと混在させない」
  • §5「法改正・通達の反映漏れチェックを品質ゲートに追加」

7よくある質問

▶ /company-setup と /sme-ai-proposal の違いは？

/sme-ai-proposal：クライアントへの「提案書」を作るスキル。成果物はHTMLの提案書ファイル。

/company-setup：そのクライアント（またはオーナー自身）の「AI組織そのもの」を構築するスキル。成果物は CONSTITUTION・CLAUDE.md・スキル群・管理フォルダ一式。

使い分け：まず /sme-ai-proposal で「AI導入を提案」→ 採用されたら /company-setup で「組織を構築」という流れが自然です。

▶ 生成されたファイルの内容は後から変更できるか？

もちろんできます。特に CONSTITUTION.md は「生きているドキュメント」として、運用しながらアップデートするものです。変更する際は CONSTITUTION §7（改訂ルール）に従い、バージョン番号と日付を更新してから git commit してください。

▶ 壁打ちモードで途中で止めてもいいか？

大丈夫です。「今日はここまでにします」と伝えれば Kai が途中までの情報をヒアリングシートに保存します。次回同じプロジェクトフォルダで再開できます。

▶ 既存のCLAUDE.mdがある場合はどうするか？

「既存の CLAUDE.md を上書きしないで差分を確認したい」と伝えてください。Kai が既存ファイルを読んで、新しい設計との差分を提示します。どの部分を採用するかオーナーが判断してからマージします。

▶ 生成後にスキルを追加・削除したい場合は？

スキルの追加：skill/[スキル名]/SKILL.mdを作成し、CLAUDE.mdのスキル一覧に追記します。

スキルの削除：フォルダを削除し、CLAUDE.mdから該当行を削除します。削除はオーナー確認後に行います（CONSTITUTION §3）。

▶ 「Kai」という名前を変えたいのだが？

可能です。setup 完了後に「AIパートナーの名前を〇〇に変更して」と伝えてください。CONSTITUTION.md・CLAUDE.md・各 SKILL.md の該当箇所を一括変更します。ただし「Kai」は有限会社アートソウルのプロジェクトでの呼称なので、別オーナーの環境では別の名前を推奨します。
