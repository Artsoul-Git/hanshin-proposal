## 3. 採用したCC機能（実使用）

| 機能 | 使い方 |
|---|---|
| **goal** | 「釣り市場以外の新販路を半年分から抽出→検証済HTML納品→ポータル統合」を逆算 |
| **batch** | WebSearch 11軸を1ターン並列・browser_batchで navigate+wait+screenshot をシーケンス化 |
| **DCI** | Design（DESIGN.md・美学プロンプト）→Code（index.html、wader_channels.html）→Inspect（preview検証） |
| **tasks** | Kai Tasksプロジェクト `cb912de8` 作成・9タスク連動・ピボット記録・session-end snapshot |
| **Mem** | CLAUDE.md/CONSTITUTION.mdの命名/保存場所/個人情報/Kaiアイデンティティを常時参照 |

## 4. 省略したCC機能（理由）

| 機能 | 省略理由 |
|---|---|
| Hooks | 自動化トリガー不要（単発タスク） |
| Rules | CLAUDE.md/CONSTITUTION.mdは常時適用済みのため明示不要 |
| fork | 単独タスク、隔離環境不要 |
| allow | 既存allowlistで足りた |
| sec | 公開コード/外部API/個人情報なし、セキュリティレビュー対象外 |
| Teams（subagent） | リサーチ自体が並列WebSearchで完結、深掘り役の追加投入は過剰 |
| Ultra | プロトタイプ規模、`/ultrareview` 起動は費用対効果が見合わない |

## 7. 学び・改善ポイント

### うまくいったこと
- WebSearch 11軸並列で1ターンで網羅的な情報収集
- DCI（Design→Code→Inspect）の3フェーズ徹底でアウトプット品質を担保
- ピボットを隠さずKai Tasksに記録、Keiさんに即座に方針転換を提案
- 阪神素地統合版で既存提案との連携を明示し「破棄するものではなく補強する」位置付けに

### 改善余地
- **Chrome拡張のpermission運用**：拡張側で「常に許可」をプロジェクト単位で記憶できる運用ルールが必要。次回は事前にKeiさんに主要ドメインをまとめて許可してもらう
- **スクショ取得の代替手段**：Chromeが詰まった場合、playwright/puppeteerのローカル実行や、preview MCP（file://ではなくlocalhost配信）で巡回する選択肢を事前に持つ
- **ターゲット視点の早期確定**：今回は汎用版→阪神素地統合版の2段階で作ったが、最初から「特定クライアント向け」と分かっていれば直接統合版を作る方が効率的
