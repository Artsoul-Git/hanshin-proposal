# eval-weekly — 週次ゴール整合評価

## このスキルのルール

1. **承認ゲートはStep 3の1回のみ**（タスク自動作成の確認）
2. **Kai がセッション内で分析** — 追加API費用なし
3. **Stop候補には必ず3点セットで提示**：理由 / メリット / もし続けるなら
4. **Scale候補には必ず具体的アドバイス3点**を添える
5. **翌週タスク候補はユーザー確認後にkai-tasksへ登録**

---

## 実行手順

### Step 1: 週次データ集計（コスト0）

```bash
# 今週を評価
python 08_アプリ開発事業部/outputs/kai-review/kai-review.py weekly

# 先週を評価
python 08_アプリ開発事業部/outputs/kai-review/kai-review.py weekly --last
```

→ 日次データが存在しない日は自動補完される
→ 構造化されたレポートテキストが出力される

### Step 2: Kai が分析・評価レポートを生成

出力されたレポートテキストと以下の評価基準をもとに、Kai が分析を行う。

**評価基準: 構造改革ロードマップ_2026.md の5本柱**

```
柱1: ナレッジ標準化パイプライン
柱2: Kai自己検証プロトコル
柱3: 段階的自律権限拡張（L1→L2→L3→L4）
柱4: フィードバック→ルール化ループ
柱5: 案件パイプライン可視化
```

**出力フォーマット（Kai が生成）:**

```markdown
## 週次評価レポート: YYYY-W##

### ゴール整合スコア: X/10
[根拠: 柱別アクティビティと Phase1 チェックリスト達成率から算出]

### 週次サマリー
[3文以内で今週全体を評価]

---

**1. [活動名]**
- 理由: [結果・数値根拠を含む]
- スケールアドバイス:
  ① [具体的アクション]
  ② [具体的アクション]
  ③ [具体的アクション]
- タスク候補: [kai-tasks に追加するタイトル]
```

### Step 3: タスク自動作成（確認後）

Kai が提示したタスク候補を確認し、承認されたものを登録:

```bash
python 08_アプリ開発事業部/outputs/kai-tasks/kai-tasks-cli.py add-task <PID> \
  --type small --title "タスクタイトル" --desc "詳細"
```

## Stop 判定の基準

以下の条件が重なる場合に Stop 候補と判定:

| 条件 | 説明 |
|------|------|
| ゴール整合0 | ロードマップ5本柱のいずれにも貢献しない |
| 繰り返し発生 | 同じカテゴリの脱線が週2回以上 |
| アウトプットなし | コミットはあるが成果物ファイルが増えていない |
| Phase1未到達 | Phase1 タスクが残っているのに別領域に手を出している |

---

## Scale 判定の基準

| 条件 | 説明 |
|------|------|
| スコア5〜6 | 高スコアコミットが週に3件以上 |
| 柱への貢献 | ロードマップの柱に直結し、かつ成果物がある |
| タスク完了 | kai-tasks での完了が記録されている |
| 再現性 | 過去2週以上で継続して高評価 |
