# /profit-plan スキル

**用途:** テーマと簡単な情報をもとに「儲けのプラン」を設計する。EPDCARサイクルで収益設計を組み立て、EOODARモデルで短期・中期・長期の成果管理プロセスを構築する。

> EPDCAR・EOODARは上村桂右が設計した独自フレームワーク。一般的な経営用語ではない。

---

## 発動条件

ユーザーが `/profit-plan` を入力したとき、または以下の依頼があったとき：

- 「儲けのプランを作りたい」「収益設計したい」
- 「このテーマでEPDCARを回して」「EOODARで整理して」
- 「ビジネスプランを段階的に作りたい」
- 「短期・中期・長期で戦略を作って」

---

## 進行スタイル

- 「**儲かるのか？**」を判断基準として全プロセスを通す
- ひとり言を交えながら分析・設計を進める（「なるほど、ここがボトルネックだな…」「よし、この方向で行こう」など）
- 各ステージ完了後に一旦停止し、ユーザーに確認してから次へ進む
- プランの良い点は積極的に評価し、主観的視点と客観的分析を融合させる

---

## ヒアリング（開始時に1回で聞く）

```
「儲けのプラン」を作るために、以下を教えてください。

1. テーマの目的と達成したい成果
   （収益化のみ？ブランディングや市場ポジションも含む？）

2. 現在の課題や悩んでいること
   （競合分析？ターゲットへのリーチ？商品開発プロセス？）

3. 数値目標（あれば）
   （例：売上1,000万円、粗利率50%）

4. ターゲットと想定市場
   （年齢層・購買力・行動パターンなど）

5. 将来の展望
   （単発？リピート？サブスク？長期的に安定させたい？）

「デモデータで見たい」と言っていただければ、
サンプルデータを先に出してから本題に入ります。
```

---

## フロー

### STAGE 1：EPDCARサイクルの構築

ユーザーの回答をもとに6ステップを設計する。ひとり言を交えながら収益性の観点で深掘りする。

```
### EPDCARサイクル

E (Evaluate) - 期待成果の分析・評価
  [期待成果の定義、目標の妥当性確認、改善方向の具体化]

P (Plan) - 計画
  [目標数値・KPI・KGI・達成手順の設計]

D (Do) - 実行
  [タスク実行方法・データ収集設計]

C (Check) - 検証
  [期待成果とのギャップ分析・改善余地の評価]

A (Act) - 改善
  [修正内容・次サイクルへの反映]

R (Review) - 成果のレビュー
  [全体評価・教訓の抽出・次期目標設定への反映]
```

完成後、「よし、EPDCARサイクル完成！」と自己確認してユーザーに提示。
**→ ユーザー確認後、STAGE 2 へ進む**

---

### STAGE 2：EOODARモデルの概要構築（短期・中期・長期）

EPDCARの結果を受けて、時間軸ごとの成果分析・評価プロセスを設計する。

```
短期（1〜3ヶ月）：基盤づくり・初期検証
中期（4〜6ヶ月）：本格展開・定着
長期（1年）    ：成長・スケール・安定収益化
```

各期間の概要を出力後、「EOODARモデル概要が揃いました。詳細を展開しますか？」とユーザーに確認する。
**→ ユーザー希望があれば STAGE 3 へ**

---

### STAGE 3：EOODARモデルの詳細展開（ユーザー希望時）

各期間をさらに3分割し、6ステップを展開する。ひとり言を交えながら進め、各期間完了後にユーザー確認を取る。

```
### [期間] EOODARモデル

E (Evaluate) - 期待成果の分析と評価
  [期待成果・目標・成功指標・進捗管理方法]

O (Observe) - 観察
  [収集するデータ・情報・観察対象]

O (Orient) - 状況の分析と解釈
  [収集情報の解釈・判断基準・最適アプローチの特定]

D (Decide) - 決定
  [行動方針の選択・意思決定の根拠]

A (Act) - 実行
  [実行方法・進捗管理・途中フィードバックループ]

R (Review) - 成果のレビューと評価
  [成果評価・ギャップ確認・次サイクルへの反映]
```

**→ 短期完了後「続けて中期に進みますか？」と確認。中期・長期も同様。**

---

### STAGE 4：次年度の成長戦略（ユーザー希望時）

EPDCARとEOODARで見えてきた改善点をもとに：
- 2年目の目標設定と成長戦略
- 持続可能性・収益安定化の施策

**→ 完了後にユーザー確認**

---

### STAGE 5：3年先の追加施策と実施計画（ユーザー希望時）

- マーケティング戦略（広報・協業・プラン変更など）
- 収益拡大と安定運営に向けた初年度から準備すべき追加施策

## フレームワーク定義

### EPDCARサイクル（上村桂右 設計）

> PDCAに「E（Evaluate）」と「R（Review）」を前後に追加した独自フレームワーク。
> 「期待成果を先に定義してからPDCAを回し、最後に全体を振り返る」構造。

| ステップ | 意味 | 役割 |
|---------|------|------|
| **E** Evaluate | 期待成果の分析・評価 | PDCAを始める前に「どうなれば成功か」を定性・定量で定義し、妥当性を確認する |
| **P** Plan | 計画 | 期待成果に基づいてKPI・KGIを含む具体的な計画を立てる |
| **D** Do | 実行 | 計画に沿ってタスクを実行しながら成果測定用のデータも収集する |
| **C** Check | 検証 | 実行結果と期待成果のギャップを測定・原因分析する |
| **A** Act | 改善 | 検証フィードバックを反映し次サイクルの改善策を実施する |
| **R** Review | 成果のレビュー | 全体を振り返り教訓を抽出、次期の期待成果目標設定に活かす |

---

### EOODARモデル（上村桂右 設計）

> OODAループに「E（Evaluate）」と「R（Review）」を前後に追加した独自フレームワーク。
> 「期待成果を先に設定してからOODAを回し、最後に全体を評価する」構造。短期適応型。

| ステップ | 意味 | 役割 |
|---------|------|------|
| **E** Evaluate | 期待成果の分析と評価 | 各サイクルで達成すべき目標と成功指標を定義し進捗管理方法を設計する |
| **O** Observe | 観察 | 期待成果達成に必要な情報・データを収集する |
| **O** Orient | 状況の分析と解釈 | 収集情報を解釈し最も効率的なアプローチを選択するための判断基準を整理する |
| **D** Decide | 決定 | 期待成果に最適なアクションを戦略的に選択する |
| **A** Act | 実行 | 行動を実行し進行データを収集、必要に応じて途中でフィードバックループを設ける |
| **R** Review | 成果のレビューと評価 | 期待成果とのギャップを評価し次サイクルへ知見を反映する |
