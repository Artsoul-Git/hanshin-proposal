# 案件受付フロー

## 1. ブリーフ受領（オーナー → CHIEF）
最低限の情報をオーナーから CHIEF に伝える：
```
A社のセミナー、来月15日、対象は経営層50名、オンライン
```

## 2. CHIEF が要件構造化（最大3問質問）
- 案件ID：PILOT-NNN
- セミナーテーマ
- 開催情報、参加対象、KPI、制約条件

## 3. TAKUMI 自動起動 → 13工程実行
```
Step 1: ディレクトリ準備
Step 2: persona-architect
Step 3: goal-designer
Step 4: scenario-writer（パターン選定＋必須オープニング5枚）
Step 5: researcher
Step 6: GUARDIAN Round 1
Step 7: 提案書ドラフト
Step 8: slide-designer（5スタイル選定＋15レイアウト）
Step 9: script-writer（本物の台本）
Step 10: reviewer（マーケ＋経営）
Step 11: GUARDIAN Round 2
Step 12: slide-builder（実物.pptx）
Step 13: CHIEF 納品報告
```

## 4. オーナー確認＆承認
完成 .pptx を確認、Yes/No で承認。

## 5. 納品
PowerPoint or Google Slides で運用。

---

## 別ルート：HTMLスライド（`/seminar-slide` スキル）

上記フローは PPTX 形式での制作フロー。  
**ブラウザ表示・GitHub Pages 公開・プレゼンターモード付き** の HTML スライドが必要な場合は別ルートを使う。

| 比較軸 | PPTX フロー（CHIEF/TAKUMI） | HTML フロー（`/seminar-slide`） |
|--------|---------------------------|-------------------------------|
| 出力形式 | `.pptx`（PowerPoint） | `index.html`（ブラウザ） |
| 公開方法 | ファイル配布 | GitHub Pages URL |
| プレゼンターモード | PowerPoint 発表者ビュー | `presenter.html`（ブラウザ） |
| トークスクリプト | 別ファイル | スライドに埋め込み（`data-notes`） |
| 向いているケース | 社内配布・印刷・既存運用 | URL 共有・オンライン配信・受講者セルフ閲覧 |

**HTML ルートの呼び出し：**
```
/seminar-slide
```
→ `rules/skills/seminar-slide.md` 参照。ヒアリング → slides.js 生成 → GitHub Pages 公開まで一気通貫。
