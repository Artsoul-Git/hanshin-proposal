# /visualize スキル

**用途:** テーマ・目標を受け取り、4象限マトリクスまたはマンダラチャートで思考プロセスを可視化し、draw.io（app.diagrams.net）に直接ペーストできるXMLを生成する

---

## 発動条件

ユーザーが `/visualize` を入力したとき、または以下の依頼があったとき：

- 「4象限マトリクスで整理して」「マトリクス分析して」
- 「マンダラチャートを作って」「9×9で展開して」
- 「図で可視化したい」「draw.ioのXML作って」
- 「戦略を整理して図にして」「思考を構造化して」

---

## 入力仕様

以下の3つを受け取ってから実行する。未提供の場合はまとめて確認する。

```
1. 【業種・業態】     分析対象の事業領域
2. 【テーマ・目標】   分析テーマまたは達成したい最終目標
3. 【出力形式】      A: 4象限マトリクス  または  B: マンダラチャート
```

---

## 出力形式の選び方ガイド

| 状況 | 推奨 |
|------|------|
| 優先順位をつけたい・リソース配分を決めたい | A: 4象限マトリクス |
| 目標達成のための要素を網羅的に展開したい | B: マンダラチャート |
| 競合・市場・内外環境を比較したい | A: 4象限マトリクス |
| アクションプランを64項目に分解したい | B: マンダラチャート |

---

## プロセスA：4象限マトリクス

### A-Step 1：分析の目的とスコープを定義

【業種・業態】と【テーマ】を解釈し、分析目的を1文で定義する。
（例：「〇〇業において、△△を最大化するための主要業務を特定し、リソース配分の優先順位を決める」）

### A-Step 2：ドメインマッピング（MECE）

分析対象に関連する項目を網羅的にリストアップ（漏れなく・ダブりなく）。
項目を構造化・階層化する。

### A-Step 3：分析軸の設計

目的に照らして、対象の本質的な差異を表すX軸・Y軸をカスタム設計する。
既存フレームワークに縛られず、目的に最適な軸を選ぶ。

参考観点：顧客接点（高/低）、戦略性（戦略/戦術）、標準化（標準/個別）、収益貢献（高/低）

設計した軸と4象限それぞれの意味を明記する。

### A-Step 4：プロットと戦略提言

A-Step 2の項目を論理的根拠をもってマトリクスに配置する。
各象限の戦略的意味（例：「即効投資領域」「自動化対象」）を定義し、戦略提言にまとめる。

### A-Step 5：XML生成

以下の仕様に従ってXMLを生成する。

---

#### draw.io 4象限マトリクス XML仕様

**XMLルール**
- コードブロック内はXML本体のみ（説明文を一切含めない）
- 構造：`<mxfile>` → `<diagram>` → `<mxGraphModel>` → `<root>`
- `<mxGraphModel>` に `math="0"` と `shadow="0"` を必ず含める
- `<mxGeometry>` は閉じタグ形式（`/>`）で記述
- コメント・全角スペース・`opacity` 小数指定は禁止

**図の構成**
- キャンバス：幅1200 × 高さ800
- 中央にX軸・Y軸の十字線
- 軸ラベル：X軸左右・Y軸上下（フォント16pt・太字）
- 象限タイトル：各象限に戦略的意味を簡潔に配置
- プロット項目：`rounded=1` または `ellipse`・象限ごとに配色・重ならないようバランス配置
- 全体タイトル：上部中央

**XMLテンプレート（骨格）**
```xml
<mxfile host="app.diagrams.net"
        modified="{ISO8601日付}"
        agent="5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36"
        etag="{任意文字列}"
        version="24.4.0"
        type="device">
  <diagram name="{図のタイトル}" id="{一意ID}">
    <mxGraphModel dx="1434" dy="794" grid="1" gridSize="10"
                  guides="1" tooltips="1" connect="1" arrows="1"
                  fold="1" page="1" pageScale="1"
                  pageWidth="1200" pageHeight="800"
                  math="0" shadow="0">
      <root>
        <mxCell id="0"/>
        <mxCell id="1" parent="0"/>
        <!-- タイトル・軸・象限・プロット項目をここに展開 -->
      </root>
    </mxGraphModel>
  </diagram>
</mxfile>
```

## プロセスB：マンダラチャート

### B-Step 1：最終目標の定義

【テーマ・目標】をマンダラチャートの中核「最終目標」として設定する。
【業種・業態】のコンテキストを考慮して目標の意味合いを具体化する。

### B-Step 2：8つの主要テーマを展開

最終目標を達成するために不可欠な「主要テーマ（構成要素）」を8つ導出する。
MECE（漏れなく・ダブりなく）で、目標達成の主要な柱になるものを選ぶ。

### B-Step 3：64の具体的タスクに分解

8つの主要テーマそれぞれに対して、実現するための「具体的タスク（アクション）」を8つ展開する。
合計 8×8 = 64 タスクを生成する。

### B-Step 4：XML生成

以下の仕様に従ってXMLを生成する。

---

#### draw.io マンダラチャート XML仕様

**XMLルール**（4象限と共通）

**図の全体構成**
- 「中央の3×3グリッド」＋周囲「8つの3×3グリッド」= 実質9×9
- グリッド間のマージン：約10〜20px（接続線が通る最低限の空白を確保）
- 各セルのサイズ統一（例：width="170" height="80"）
- ページサイズ：全要素が収まる大きさ（例：pageWidth="1800" pageHeight="1000"）

**セルの配色ルール**
- `M_center`（最終目標）：最も目立つ色（例：`fillColor=#b3e0ff`）
- `S*_main`（主要テーマ×8）：中央グリッドの周囲8マスに異なるパステル8色
- `S*_center`（周囲グリッドの中央）：対応する `S*_main` と同色
- `T*_n`（タスク×64）：対応する `S*_center` よりさらに明るい淡い色

**接続線のルール**
- `S*_main` と `S*_center` を結ぶ8本の接続線
- `edgeStyle=orthogonalEdgeStyle`を使用
- `<Array as="points">` で中間座標を明示指定し、他セルを横切らないようにルート設計
- `strokeColor=#888888`・矢印なし（`endArrow=none`）

**XMLテンプレート（骨格）**
```xml
<mxfile host="app.diagrams.net"
        modified="{ISO8601日付}"
        agent="5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36"
        etag="{任意文字列}"
        version="24.4.0"
        type="device">
  <diagram name="{タイトル}" id="{一意ID}">
    <mxGraphModel dx="1434" dy="794" grid="1" gridSize="10"
                  guides="1" tooltips="1" connect="1" arrows="1"
                  fold="1" page="1" pageScale="1"
                  pageWidth="1800" pageHeight="1000"
                  math="0" shadow="0">
      <root>
        <mxCell id="0"/>
        <mxCell id="1" parent="0"/>
        <!-- M_center / S*_main×8 / S*_center×8 / T*_n×64 / edge×8 をここに展開 -->
      </root>
    </mxGraphModel>
  </diagram>
</mxfile>
```

---

## 共通ルール

- 分析結果（思考プロセス）を先に提示してからXMLを出力する
- XMLコードブロック内はXMLデータのみ（「こちらがXMLです」等の説明文は禁止）
- 分析内容はMECEを原則とし、論理の飛躍がないか自己チェックしてから出力する
- 事実に根拠のない数値・固有名詞はKnowledgeかユーザー確認情報のみ使用する
