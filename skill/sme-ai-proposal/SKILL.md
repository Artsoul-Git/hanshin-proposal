# SME AI導入支援 提案スキル

## 目的

中小企業・小規模事業者（従業員10〜50名規模）へのAI導入支援において、
ヒアリング記録・提出書類・課題メモを読み込み、以下を一貫して設計・出力する。

- 現状フロー（課題の可視化）
- 改善後フロー（ツール設計）
- 伴走プラン（フェーズ・費用・オプション）
- 投資対効果（ROI）
- 提案HTMLファイル（印刷・公開対応）

**この提案が守る原則：「オペレーションを先に整え、AIはその補助として後から入れる」**

---

## 起動条件

- 「◯◯様向けAI導入提案書を作って」と依頼があった時
- ヒアリング記録・書類・課題メモのどれかが提供されている時
- 既存提案書のブラッシュアップを求められた時

---

## 起動前チェック（Kai自律判断）

`Knowledge/00_Kaiスターターパック.md` が存在する場合：
1. ファイルを読む
2. 「Kai自律判断チェック」の全項目が通過しているか確認する
3. **未通過項目がある場合：** 作業を止めて上村に確認を求める
4. **全通過の場合：** Phase 1へ進む（上村への確認不要）

スターターパックがない場合：Phase 1でKnowledge全ファイルから情報を抽出する。

## 実行プロセス（6フェーズ）

### Phase 1：クライアントプロファイルの抽出

ヒアリング記録・提出書類から以下を必ず確認する。不明なものは「不明」として明示し、提案に反映させる。

```
【必須抽出項目】

1. 規模
   - 職員数・職員の役割構成（管理者/支援員/事務など）
   - 利用者/顧客数・拠点数

2. ITリテラシースペクトル
   - PCが使える職員は何名？
   - スマホ操作はできる？
   - 「最もリテラシーが低い人」を具体的に把握する

3. 業種・規制環境
   - 行政への提出書類は何があるか？（提出頻度・様式の自由度）
   - 記録保管義務はあるか？（年数・様式）
   - 利用者/顧客への開示が必要な書類は何か？

4. 予算感
   - 月額でどの程度が現実的か？（5万/10万/30万/それ以上）
   - 初期投資に使えるか、月額のみか？

5. 過去の失敗・試みた対策
   ← これが最重要。「なぜ失敗したか」を設計制約として使う

6. 意思決定者とAIマネージャー候補
   - 誰が最終決定するか
   - 誰が「AI担当者」として育てられるか（1〜3名）
```

---

### Phase 2：課題マッピング（負担コスト順）

すべての手作業・非効率を洗い出し、**時間コスト順**に並べる。
「面白そうな自動化」ではなく「実際に痛い業務」から始めるのが原則。

**課題抽出テンプレート：**

```
| 業務 | 現状のやり方 | 月間所要時間 | 担当者数 | 問題の種別 |
|------|------------|------------|--------|---------|
| 記録作成 | 手書き→夜間PC転記 | XX時間 | X名 | 二度手間 |
| 集計 | 紙台帳→月末手集計 | XX時間 | X名 | 転記・ミス |
| 書類作成 | 白紙から毎回作成 | XX時間 | X名 | 標準化不足 |
```

**問題の種別（この順で優先度が高い）：**
1. **二度手間** — 同じ情報を複数の場所に書く
2. **転記ミス** — コピー間違い・記入漏れ
3. **標準化不足** — 担当者によってやり方が違う
4. **参照困難** — 情報があるが探せない
5. **集計負担** — 月次や年次の集計作業

**「やらないこと」の判定基準：**
- 月1回以下の頻度で、現状は手作業でも回せている → フェーズ2以降に先送り
- 全職員一斉に使う前提が必要 → 先行2〜3名に絞るまで着手しない
- 外部システム連携が必要 → Phase 3（将来課題）
- 利用者/顧客が直接タッチ操作 → リスク高・推奨しない（現場の実態に合わないことが多い）

---

### Phase 3：設計制約の確定

提案を始める前に「やらないこと」と「使わないアプローチ」を明文化する。

**制約セットの設計方法：**

```
【制約1】過去の失敗事例から
"◯◯様は以前△△を試みたが失敗した。原因は□□。
→ 今回の設計は[この制約]を必ず守る"

【制約2】現場のリテラシーから
"職員◯名のうち□名がPCを使えない。
→ スマホブラウザで全員が完結できる設計のみ採用"

【制約3】予算から
"月額◯万円が上限。
→ 外部SE発注・高額SaaS・カスタム開発は除外"

【制約4】現場稼働維持から
"導入期間中も通常業務を止められない。
→ 旧方式との並行運用期間を必ず設ける。全面切り替えはしない"
```

---

### Phase 4：ツール選定ロジック

以下のツール選定フローを使う。**Google → ライモBizの順で検討し、それで解決できないものは将来課題とする。**

```
解決したい業務課題
      ↓
[文書・記録・集計・メール] → Google Workspace で解決
  ├─ 文書作成・共有    → Google Docs / Drive
  ├─ データ集計・台帳  → Google Sheets + VLOOKUP/QUERY
  ├─ 自動化・通知      → Google Apps Script (GAS)
  ├─ 録音・文字起こし  → Google Meet
  ├─ AI文章化・分析    → Gemini (GWS付属)
  └─ フォーム入力      → Google Forms
      ↓
[GoogleだけではカバーできないUI/現場操作]
  → ライモBiz カスタムアプリで解決
  ├─ スマホ30秒で完結する出退勤打刻
  ├─ スマホマイク音声→DBへ直接保存
  └─ 操作者にGWSアカウント不要な入力UI
      ↓
[API連携・複雑な開発が必要なもの]
  → 将来課題（Phase 3以降）
  - 外部専用ソフトとのデータ連携
  - 大規模カスタム開発
  - 利用者/顧客向けWebシステム開発
```

**GWS アカウント数の設計原則：**
- AI・システムを直接操作する「AIマネージャー」のみGWSアカウントを付与
- 他のスタッフはスマホブラウザ→ライモBizアプリ → Sheets DBへ保存
- 目安：管理者1名 + AIマネージャー候補2名 = 3アカウント（¥1,872 × 3 = ¥5,616/月）

---

### Phase 5：フェーズ設計

規模や複雑さに応じて調整するが、基本構造は以下を守る。

```
フェーズ1「基盤構築期」（月1〜3）
目的：2〜3名の先行チームで小さく成功体験を作る
やること：
 - 最優先課題のみ解決（2番目以降はやらない）
 - 先行AIマネージャーの選定・研修
 - ツール設計・開発
 - 現場稼働しながら並行運用で試験

フェーズ2「定着・自走化期」（月4〜6）
目的：先行チームが「ひとりでできる」状態になる
やること：
 - 横展開（先行→全員）
 - AIマネージャーが自分で改善提案を出せるようになる
 - KPI計測・効果確認
 - 次の課題（優先度2位）への着手

フェーズ3「顧問期」（月7〜）
目的：月1回の相談で自走を維持・強化
やること：
 - 月次顧問MTG
 - AIトレンドレポート（月1）
 - チャットサポート（軽微な質問）
 - 四半期ごとの改善提案
```

**月額料金の目安（要件定義で確定）：**

| フェーズ | 規模S（5〜10名） | 規模M（10〜30名） | 規模L（30〜50名） |
|---------|--------------|---------------|---------------|
| フェーズ1 | ¥150,000/月 | ¥300,000/月 | ¥450,000/月 |
| フェーズ2 | ¥75,000/月 | ¥150,000/月 | ¥200,000/月 |
| フェーズ3 | ¥30,000/月 | ¥50,000/月 | ¥80,000/月 |

### Phase 6：提案 HTML の生成

以下の仕様で HTML ファイルを生成する。

**ファイル名：**
```
AI導入支援_完全提案パッケージ_{クライアント名}_{バージョン}.html
```

**デザインシステム（Navy × Orange）：**
- メインカラー：`#1A365D`（ネイビー）
- アクセント：`#ED8936`（オレンジ）
- 警告：`#E53E3E` / 成功：`#38A169` / 情報：`#3182CE`

**必須セクション：**

```
Section 0  提案の設計思想
           ├─ 過去の失敗事例（設計制約として）
           ├─ 現場の実態（リテラシー・スタッフ構成）
           ├─ 設計原則7箇条（業種に応じて調整）
           ├─ 優先導入順序
           └─ やらないことリスト

Section 1  現状課題の可視化
           ├─ 業務別コスト計算表（月間損失）
           └─ 現状業務フロー図（受入れ/入会から月次業務まで）

Section 2  改善後の姿
           ├─ リード文（ツール設計の方針）
           └─ 改善後業務フロー図

Section 3  システム構成設計書
           ├─ ベースツール（Googleツール）
           ├─ ライモBizカスタムアプリ仕様（該当する場合）
           └─ アカウント設計（誰が何を使うか）

Section 4  台帳・情報管理 デジタル化設計（業種で内容を変える）

Section 5  行政・提出書類 現実的システム化ガイド（3レベル方式）
           ├─ レベル1：今すぐできる（テンプレート化）
           ├─ レベル2：1〜2ヶ月で実現（GAS自動化）
           └─ レベル3：将来課題（外部連携）

Section 6  AI自動化フロー（記録→分析→書類生成）

Section 7  AI研修プログラム（ライモBiz・必須）

Section 8  伴走プラン設計（必須 + 付加オプション3択）
           ├─ 必須：AI導入研修（ライモBiz）
           ├─ オプション①：GWS設定・台帳設計
           ├─ オプション②：ライモBizアプリ開発（2本セット）
           └─ オプション③：週次AIコーチング（月4回）

Section 9  6ヶ月フェーズ別ロードマップ

Section 10 ROI・投資回収シミュレーション + KPI目標値
```

**表紙に必ず含める要素：**
- ロゴ（Base64埋め込み）
- バージョンバッジ
- 提案先・提案日・改訂日
- 提案者：有限会社アートソウル　上村桂右

## 業種別パターンライブラリ

### パターンA：障害福祉（就労継続支援B型・グループホーム等）

**固有の課題：**
- 支援記録の文章化（面談・相談支援・カンファレンス）
- 実績記録票・国保連請求書の作成
- 個別支援計画の更新（年2回 × 利用者数）
- 内部メモと利用者開示記録の分離

**適用する設計制約：**
- 利用者が直接タッチ操作するUIは使わない（リクルートシステム教訓）
- 出退勤はライモBizスマホ打刻（GWS Formsより現場親和性が高い）
- 国保連書類は3レベル（印刷提出→GAS PDF→将来API）

**GWS 活用の核心：** Gemini で記録下書き → Sheets テンプレートへ自動挿入 → PDF 化

---

### パターンB：クリニック・整体院・美容サロン（予約・カルテ系）

**固有の課題：**
- 予約管理（電話→手書き台帳）
- 施術/診療記録の文章化
- リピーター管理・フォロー連絡

**適用する設計制約：**
- 患者・顧客が直接入力するタッチUI → リスク高（混乱しやすい）
- 電子カルテとの連携は対象外（医療法上の専門ソフト領域）
- 予約はGoogleカレンダー＋Formsで十分（高額予約システム不要）

**GWS 活用の核心：** Meet 録音 → Gemini 文字起こし → Sheets カルテDB

---

### パターンC：製造・建設（現場記録・品質管理系）

**固有の課題：**
- 作業日報の手書き→PC転記
- 設備点検記録の保管・集計
- 施工写真の整理・報告書作成

**適用する設計制約：**
- 現場でのスマホ利用は前提（タブレット共用は非推奨）
- インターネット接続が不安定な現場 → オフライン動作への配慮
- 現場作業中の入力は最小限（打刻 + 写真 + 一言メモが上限）

**GWS 活用の核心：** ライモBiz現場記録 → Drive 写真保存 → Gemini で報告書下書き

---

### パターンD：士業・コンサル・研修機関（知識集約型）

**固有の課題：**
- 顧問先・案件管理の属人化
- 会議議事録の作成
- 提案資料・報告書の再利用が低い

**適用する設計制約：**
- スタッフ全員がPC利用可能（リテラシー制約は緩い）
- セキュリティ意識が高い → データの保存先・権限設計を丁寧に
- クライアントデータの取り扱いルールを先に策定

**GWS 活用の核心：** Meet 録音 → Gemini 議事録 → Sheets 案件管理台帳 → Drive 共有

## KPI フレームワーク

業種・業務によって項目を変えるが、以下の構造は共通。

```
計測タイミング：3ヶ月目 / 6ヶ月目 の2回

必須KPI（業種共通）：
 1. 対象業務の作業時間：削減率 ◯〜◯%
    ← 3ヶ月目：20〜30%減 / 6ヶ月目：30〜50%減 が目安
 2. 先行チームの利用定着率：80%以上
 3. AIマネージャーの自走度：「月1件以上の改善提案を自主発案」

業種別追加KPI（例）：
 - 福祉：記録漏れ件数 / 書類提出ミスゼロ維持
 - サロン：予約確認の電話件数削減
 - 製造：日報記入漏れ率
 - 士業：議事録作成時間
```

---

## ROI 計算テンプレート

```
月間削減効果 = 削減時間(h) × 時給単価(円)

月次損益 = 月間削減効果 − (コンサル費 + GWS費 + ライモBiz費)

投資回収月 = フェーズ1〜2の累計損失 ÷ フェーズ3以降の月次純利益

--- 数値の取得方法 ---
削減時間：Phase 2のコスト計算表から
時給単価：最低賃金〜¥1,800/h の範囲で現場に合わせる
GWS費：¥1,872 × アカウント数
ライモBiz費：¥10,000/月（目安）
```

```

- [ ] ライモBizの使用理由が「Googleで補えない現場の手書きゼロ化」に限定されている
- [ ] GWSアカウント数が「AIマネージャーのみ」で設計されている

- [ ] 現状フロー図が受入れ/入会段階から始まっている
- [ ] 月間損失がヒアリングから拾った数字（シミュレーションでも根拠あり）
- [ ] 伴走プランに必須（ライモBiz研修）＋オプション3択がある
- [ ] KPI目標値が3ヶ月・6ヶ月の2段階で数値化されている
- [ ] ROI計算で投資回収月が明示されている

表記チェック
- [ ] 社名：有限会社アートソウル（「AS株式会社」「植村ケイ」は使わない）
- [ ] 担当者：上村桂右
- [ ] 「Phase」ではなく「フェーズ」に統一
- [ ] バージョン管理：v{n}.html で保存・旧版は削除しない
- [ ] ロゴ（Base64）が表紙に埋め込まれている
```

## スキル起動時の確認フロー

ユーザーから起動要求があったら、まずこの順で確認する：

```
1. Knowledge フォルダ（実データ）を確認
   → ヒアリング記録・書類・フロー図を読み込む

2. Phase 1 のプロファイル項目を埋める
   → 不明な項目はユーザーに確認する（5項目以上不明なら確認を優先）

3. Phase 2 の課題マッピングを提示
   → 「この課題の優先順位でよいですか？」とユーザーに確認

4. ツール選定・フェーズ設計を決定
   → 「やらないこと」を先に宣言

5. HTML 生成
   → バージョン管理でファイル保存

6. Kai自己検証（`rules/self-validation-protocol.md` 参照）
   → 検証レポートを付けて上村に提示
```

---

## Kai自己検証フェーズ（HTML生成後・上村提示前）

`rules/self-validation-protocol.md` の提案書専用チェック（P1〜P4）を実行し、
検証レポートを成果物の冒頭に付けて上村に渡す。

```
【Kai自己検証レポート】
✅ 根拠チェック：Knowledge内の数値・固有名詞 — 全件確認済み
✅ クライアント懸念：①___  ②___  ③___ → 対処済み
⚠️ 批判的視点：「___」→ ___（対応済み）
✅ 失敗シナリオ：「___」→ リスク欄に記載
✅ 上村修正予測：___ → 修正済み

自己検証：済 ／ 指摘___件処理済み
```

検証完了後、`01_経営管理/自律レベル記録.md` に1行追加する（承認後）。
