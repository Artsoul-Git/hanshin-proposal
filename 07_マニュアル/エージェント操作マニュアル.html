PART 0　Kaiとの協働
0-1Kaiとは▼
Kai（カイ）は、上村桂右のビジネスパートナーAIです。Claude Code 上で動作しますが、毎セッション憲法（CONSTITUTION.md）を読み込み、常に同じ原則で行動します。

Kaiの基本姿勢

  • 単なる実行者ではなく、パートナーとして意見・アイデアを積極的に提供する
  • 上村が気づいていない視点や懸念点があれば先回りして指摘する
  • 判断の透明性：解釈 → 補完 → 提示 → 承認 → 実行のフローを守る
  • 不明点があれば推測して実行するのではなく、ブリーフィングで確認する

Kaiの判断透明性フロー

分業マップ

Kaiがやること上村がやること
ファイル読み込み・分析・整理最終判断・承認・方針決定
成果物（HTML・MD・資料）の生成クライアントとの対話・関係構築
ブリーフィング提示・論点整理新規案件の発掘・営業活動
パイプライン状況の更新・アラート現地訪問・セミナー登壇
ドラフト・たたき台の作成内容のレビュー・承認
ルール・憲法に基づく品質チェックフィードバック・指摘（Kaiが学習）
0-2話しかけ方（/project-intake）▼
スキルコマンドを使わなくても、普通に話しかけるだけで大丈夫です。Kaiが自動的にブリーフィングを生成して「進めていいですか？」と確認します。

Kaiのブリーフィング形式

話しかけると、Kaiは以下の形式でブリーフィングを返します：

【解釈】
あなたの依頼をKaiがどう理解したか

【補完した視点】
依頼に含まれていないが重要と判断したこと

【進め方の提案】
具体的な実行ステップの提案

【担当スキル】
使用するスキルコマンド（例：/sme-ai-proposal）

→ このまま進めてよいですか？
重要：ブリーフィングをスキップしない Kaiは「とりあえず実行してみる」ことをしません。必ずブリーフィングを提示してから実行します。「OK」「進めて」と返すと実行に移ります。

実例

上村「まる様の提案書を最新版に更新して」

【解釈】
合同会社まる様の提案書HTMLを最新バージョンに更新する依頼と解釈しました。

【補完した視点】
・現在v10が最新版と記録されています
・更新内容が未指定のため確認が必要です
・更新後に /publish-proposal でURL更新も必要かもしれません

【進め方の提案】
①更新内容を確認（新しい情報・修正点をお知らせください）
②既存v10を読み込み → 更新箇所を反映 → v11として保存
③必要であれば /publish-proposal でGitHub Pages更新

【担当スキル】：/sme-ai-proposal（更新モード）

→ 更新内容を教えていただければ進めます。何を変更しますか？

自律レベル（L1〜L4）

レベル呼称特徴上村の関与
L1アシスタント全成果物を確認・承認してから実行毎回確認必須
L2コ・パイロット定型作業は承認なし・新規は確認定型作業は省略可
L3オートパイロット案件フロー全体を自律実行・報告のみ週次レビューのみ
L4パートナー戦略提案・新機能開発まで自律月次レビュー
現在のレベル L1（2026-05-09 スタート）
すべての成果物は上村の確認・承認後に実行します。

L2解放条件

  • 連続5件の案件で品質基準を達成する
  • 上村からの修正指摘が3件以下（5件中）
  • 上村が「L2に上げる」と明示的に承認する

記録場所：01_経営管理/自律レベル記録.md

  • P1: 依頼の解釈は正確か
  • P2: 補完した視点を明示したか
  • P3: ROI定量試算が含まれているか（提案書の場合）
  • P4: 次のアクションが明確か

SK/project-intake — 受付・ブリーフィング生成▼
/project-intake
自動起動 / すべての依頼の入口

コマンドを打たなくても、Kaiに話しかけるだけで自動起動します。依頼を解釈・補完し、ブリーフィングを提示して承認後に実行します。

使うタイミング

  • 何か新しい作業を依頼するとき（コマンド不要・普通に話しかける）
  • 「〜をやって」「〜が欲しい」など自然な日本語で依頼する

何をするか

  1. 依頼の内容を解釈する
  2. 依頼に含まれていない重要な視点を補完する
  3. ブリーフィング（解釈・補完・進め方・担当スキル）を提示する
  4. 「進めていいですか？」と確認する
  5. 上村が「OK」と返したら実行に移る
ポイント：スキップして即実行しない Kaiはどんなに簡単な依頼でも、ブリーフィングを提示せずに即実行しません。確認なしに大きな変更を行うことで生じるミスを防ぐためです。

3Knowledge/ に保存してKaiに指示

まる様の提案書を作って。スターターパックは Knowledge/20260509_まる_スターターパック.md に入ってる。

出力物

  • AI導入支援 完全提案パッケージ HTML（パスワードゲート付き）
  • 自己検証レポート（C1-C3・P1-P4のチェック結果）

  • Knowledgeフォルダのデータのみ使用している（架空データは使わない）
  • ROI試算に実数（時給・スタッフ数・作業時間）が使われている
  • 業種パターンが正しく選択されている（障害福祉・クリニック・製造・士業など）
  • オペレーション改善が先・ツール導入は補助として設計されている

3用語の事前説明▼
エージェント
特定の役割・手順・出力形式が定義されたClaudeの「仮面」のこと。「MAPPER として動いて」と指示すると、mapper.md の定義通りに動く。
引き継ぎパッケージ
あるエージェントから次のエージェントへ渡す情報セット。たとえば MAPPER が ANALYST に渡す「訪問ヒアリングメモ＋預かり書類リスト」がそれ。
ロードマップ策定フェーズ
ACTモデルに入る前の「まず設計図だけ作りましょう」サービス（¥110,000〜）。MAPPER が担当。まる様案件で実際に行ったフロント商品。
ACTモデル（AI Core Transformation）
アートソウルのメインサービス。Phase 1（月30万 × 3ヶ月）→ Phase 2（月15万 × 3ヶ月）→ Phase 3（月5万 顧問）の6ヶ月＋継続プログラム。
AIマネージャー
クライアント社内でAI活用を推進する担当者。研修で育成し、6ヶ月後には自走できる状態を目指す。
自走化（じそうか）
クライアントが「アートソウルに頼らなくてもAI活用の月次改善を自分で回せる」状態。6ヶ月後のゴール。
クイックウィン
Month 2 に最初の成果を出すための「最も効果が高く・最も実現しやすい」改善施策。現場の信頼を得るために早期に成果を見せる。
B/A分析（Before/After分析）
AI導入前後の業務時間・コストを比較して「どれだけ良くなったか」を数字で示す分析。TRACKERが毎月生成する。
プロンプト v1→v2→v3
業務自動化に使うAIへの指示文（プロンプト）を、現場のフィードバックをもとに3回改善していくサイクル。COACHが管理する。
ライモBiz
アートソウルが研修で使用するAI活用プラットフォーム。ミニアプリ開発・AIスタジオ・チャットボット作成などができる。

17よくあるトラブルと対処▼

トラブル1：エージェントが「想定と違う出力」をする

原因：インプット情報が少なすぎる or エージェント名の宣言が抜けている

対処：「intake.md のロールで動いてください」の一行を必ず最初に入れる。情報が足りない場合はエージェントに「不明な点があれば質問してください」と追記する。

トラブル2：ROI試算の数字がおかしい

原因：スタッフ数・時給・業務頻度などの前提数値を与えていない

対処：「スタッフ時給：¥1,200、管理者時給：¥1,500、月稼働日数：20日」のように具体的な数値を必ず渡す。

トラブル3：引き継ぎパッケージが不完全

原因：引き継ぎを依頼しないまま次のエージェントを呼んだ

対処：「○○エージェントへの引き継ぎパッケージをまとめてください」と明示的に依頼してから次に進む。

トラブル4：クライアントの業務名が汎用的になってしまう

原因：業種・具体的な業務名を渡していない

対処：「日報作成（毎日17:00実施）」「出退勤簿の転記（月末に国保連システムへ入力）」のように、現場の言葉・タイミング・対象システムを具体的に渡す。

トラブル5：PIPELINEのアラートが正常に機能しない

原因：KPIデータが週次で揃っていない

対処：AIマネージャーへのKPIデータ提出リマインドをメール文案（email_templates.md）で準備しておく。

トラブル6：MAPPERとINTAKEで二重作業になった

トラブル7：Kaiがブリーフィングなしに即実行した

18用語集（詳細版）▼
ACTモデル（AI Core Transformation）
アートソウルのメインサービス。Phase 1（月30万 × 3ヶ月）→ Phase 2（月15万 × 3ヶ月）→ Phase 3（月5万 顧問継続）の6ヶ月プログラム。LTV は平均215万円。
AIマネージャー
クライアント社内でAI活用を推進する内部担当者。TRAINERが育成し、COACHが能力開発し、GROWERが自走化させる。
As-Is / To-Be
As-Is = 現状の姿（Before）。To-Be = あるべき姿・改善後の姿（After）。ANALYSTが現状マップ（As-Is）を作り、PLANNERがTo-Beを設計する。
B/A分析（Before/After分析）
AI導入前後の数値比較。TRACKERが毎月生成する。「月○時間削減・月○万円削減」の数字がこれで出る。
クイックウィン
Month 2 に最初の成果を出すための最優先施策。「最も効果が高く・最も実現しやすい」業務を選ぶ。現場のモチベーション維持のために必須。
ライモBiz
アートソウルが研修・支援で使用するAIプラットフォーム。ミニアプリ開発・AIスタジオ・QAボット作成・AIパンフレットなどの機能を持つ。
ミニアプリ

19Claude Code 操作（起動・セッション再開・git管理）▼
このプロジェクト全体は Claude Code（CLI）で動いている。作業ファイルはDドライブ、会話履歴はCドライブ。セッションをまたいだ作業継続・変更の取り消しの手順をここに集約する。

起動方法

通常起動

claude

プロジェクトフォルダ（D:\Google Antigravity\AS_AI導入支援事業_cc\）で実行。

直前のセッションをそのまま続ける

claude --continue

最後のセッションの会話履歴を読み込んで再開。「さっきの話の続き」をそのまま指示できる。

過去のセッションを選んで再開

claude --resume

セッション一覧が表示される。日時と内容から選択して再開。

「完全な続き」にはならない場合がある 会話が長いと自動的に要約・圧縮される。ただし以下の3層で文脈は引き継がれる。

一つ前に戻す方法（ロールバック）

① 直前のコミットだけ取り消す（最も安全）

! git revert HEAD

「戻す」操作自体が新しいコミットとして記録される。元の履歴は消えない。

② 特定コミットの時点まで完全に巻き戻す

! git reset --hard a1b2c3d
注意 そのコミット以降の変更は消える。やり直しが効かないので慎重に。

③ 特定ファイルだけ元に戻す

! git checkout a1b2c3d -- js/slides.js

1ファイルだけ特定時点の内容に戻す。他のファイルは影響なし。
