# 実演＋ハンズオン 進行ガイド v2（20分）

---

## 全体フロー概要

| フェーズ | 内容 | 目安時間 |
|---|---|---|
| 0. ヒアリング | 受講者の状況確認・デモルートを決定する | 2〜3分 |
| 1. 実演 | 選択したルートで講師がデモを行う | 8分 |
| 2. ハンズオン | 受講者が実際に試す | 7〜8分 |
| 3. デブリーフ | 振り返りと次フェーズへの橋渡し | 2分 |

**実演のルートは3つ。当日のヒアリング結果でいずれかを選ぶ。**

| ルート | 状況 | デモの中心 |
|---|---|---|
| A | 受け取る側 × 交渉できる | 不利条項の洗い出し＋修正案の生成 |
| B | 受け取る側 × のむしかない | リスク優先度付け＋社内対策＋弁護士相談準備 |
| C | 渡す側 | 自社契約の問題点＋相手目線のシミュレーション |

弁護士相談のための要件定義・質問リスト作成は**全ルート共通オプション**として実演に組み込める。

---

## フェーズ0：ヒアリング（2〜3分）

### 目的
受講者の実際の状況を把握し、最も刺さるルートで実演を行う。

### ヒアリング3問

「ここからは実際に動かす時間です。まず3点だけ確認させてください。」

**問1：立場の確認**
「普段の取引で、契約書や利用規約を"受け取る"ことが多いですか、"渡す・提示する"ことが多いですか？」

→ 受け取る → 問2へ
→ 渡す → ルートC（問2・3はスキップ可）
→ 両方 → どちらか今日試したい方を選んでもらう

**問2：交渉余地の確認**（受け取る側の場合のみ）
「今日チェックしたい書類、もしくは普段受け取る書類は、条件の交渉ができる場面ですか？それとも、基本的に相手の条件をそのまま受け入れるしかない場面が多いですか？」

→ 交渉できる → ルートA
→ のむしかない → ルートB

**問3：書類の確認**
「今日持参された書類はありますか？なければ私がサンプルを用意しています。」

→ 持参あり → そのまま使用（マスキング手順をハンズオン冒頭で実演）
→ 持参なし → `demo_sample_contract.md`（業務委託）または `demo_sample_terms.md`（利用規約）を使用

### ルート決定の宣言

「ありがとうございます。では今日は[ルートA / B / C]を中心に進めましょう。」

## フェーズ1：実演（8分）

### 共通：画面共有の準備（1分）

「では画面を共有します。」

- Claude（claude.ai）を開く
- 新規チャットを作成

「今日はClaudeを使います。ChatGPTでも同じように動きます。

まず最初に、契約書をAIに渡す方法をお見せします。

テキストをチャット欄に直接貼り付ける方法もありますが、今日はもう少し実務的なやり方で進めます。サンプル契約書をあらかじめGoogleドキュメントに保存してあります。Claudeの場合はここからファイルをアップロードします。」

（ペーパークリップ/添付アイコンをクリック → ファイルを選択する画面を見せる）

「Googleドキュメント・WordのファイルはそのままドラッグするかアップロードするだけでAIが読み込めます。Geminiの場合はGoogleドキュメントのURLを貼り付けるだけで読み込めます。この方法を使うと、長い文書でもコピペの手間なく、まるごと渡せます。

プロンプトの内容が重要なので、ツールよりも"何を書くか"を見ていてください。」

### ルートA：受け取る側 × 交渉できる場合

#### A-1. 不利条項の洗い出しと修正交渉案（8分）

**[1] プロンプトを入力する（1分）**

「今回の状況をプロンプトに書きます。テンプレートをそのまま使いつつ、立場だけカスタマイズします。」

以下をチャット欄に入力する（ファイルは先にアップロード済み）：

```
あなたは経験豊富な日本の企業法務の専門家です。
添付した契約書について、当社の立場から確認してください。

【当社の立場】
・受託側（Webシステム開発を請け負う中小企業）
・相手方から提示された業務委託契約書のチェックが目的
・条件交渉の余地はある

【出力してほしい内容】
1. 当社にとって著しく不利、またはトラブルの原因になりやすい条項を
   リスクの高い順に挙げてください（該当箇所を明記）
2. なぜそれがリスクなのかの理由（具体的なシナリオを交えて）
3. 相手方に提案すべき修正案（そのまま使える文言で）
```

「会社名・金額・日付はあらかじめマスキング済みのサンプルを使っています。プロンプトの末尾に契約書テキストを貼る方法でも全く同じように動きます。」

**[2] 出力を待つ（30秒〜1分）**

「出力されるまで少し待ちます。長い契約書だと1〜2分かかることもあります。そのときは分割して入力する方法もあります。」

**[3] 出力を読み解く（4〜5分）**

出力されたら、以下の順で解説する。

**着目1：最初に挙げてきた条項**

「AIが最初に挙げた条項を見てください。損害賠償の条項が先頭に来ていますね。」

→ 出力の該当箇所を画面上で指し示しながら補足：
「"一切の損害を賠償する"という表現は、上限がないという意味です。受託金額を大幅に超える賠償請求が来ても、法的には通る可能性がある。ここをAIはきちんと掴んでいます。」

**着目2：修正案の内容**

「修正案のテキストも出てきていますね。これをそのまま相手に送るのではなく、交渉のたたき台として使います。"こういう文言に変えてほしい"という具体的な提案ができると、交渉の入り口がずっとスムーズになります。」

**着目3：AIが見落としている可能性のある条項の確認**

「知財帰属の条項（第9条）も確認してみましょう。開発過程で生まれたツールや部品的なプログラムも含めて全部相手方のものになる、という内容です。AIがこの条項への指摘を弱めにしか出していない場合があります。重大な条項でも、AIが強調しないことはあります。」

→ 元の文書で確認する実演：
「AIが"第9条"と言っているか、元の文書で確認してみましょう。AIの指摘した条番号と実際の文書が一致しているかは、必ず自分の目で確かめる。これがハルシネーション対策の習慣です。」

**着目4：修正案を受け取った後のネクストアクション**

「これで洗い出しは完了です。次にやることは2つ。重大度の高い条項だけ弁護士に確認を入れるか、そのまま修正案を持って交渉に入るか。今日はこのプロセスが分かれば十分です。」

### ルートB：受け取る側 × のむしかない場合

#### B-1. リスクの優先度付けと社内対策（5分）

**[1] プロンプトを入力する（1分）**

「のむしかない場合は、聞き方が変わります。修正案を求めても意味がないので、"リスクの大きさ"と"自分たちでできる対策"を聞きます。」

```
あなたは経験豊富な日本の企業法務の専門家です。
添付した契約書について確認します。

【前提条件】
・この契約書は相手方の標準書式であり、条件の変更はほぼ見込めない状況です
・ただし事業上の理由からこの契約を締結する方向で進めており、
  リスクを正確に把握した上で対応策を検討したいと考えています

【当社の立場・状況】
・立場：受託側（コンテンツ制作を請け負う個人事業主に近い小規模企業）
・この契約の事業上の重要度：高（主要取引先からの依頼）

【確認してほしい内容】
1. 当社にとってリスクの高い条項を重大度順に3つ挙げてください
   （なぜリスクなのか、具体的なトラブルシナリオも添えてください）

2. 各リスク条項について、「契約条件を変えられない前提で当社側でできる
   現実的な対策」を具体的に提案してください
   （例：証拠を残す方法、社内ルールの整備、保険の活用、作業スコープの文書化など）

3. 条件変更が難しい状況でも、念のため確認・交渉を試みる価値のある条項が
   あれば、その理由と打診のアプローチ方法を教えてください
```

**[2] 出力を待つ（30秒〜1分）**

「出力されるまで少し待ちます。」

**[3] 出力を読み解く（3〜4分）**

**着目1：リスクの絞り込み**

「3つに絞って、重大度の順で出てきていますね。のむしかない場合は、全部の条項に同じように悩むのではなく、"何が一番怖いか"を最初に決めることが大事です。ここで優先度が見えると、次の行動が具体的になります。」

**着目2：社内対策の具体性を確認**

「社内対策の項目を見てください。たとえば検収条項のリスクに対して、"納品時の合意内容をメールで都度確認・記録に残す"という提案が出てきていますね。これは明日からできることです。契約書の文言は変えられなくても、運用でカバーできるものがある。それを具体的に出してくれています。」

**着目3：打診できる余地の確認**

「"これだけは打診してみる価値がある"という項目が出ていれば、それだけ交渉してみる。全部のむのとは違います。」

#### B-2. 弁護士相談のための要件定義と質問リスト（3分 ※時間があれば）

「リスクが分かったら、次は"どこを弁護士に確認するか"の準備です。AIにそのまま作らせます。」

```
先ほどのリスク分析結果を踏まえて、弁護士へ効率よく相談するための
準備資料を作成してください。

【状況の補足】
・のむしかない契約であることは理解している
・ただし法的リスクの大きさを弁護士に確認した上で最終的な判断をしたい
・弁護士との相談時間は30〜60分を想定している

【作成してほしいもの】

1. 相談背景のサマリー（3〜5行）
   ・誰と誰の間の、どんな取引の契約か
   ・当社の立場とこの契約の事業上の重要度
   ・条件変更が難しい理由

2. 弁護士に確認してほしい事項リスト
   ・条項ごとに：「何が問題か」「当社が懸念している具体的なシナリオ」
   ・「条件を変えられない場合、社内でこの対策を取ろうと思っているが
     法的に問題ないか確認してほしい項目」

3. 弁護士への質問リスト（5問以内）
   ・法的判断が必要な質問のみに絞る
   ・「Yes / No」または「選択肢A・B」で答えられる形にする
   ・優先順位を付ける（最重要→重要→確認程度の順）

4. 相談前に当社が自分で準備・確認すべきことリスト
```

「ここまでの出力を持って弁護士に相談すれば、30分で本題に入れます。何を聞けばいいか分からないまま相談するより、時間もコストも大幅に下がります。」

### ルートC：渡す側

#### C-1. 自社契約書の法的適合性・公平性チェック（4〜5分）

**[1] プロンプトを入力する（1分）**

「渡す側のチェックは少し視点が変わります。自分が提示している書類が法令上問題ないか、それから相手が"受け入れにくい"と感じる部分はどこかを確認します。」

```
あなたは経験豊富な日本の企業法務の専門家です。
添付した契約書は、当社が取引先に提示しているものです。

【当社の立場】
・委託者（デザイン業務を発注する中小企業）として相手方に提示する側
・相手方：フリーランスのデザイナー（個人事業主）

【確認してほしい内容】

① 法令違反の確認
現行の日本の法令（下請法・個人情報保護法・消費者契約法など）に
抵触する可能性のある条項はあるか。
該当する場合は根拠となる法令と修正の方向性を教えてください。

② 相手方が「不公平」と感じやすい条項の確認
相手方の立場から見て「受け入れにくい」「不当だ」と感じる可能性の高い条項を
指摘してください。特にフリーランス・個人事業主が相手の場合のリスクも
含めて教えてください。

③ 意図しない解釈が生まれやすい表現の確認
曖昧な表現や複数の解釈ができる条項があれば指摘してください。
当社に不利な方向で解釈された場合に何が起きるかも説明してください。

④ 抜け漏れの確認
この契約として機能するために追加すべき重要な条項があれば教えてください。

【出力形式】
各観点ごとに：該当条項の引用 → 問題の内容 → 修正案または追加すべき文言
```

**[2] 出力を待つ（30秒〜1分）**

「出力されるまで待ちます。」

**[3] 出力を読み解く（3〜4分）**

**着目1：法令違反の有無**

「法令に抵触する可能性のある箇所が出ていたら最優先で対応が必要です。知らずに使い続けていると、相手方から指摘される前にリスクが積み上がります。たとえば支払条件に関して、下請法上の問題が指摘されるケースがよくあります。出力を見ると、その観点での指摘も入っていますね。」

**着目2：相手が「不公平」と感じやすい条項**

「ここが渡す側ならではの視点です。自分では気づかないまま使っていた条項が、相手から見ると受け入れにくいものになっていることがある。契約交渉がスムーズに進まない理由がここにあることも多いです。」

**着目3：曖昧な表現の確認**

「意図しない解釈というのも見落とされやすい。"相当の期間内に"という表現は相手に有利にも不利にも解釈できます。どちらに転んでも問題ない表現なのか、確認しておく価値があります。」

#### C-2. 相手目線での交渉シミュレーション（3〜4分 ※時間があれば）

「もう一歩踏み込むなら、相手がどう反応してくるかをAIにシミュレーションさせることができます。」

```
添付した契約書を「相手方（受託側のフリーランス）」の立場に立って
読んでください。当社が提示したこの契約書に対して、相手方がどのような
反応・質問・修正要求をしてくると想定されるかを分析してください。

【相手方の立場設定】
・立場：フリーランスのデザイナー（個人事業主）
・この取引の重要度：相手方にとって比較的重要（初取引）

【確認してほしいこと】

1. 「これは受け入れにくい」と感じて修正を求めてくる可能性が高い条項を
   優先度順に3つ挙げてください。相手方が主張しそうな理由も添えてください。

2. 「この条項はどういう意味ですか？」と質問が来やすい曖昧な表現を
   指摘してください。

3. 「この条項があるなら契約を見送りたい」と感じる可能性のある条項が
   あれば教えてください。

4. 上記を踏まえて、当社が事前に修正しておくべき条項と、
   説明を準備しておくべき条項を区別して教えてください。
```

**出力を受けたら：**

「相手が修正を求めてくる条項と、説明すれば納得してもらえる条項が分けられましたね。前者は事前に直しておく。後者は打ち合わせで説明を準備しておく。これだけで契約交渉の時間が短くなります。」

#### C-3. 渡す側の弁護士相談のための要件定義と質問リスト（3分 ※時間があれば）

```
先ほどのチェック結果を踏まえて、弁護士へ効率よく確認するための
準備資料を作成してください。

【状況の補足】
・当社が取引先に提示している契約書のセルフチェックを行った
・AIのチェックでいくつかの懸念点が見つかった
・法的に問題がないかの確認と、必要な修正についてのアドバイスが欲しい
・できれば契約書全体が現行法令に適合しているかも確認してほしい

【作成してほしいもの】

1. 相談の背景説明（3〜5行）
   ・この契約書を誰に何のために使っているか
   ・今回確認が必要だと気づいた背景・きっかけ

2. 弁護士に確認してほしい事項リスト
   ・AIが指摘した懸念点のうち、法的判断が必要なもの
   ・「このまま使い続けて問題がないか」確認したい箇所
   ・修正が必要な場合にどう修正すべきかアドバイスが欲しい箇所

3. 弁護士への質問リスト（5問以内）
   ・優先順位付き
   ・「Yes / No」または「選択肢」で答えられる形に整える

4. 弁護士に渡すべき参考資料のリスト
   （現在の契約書、これまでの取引履歴の記録、相手方との合意メールなど）
```

## フェーズ2：ハンズオン（7〜8分）

### 書類持参ありの場合

「では今度は皆さんに実際に試していただきます。

まず持参いただいた書類を開いてください。

マスキングが必要な箇所を一緒に確認します。会社名・個人名・金額・日付、この4種類が基本です。テキストエディタで一時的に置き換えてから入力します。慣れれば2〜3分でできます。」

（マスキング作業中に確認）「この表現はどちらに分類しますか？迷ったら少し広めに伏せる方が安全です。」

マスキング完了後：

「先ほどのデモと同じプロンプトを使います。[ルートA / B / C]でしたね。"当社の立場"の部分だけ、実際の状況に合わせて書き換えてから入力してみてください。」

→ 入力・送信

出力されたら：

「出力を一緒に読みましょう。AIが指摘している箇所の中で、ご自身が実際に気になっていた箇所と重なるものはありましたか？逆に、気になっていなかったけれど指摘されたものはありましたか？」

→ ディスカッション（2〜3分）

---

### 書類持参なしの場合

「書類をお持ちでない場合は、こちらで用意したサンプルを使います。

[ルートA / B] の方には業務委託契約書のサンプルを用意しています。
[ルートC] の方には渡す側のサンプルも別途あります。

先ほどのデモで使ったものとは別のサンプルですので、結果も少し違ってくると思います。」

→ サンプルを共有し、受講者自身でプロンプトをカスタマイズして入力

出力されたら：

「ご自身のビジネスに当てはめると、この中のどれが一番気になりますか？」

→ ディスカッション（2〜3分）

## フェーズ3：デブリーフ（2分）

「一度止めましょう。

今日体験していただいたのは、基本的には同じ流れです。

1. プロンプトに状況を書く（立場・前提・聞きたいこと）
2. マスキングしたテキストを貼る
3. 出力された指摘を元の文書で確認する
4. 必要なら弁護士相談の準備をそのままAIに作らせる

テンプレートをそのまま使えば、この流れは1人で再現できます。

後半は質問の時間です。今日試しながら出てきた疑問も含めて、遠慮なくどうぞ。」

## 講師用サブノート

### タイムが余った場合の追加メニュー（優先度順）

1. **弁護士相談準備の実演**（実演でB-2またはC-3を省略した場合）
2. **プライバシーポリシーのチェック**（prompt_templates.md プロンプト3を使用）
3. **弁護士への相談メール文を作らせる**（prompt_templates.md 発展プロンプトを使用）

### タイムが足りなくなった場合の削り方

| 削れる箇所 | 短縮方法 |
|---|---|
| 実演の「着目4」 | 省略してデブリーフに移行 |
| C-2 交渉シミュレーション | 「時間があれば試せます」と説明のみで省略 |
| ハンズオンのディスカッション | 「出力が出たら確認だけして次へ」と短縮 |
| デブリーフ | 省略可。Q&Aの冒頭で一言まとめるだけでよい |

### サンプル契約書の問題条項リスト（demo_sample_contract.md 対応）

| 条項 | 問題点 | AIが指摘しやすいか |
|---|---|---|
| 第3条 再委託禁止 | 書面承諾なしの再委託全面禁止 | 指摘しやすい |
| 第4条 支払条件 | 翌々月末払い（最長60日サイト）| やや指摘しにくい |
| 第6条 検収 | 「甲の判断による」無期限化・異議申し立て禁止 | 指摘しやすい |
| 第7条 解除 | 甲のみ即時解除可能。乙の解除条件なし | 指摘しやすい |
| 第8条 損害賠償 | 上限なし「一切の損害（逸失利益含む）」 | 最初に指摘されやすい |
| 第9条 知財帰属 | 開発過程のツール・ライブラリも全部甲に帰属 | 見落とされやすいが重大 |
| 第11条 管轄 | 甲の本店所在地の専属管轄 | 指摘しやすい |

### デモ中に想定される誤出力と対応

| 想定される誤出力 | 対応方法 |
|---|---|
| 存在しない条項番号を引用する | 「良い機会です。元の文書で確認しましょう」とハルシネーション実演に転換 |
| 指摘が過少で重大な条項を見落とす | 「AIが見落とした箇所があります」と補足し、AIの限界として教育材料に使う |
| 指摘が過多で出力が長すぎる | 「実務では最初の3〜5つに絞って確認する」と優先度付けの話に展開 |
| 修正案の文言が不自然な日本語 | 「たたき台として使い、実際に使う前に自分で読み直す」と補足 |
