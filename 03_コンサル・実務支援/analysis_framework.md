# 業務分析フレームワーク（診断・課題構造化の型）

Ver 1.0 ／ 2026年5月作成
担当AI社員：策（さく）・財（ざい）・改（かい）

> 本フレームワークはヒアリング完了後〜6ヶ月計画策定前の「分析・設計フェーズ」で使用する。
> `detailed_hearing_sheets.md` で収集した情報をここで構造化する。

---

## STEP 1：収集情報の整理（ヒアリング後 即日）

### 1-A. 情報カテゴリへの仕分け

ヒアリングで得た情報を以下の4バケツに分類する。

```
┌─────────────────┬─────────────────┐
│  【経営課題】        │  【現場課題】        │
│                   │                   │
│ ・売上・利益の伸び悩み│ ・特定業務の工数過多  │
│ ・採用・人材不足     │ ・属人化・ブラックボックス│
│ ・事業継続リスク     │ ・ミス・品質のバラつき  │
│ ・競合との差別化不足  │ ・情報共有の断絶      │
├─────────────────┼─────────────────┤
│  【リソース制約】    │  【変革リスク】      │
│                   │                   │
│ ・予算の上限        │ ・現場の抵抗（誰が）   │
│ ・時間・人員の限界   │ ・キーパーソンの不在   │
│ ・技術スキルの限界   │ ・タイミングの問題    │
│ ・ツール導入の制約   │ ・経営者の本気度      │
└─────────────────┴─────────────────┘
```

### 1-B. 業務量データの集計

`detailed_hearing_sheets.md` の業務量調査表を集計し、以下を算出する。

| 業務名 | 月間工数（時間） | 担当人数 | 月間コスト（概算） | 課題の深刻度（1-5） |
|-------|--------------|--------|-----------------|-----------------|
| | | | | |
| | | | | |
| **合計** | | | | |

> コスト概算 = 月間工数 × 平均時給（中小企業目安：2,000〜3,000円/時）

## STEP 2：As-Is 現状マップ（ボトルネック特定）

### 2-A. 業務フロー図の作成

対象業務を「誰が・何を・どの順番で・どこに渡すか」でフロー化する。

```
フォーマット：

[開始] → [担当：○○] → [作業内容] → [所要時間] → [次へ渡す先]
                ↓
            ★ボトルネック（ここで詰まる理由）
                ↓
[担当：△△] → [作業内容] → [所要時間] → [完了/次の工程]
```

**ボトルネックを見つける3つの質問**
1. 「ここが終わるまで次が始まれない」場所はどこか？
2. 「ここだけ特定の人しかできない」業務はどこか？
3. 「ここでよくミスや手戻りが起きる」のはどこか？

### 2-B. 時間・コストの見える化マップ

```
業務カテゴリ別 コスト構成（円グラフイメージ）

例：
  事務・書類作成    ：35%（月120時間）
  コミュニケーション：25%（月85時間）
  データ収集・整理  ：20%（月70時間）
  承認・確認待ち    ：12%（月40時間）
  その他            ：8%（月27時間）
  ─────────────────────────────
  合計              ：月342時間 ≒ 年4,104時間
  年間コスト換算    ：約1,232万円（@3,000円/h）
```

### 2-C. 根本原因分析（5 Why）

ボトルネックに対して「なぜ」を5回繰り返す。

```
課題：「見積書作成に1件60分かかっている」

Why 1：なぜ60分かかるのか？
  → 価格表が複数のExcelに分散していて毎回確認が必要だから

Why 2：なぜ分散しているのか？
  → 担当者ごとに自分用の価格表を持っているから

Why 3：なぜ担当者ごとに持っているのか？
  → 共有の価格マスターが存在しないから

Why 4：なぜ共有マスターがないのか？
  → 「誰かが作るべき仕事」として認識されてこなかったから

Why 5：なぜ認識されてこなかったのか？
  → 管理業務の役割分担（誰が何を管理するか）が明確でないから

【根本原因】：業務管理の役割分担・責任の不明確さ
【解決策】：価格マスターの一元管理 + 更新ルールの制度設計
```

## STEP 3：To-Be 設計（あるべき姿の定義）

### 3-A. 理想状態の言語化

クライアントの「成功のイメージ」（ヒアリングで確認済み）を具体化する。

```
【To-Be 設計テンプレート】

対象業務：
現状（As-Is）：所要時間___分、担当___名、月___回
目標（To-Be）：所要時間___分、担当___名、月___回
改善率目標   ：時間___%削減、コスト___万円/年削減
実現方法     ：（AI活用・自動化・制度変更 等）
実現期限     ：___ヶ月後
```

### 3-B. To-Be業務フロー図

As-Is と同じ形式で、改善後の理想フローを描く。
- AI・ツールが入る箇所を明示
- 工数削減のポイントに★を付ける
- 手動→自動に変わる箇所を色分け

## STEP 4：優先度マトリクス（何から手をつけるかの決定）

### 4-A. 4象限マトリクス

全ての改善候補を以下に配置する。

```
        インパクト（大）
              ↑
  ┌───────────┬───────────┐
  │  【第2優先】  │  【最優先】   │
  │  難易度：高  │  難易度：低  │
  │  時間をかけて │  最初に着手  │
  │  取り組む    │  クイックウィン│
難←┼───────────┼───────────┼→易
  │  【後回し】   │  【第3優先】  │
  │  難易度：高  │  難易度：低  │
  │  インパクト小 │  余力があれば │
  │  基本的に保留 │  取り組む    │
  └───────────┴───────────┘
              ↓
        インパクト（小）
```

### 4-B. 優先度スコアリング表

| # | 改善施策 | インパクト（1-10） | 難易度（1=難・10=易） | 総合スコア | 優先度 |
|---|---------|----------------|-------------------|----------|--------|
| 1 | | | | | |
| 2 | | | | | |
| 3 | | | | | |

> 総合スコア = インパクト × 難易度　高いほど先着手

### 4-C. 最初の3ヶ月で狙うべき「クイックウィン」の選定基準

```
以下を全て満たすものを最優先に選ぶ：
□ 効果が出るまで1ヶ月以内
□ 特定のキーパーソン1〜2人が対応できる
□ 既存ツール（ChatGPT等）で対応できる
□ 成功すれば他部署への横展開が可能
□ 失敗しても組織的ダメージが小さい
```
