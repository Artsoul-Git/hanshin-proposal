# 案件フォルダ 運用ルール

**Ver 2.0 ／ 2026年5月29日改訂**

> 本フォルダはクライアントごとの実務ドキュメントを管理する場所。
> `03_コンサル・実務支援/` は「型（テンプレート）」、こちらは「各クライアントの実データ」。
> **熟練コンサル企業の案件管理を前提とする：誰がいつ見ても、属人化せず、顧客情報・ナレッジ・進捗・公開物を迷わず特定できる状態を維持する。**

## ■ フォルダ命名ルール

```
YYYYMMDD_クライアント名_ステータス/

例：
  20260504_さくら就労支援センター_デモ/    ← デモ・参考用
  20260601_〇〇建設株式会社_Phase1/        ← 進行中
  20261201_△△法律事務所_Phase3顧問/       ← 顧問契約中
  20260901_□□製造_完了/                   ← 終了済み
```

|-----------|------|--------|
| デモ | デモ・参考事例 | ⚪ |
| 商談中 | ヒアリング〜提案段階 | 🟡 |

### 配置の判断基準（迷ったらこの表）

| 種類 | 配置先 | 理由 |
|------|--------|------|
| クライアント側からもらった資料（生データ） | `Knowledge/` | Kaiが直接参照する素材 |
| 整形済みの議事録・面談メモ | `01_ヒアリング記録/` `05_議事録/` | 時系列で並べる |
| 上村が整理した分析・要件 | `02_分析・要件/` | 設計の前段 |
| 提案書の最新確定版 | `03_提案書/` | 1本だけ |
| 提案書の試行・没案 | `03_提案書/_drafts/` | 物理隔離 |
| GitHub Pages公開中の成果物 | `10_PUBLISHED/{repo-name}/` | リポジトリ名一致 |
| 契約書・請求書・見積書 | `07_契約・請求/` | 会計連動 |
| もう使わないが残しておく | `99_archive/` | 削除しない |

## ■ 案件開始時の必修3点セット

ヒアリング後、**必ず以下3つを揃える**まで提案作業に入らない。

```
1. Knowledge/00_Kaiスターターパック.md   ← _templates から複製・記入
   → Kai自律判断チェックが全通過するまでKaiは提案書作成を開始しない
2. 00_README.md                          ← _templates から複製・記入
   → 案件サマリー・主要リンク・固有注意を集約
3. PUBLISH_MAP.md                        ← _templates から複製
   → 公開物が出る前から器を用意（未公開状態で開始）
```

### テンプレ配置

| ファイル | 配置 |
|---------|------|
| `00_Kaiスターターパック_テンプレート.md` | `05_クライアント案件/` 直下（既存） |
| `00_README_template.md` | `05_クライアント案件/_templates/` |
| `PUBLISH_MAP_template.md` | `05_クライアント案件/_templates/` |

## ■ 公開物管理ルール（最重要・新規）

### 鉄則

1. **ローカル `10_PUBLISHED/{folder}` のフォルダ名 = GitHubリポジトリ名**
   - 例：リポジトリが `Artsoul-Git/maru-proposal-2026` ならローカルは `10_PUBLISHED/maru-proposal-2026/`
   - URLから即ローカル位置が逆引きできる状態を保つ

2. **`_enhanced` 等の枝葉サフィックスは禁止**
   - 旧）`maru-proposal-2026_enhanced/`
   - 新）`10_PUBLISHED/maru-proposal-2026/`

3. **公開した瞬間に `PUBLISH_MAP.md` を更新する**
   - 公開URL・パスワード・最終コミットSHA・公開日を記録
   - 共有先・共有日も「3. 関係者への共有履歴」に記録

4. **試行錯誤のv系統は `_drafts/` に隔離**
   - v1〜vN・没案・派生実験は `03_提案書/_drafts/`
   - 最新確定版だけを `03_提案書/` 直下に置く

5. **公開作業前にKei明示承認の3点確認**（CONSTITUTION §3・§5）
   - GO？ / 想定読者？ / **パスワード**？
   - `123456` 等のテスト値で本番公開しない

### PUBLISH_MAP.md の必須記録項目

- 公開URL / パスワード / ローカルパス / リポジトリ / 最終公開日 / コミットSHA
- 公開停止履歴（旧URL）
- 関係者への共有履歴（誰にいつ何を渡したか・パスワード共有有無）
- 非公開ドラフトの所在

## ■ 更新ルール

| タイミング | アクション |
|-----------|----------|
| 面談・訪問 | 翌営業日中に `05_議事録/YYYYMMDD_*.md` 作成 |
| 公開物更新 | `PUBLISH_MAP.md` を同タイミングで更新（漏らさない） |
| ステータス変動 | `00_README.md` のステータスバッジ＋マイルストーン履歴を更新 |
| 提案書改訂 | バージョン番号を上げる（v1.0→v1.1）。旧版は `_drafts/` へ |
| 完了案件 | フォルダ名を「完了」にリネーム＋ステータスバッジを ⚫ に |
| デモ・サンプル | 「デモ」ステータスで実案件と物理区別 |

## ■ 横断管理（複数案件をまたぐ視点）

- 最新の案件ステータスは `01_経営管理/案件パイプライン.md` を参照
- 月次評価は `/eval-monthly` で全案件を横断確認
- 週次は `/eval-weekly` で進捗・Stop候補・Scale候補を抽出
