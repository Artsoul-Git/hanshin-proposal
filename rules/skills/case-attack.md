# /case-attack — 実行手順本体

> **文体規範継承宣言：** 本スキルは [`rules/writing-style-rules.md`](../writing-style-rules.md) を継承する。全出力に文体11ヶ条を自動適用する。加えて本スキル固有の **「完全マニュアル＝攻略マニュアル」原則**（[`rules/kai-style-guide.md`](../kai-style-guide.md)）を必修適用する。

---

## 0. このスキルの位置づけ

新規クライアント候補との商談を **「武器」で攻略するためのデモ資料セット一式** を1〜2営業日で生成する。

- **15ファイル全部入り**：クライアント共有7HTML＋社内5MD＋社外秘マニュアル2本＋ポータル1本
- **3層構造**：①クライアント共有可 ②社内専用ストーリー設定 ③社外秘営業ノウハウ
- **アプリ版ラシンバン完全機能継承**：マンダラ81セル→マトリクス→フロー→ガント連鎖
- **実データ出典必修**：会社固有情報のみ架空、市場統計・参照ブランドは公開実データ＋URL明記

起点ケース：越前刃心デモ（2026-04-10、福井・業務用刃物メーカー架空案件）

## 1. 入力素材（投入想定）

担当者（Kei）が以下のうち少なくとも3つを投入：

| 素材 | 例 | 必須度 |
|---|---|---|
| クライアント業種・規模 | 「業務用刃物メーカー／年商23億円」 | 必須 |
| 主要販路構造 | 「B2B卸代理店480社＋EC8チャネル」 | 必須 |
| 経営層の課題感 | 「卸経由でエンドユーザーが見えない」 | 必須 |
| 想定転用先（異業種） | 「医療メス／産業用ナイフ／海外プロ料理学校」 | 推奨 |
| 業界団体候補 | 「日本調理師会連合会／全国食品工業協会」等 | 推奨 |
| カラーテーマ指定 | 「和テイスト（墨黒×朱×金）」「青系」等 | 任意 |
| パスワード | 「demo2026」等 | 必須 |

## 2. 実行フェーズ（8段階）

### Phase 0：方針宣言（編集系ノンストップモード下では省略可）

「これから15ファイル生成します。クライアント共有7HTML＋社内5MD＋社外秘マニュアル2本。約1〜2営業日。何か事前に確認したい点ありますか？」

### Phase 1：要件整理＋業種選定（10〜30分）

Keiから提示された情報をもとに5案を生成（既存パターン）：
1. 業種A（既存B2B卸×後継者問題型）
2. 業種B（製造×海外展開模索型）
3. 業種C（中堅メーカー×直販構築型）
4. 業種D（伝統工芸×現代化型）
5. 業種E（特殊技術×異業種転用型）

各案に「事業規模／本質課題／異業種転用候補／業界団体機会」を1行ずつ提示。Kei選択を待つ。

### Phase 2：5MD生成（社内専用ストーリー設定）

選定案に従い以下5本を作成（`05_クライアント案件/Demo_{YYYYMMDD}_{企業名}/` 直下）：

| ファイル | 内容 | 量 |
|---|---|---|
| `00_クライアント基本情報.md` | 会社概要・代理店網・販売チャネル・戦略の核 | 80〜120行 |
| `01_社長ペルソナ.md` | 名前・年齢・経歴・性格・口癖・本当の悩み・ステークホルダー関係 | 100〜150行 |
| `02_財務業績情報.md` | 直近5期業績／販路別／代理店上位10社／コスト構造／業界外部指標 | 150〜200行 |
| `03_経営会議文字起こし.md` | 架空議事録2時間分（会長／専務／営業部長／職人頭との対話） | 300〜400行 |
| `04_現場ヒアリング.md` | 職人／営業部長／海外営業／顧客／給食センター等の4〜5本ヒアリング | 250〜350行 |

**禁則：** 実在企業との直接的関係はゼロにする（社名・住所・代表者は完全架空）。業界統計・参照ブランドは実データ。

### Phase 3：実データ収集（WebSearch並列）

クライアント業界の最新統計を10件並列WebSearchで収集：

```
1. 国内市場規模・推移
2. 海外市場規模・成長率
3. 業界の人口統計（従事者数推移）
4. 参照ブランド事例（同業3〜5社の戦略）
5. 関連業界団体（実在）
6. HACCP・規制等の法令動向（該当業界のみ）
7. 隣接市場5〜10領域の市場規模
8. EC・直販構造のトレンド
9. 後継者問題・事業承継統計
10. 海外展開事例
```

→ 結果をJSON化して保存。提案書HTML生成時の出典URL一覧として再利用。

### Phase 4：提案書HTML4本生成（4〜6時間）

`越前刃心デモ` の以下4本をテンプレに、コピー＋差し替え方式で生成：

| ファイル | テンプレ | 差し替え方針 |
|---|---|---|
| `proposal.html` | 提案①卸ルート再定義 | 12章構成維持／五箇条／7施策／4象限／12ヶ月ロードマップ／実データ出典必修 |
| `proposal_global.html` | 提案②グローバル戦略5路線 | 参照ブランド3〜5社の実戦略事例／5路線（国内3＋国外2）／24ヶ月ロードマップ |
| `proposal_association.html` | 提案③業界団体総会戦略 | 実在業界団体／2分マイクスクリプト／4本柱／3レーン並走 |
| `knife_channels.html` | リサーチ④新販路マップ10領域 | SVG散布図（顕在度×競合度）／10販路カード／重点3販路深掘り／90日プラン |

**カラーテーマ**：業種に合わせて変更（食品=深緑／建材=オレンジ／IT=青／伝統工芸=墨×朱×金 等）

**共通UI必修**：
- パスワードゲート（Phase 1で指定されたPASS）
- 右下「↑トップ」ボタン
- ナビバーscroll変色
- 右端「📋 ポータル」ボタン
- 出典セクション（実データURLのみ）

### Phase 5：ラシンバン3本生成（3〜4時間）

`08_アプリ開発事業部/outputs/rashinban/rashinban-template.html` の完全機能を継承し、DATA部分のみを書き換え。

**書き換え対象（HTML/CSS/JSは触らない）：**

```javascript
const DATA = {
  meta: { theme, background, targetPeriod, constraints, createdAt },
  kai: { summary, coreIssue, topPriority, consultantVerdict,
         strengths[3], risks[3], themeInsights[8] },
  mandala: {
    center: "中央テーマ",
    themes: [/* 8テーマ × 各items[8] = 64アクション */]
  },
  matrices: [/* 8テーマの4象限マトリクス */],
  flows: [/* 主要3〜5項目の詳細フロー(5〜7ステップ＋kaiHint) */],
  gantt: {
    title, totalWeeks,
    phases: [/* フェーズ別タスク＋linkTo（matrix/flow/dashboard連動） */]
  }
};
const SK = 'rsh_{案件英語名}_1/2/3'; // localStorage独立キー
```

**守るべき仕様：**
- マンダラ81セル（中央1＋テーマ8＋tr8＋item64）
- テーマセルクリック→該当マトリクス遷移
- マトリクス項目クリック→該当フロー（未定義時は動的フロー＋プロンプト生成）
- ガントタスククリック→linkTo連動
- ヘッダー進捗バー＋localStorage完了管理

### Phase 6：ポータルindex.html＋出典セクション仕上げ（1時間）

**index.html 絶対要件：**
- パスワード記載は本文に絶対入れない（営業時にURL共有するため）
- デモ資料セット欄（社内MDへのリンク）は入れない
- 7カード（提案書3＋構造分解3＋リサーチ1）配置
- カラーテーマ統一

### Phase 7：社外秘マニュアル2本生成

`05_クライアント案件/Demo_{YYYYMMDD}_{企業名}/` 直下に：

1. `99_案件獲得攻略マニュアル_社外秘.md`（編集用Markdown・30KB前後）
2. `99_案件獲得攻略マニュアル_社外秘.html`（閲覧用HTML・図解付き）

**必修10章構成：**
1. このマニュアルの位置づけ
2. デモ資料セット全体像（社外用vs社内用切り分け）
3. 営業・提案での活用シーン5パターン（A〜E）
4. デモを見せる時の話法・流れ（10分標準シナリオ）
5. 新規デモ資料の作成手順（Step 1〜8）
6. AIへの指示文例（プロンプト集A〜F）
7. クライアント別カスタマイズ実例
8. よくある質問・反論への切り返し
9. 受注後の次ステップ
10. 運用ルールとファイル管理

**`.gitignore` 追加必修**：
```
**/99_案件獲得攻略マニュアル_社外秘.md
**/99_案件獲得攻略マニュアル_社外秘.html
05_クライアント案件/Demo_*/00_クライアント基本情報.md
05_クライアント案件/Demo_*/01_社長ペルソナ.md
05_クライアント案件/Demo_*/02_財務業績情報.md
05_クライアント案件/Demo_*/03_経営会議文字起こし.md
05_クライアント案件/Demo_*/04_現場ヒアリング.md
```

### Phase 8：preview実機検証＋Inspect 4点

`.claude/launch.json` に `{client}-proposal` エントリ追加 → preview起動 → 全7HTML動作確認：

| Inspect | 検査内容 |
|---|---|
| **I1 実装テスト** | マンダラ→マトリクス→フロー→ガント→マトリクスの連鎖動作（3パターン以上） |
| **I2 リンク切れ** | href先のid存在確認（hooks + html-validator） |
| **I3 版番号同期** | 「v1.0」「2026-04-10」等の表記揺れ全件Grep |
| **I4 SVG座標スケール** | knife_channels等の散布図でバブル位置とラベル位置が±5px以内一致 |

コンソールエラー0件を確認。

## 5. 反論集（営業現場で頻出）

| 反論 | 切り返しの核 |
|---|---|
| 「AIで作ってるなら安くなるはず」 | 「AIは手を動かしてもらってますが、設計と判断は私が全部やっています。出典確認・数値検証・矛盾チェックに一番時間がかかります。」 |
| 「うちみたいな小さい会社にここまで必要？」 | 「料金は出すドキュメントの数に比例します。3つに絞った構造分解だけでもお作りできます。」 |
| 「うちの業界はAIなんて使えない」 | 「AIは"見えない裏方"として、ヒアリング分析・提案書下書き・施策アイデア量産で使います。フロントは全部、貴社の人と私です。」 |
