そもそも .envファイルって何？

一言で言うと「パスワードだけを書いておく金庫メモ」。プログラムのコードとは別ファイルに分けることで、コードを誰かに見せても秘密の値は守られる。

たとえば、お店の金庫の暗証番号を考えてみましょう。

  • 店舗マニュアル（誰でも見るもの）に「金庫番号は1234」と書いてしまうと危険
  • 番号だけを別の金庫メモに書いて、マニュアルからは「金庫メモを参照」と書いておく → 安全

これと同じ構造です。

役割例え実際のファイル
店舗マニュアル（コード）誰でも見られる手順書server.py
金庫メモ（シークレット）番号だけ書いた非公開メモ.env
「メモを見て」という指示「金庫メモを参照」という記述os.environ.get("GROQ_API_KEY")
なぜ分けるのか コード（server.py）は Claude Code や GitHub で共有することがある。でも .env は絶対に共有しない。この分離があることで「コードを見せてもキーは守られる」という状態が作れる。

ファイル名の決まり

ファイル名は必ず .env（それだけ）

書き方正しいか備考
.env✅ 正しいこれだけでOK
kai-tasks.env⚠️ 動くが非推奨プログラムが自動で読まない場合がある
.env.local⚠️ 条件付きでOKフレームワークによる、ここでは使わない
env.txt❌ NG拡張子が違う
env❌ NG先頭のドット（.）が必要
Windowsでの注意点 Windowsのエクスプローラーは「.」（ドット）で始まるファイルを隠しファイル扱いにすることがある。メモ帳で保存するとき「.env.txt」になってしまう罠に注意（後述の手順で回避）。

エンコード（文字コード）の話

UTF-8 で保存する。それだけ覚えておけばOK。

「エンコード」とは、文字をパソコンが扱えるデータに変換する方式のことです。日本語テキストは特にこの設定を間違えると文字化けします。

エンコード名.envファイルに使えるか備考
UTF-8✅ 推奨世界標準。これを選ぶ
UTF-8 BOM付き⚠️ 基本OK一部ツールで問題が出ることがある
ANSI / Shift-JIS❌ 非推奨日本語が文字化けする危険
UTF-16❌ NGプログラムが読み込めない
Groq APIキーは英数字のみなので文字化けは実質起きない gsk_ から始まるキーはすべて半角英数字なので、エンコードを間違えてもキー自体は動くことがほとんど。ただし将来コメントや日本語を書くときのために、最初から UTF-8 で習慣づけておくことを推奨。

Step 1：.envファイルを作る

3つの方法を用意しました。初心者には「方法A（メモ帳）」が一番わかりやすいです。

A. メモ帳を使って作る方法

1メモ帳を開く

スタートメニューで「メモ帳」と検索して開く。または Win + R キーを押して notepad と入力してEnter。

2以下を1行だけ入力する
GROQ_API_KEY=gsk_ここに自分のキーを貼り付ける
書き方のルール
  • =（イコール）の前後にスペースを入れない
  • 値（キー）をクォート（" "）で囲まない
  • 行末に余計なスペースを入れない
  • 改行は最後の1行でOK（空行があっても問題なし）
3「名前を付けて保存」で保存する（ここが重要）

メモ帳のメニュー → ファイル → 名前を付けて保存

  • 保存先： 08_アプリ開発事業部\outputs\kai-tasks\ フォルダ
  • ファイル名： .env と入力（ダブルクォートで囲む → ".env"）
  • ファイルの種類： 「すべてのファイル (*.*)」を選択
  • 文字コード： 「UTF-8」を選択
ファイル名の入力は必ず ".env"（ダブルクォートで囲む） ダブルクォートなしで .env と入力すると、Windowsが自動で .env.txt に変えてしまう。ダブルクォートで囲むことで「拡張子なしのファイル」として保存できる。
4保存できたか確認する

エクスプローラーで kai-tasks フォルダを開く。.env というファイルが見えていればOK。

ファイルが見えない場合 エクスプローラーの「表示」タブ → 「隠しファイル」のチェックをONにする。ドットで始まるファイルはWindowsで隠しファイル扱いになることがある。

B. Kaiに頼む方法（おすすめ）

Claude Code のチャット欄に以下をコピーして送る。キー部分だけ自分のものに書き換えてから送ること。

08_アプリ開発事業部/outputs/kai-tasks/ フォルダに .env ファイルを作成して。
中身は1行だけ：

GROQ_API_KEY=gsk_ここに自分のキーを貼り付ける

UTF-8エンコード、改行コードはLFで保存してください。
ファイル名は必ず「.env」（ドットenv、拡張子なし）にしてください。
この方法が「おすすめ」な理由 Kaiが正しいエンコード・改行コード・ファイル名で自動作成してくれる。メモ帳の「拡張子がtxtになる罠」を回避できる。

C. ターミナル（PowerShell）で作る方法

Claude Code のターミナル欄（先頭に ! を付けて実行）で以下を入力する。

# PowerShell — ! を頭に付けてClaude Codeのターミナルから実行
! Set-Content -Path "08_アプリ開発事業部\outputs\kai-tasks\.env" `
  -Value "GROQ_API_KEY=gsk_ここにキーを貼る" `
  -Encoding UTF8
注意 gsk_ここにキーを貼る の部分を自分の実際のキーに置き換えてから実行すること。このコマンドはコマンド履歴に残るため、実行後は以下で履歴を確認・削除すること： 
# 実行後に履歴から削除する（任意）
! Clear-History

Step 2：.gitignoreに追加する（キー流出を防ぐ）

.env ファイルは「絶対にGitで管理してはいけないファイル」。これを Git に伝えるのが .gitignore の役割。

まず「プロジェクトルート」を理解する

プロジェクトルートとは、プロジェクトの「一番上のフォルダ」のことです。このプロジェクトでは：

C:\Users\kei\Dropbox\00_Antigravity\AS_AI導入支援事業_cc\

このフォルダが「プロジェクトルート」です。フォルダの中身はこんな構造になっています：

AS_AI導入支援事業_cc\　　← ここがプロジェクトルート ├── .gitignore　　　　　← このファイルを編集する ├── CLAUDE.md ├── 07_マニュアル\ ├── 08_アプリ開発事業部\ │ └── outputs\ │ └── kai-tasks\ │ ├── .env　　← Step 1 で作ったファイル │ └── server.py └── （その他のフォルダ）

.gitignore ファイルを探す

1.gitignore の場所を確認する

Claude Code のチャット欄で以下を送ると現状を確認できる：

プロジェクトルート（AS_AI導入支援事業_cc\）に .gitignore ファイルはありますか？あれば中身を表示して。

.gitignore に .env を追加する

2以下をそのままKaiに送る
プロジェクトルート（AS_AI導入支援事業_cc\）の .gitignore に以下を追加してください。
なければ新規作成してください。

# API keys / secrets
.env
*.env
.env.local
.env.*.local
追加後の .gitignore の中身（例） 
# API keys / secrets
.env
*.env
.env.local
.env.*.local

# Python
__pycache__/
*.pyc

（その他の既存の内容はそのまま残す）
.gitignore の仕組み（読まなくてもOK）

Git は「変更をスナップショットとして記録するシステム」。.gitignore に書いたファイルは「このファイルの変更は記録しないで」という除外リスト。除外されたファイルは git commit しても記録されず、GitHub に push しても送られない。

既に .env を git に追加してしまった場合 もし過去に .env を誤って git commit した場合は、そのキーは 即座に無効化（Groqコンソールでキーを削除） して再発行すること。.gitignore を追加しても、過去のコミットに含まれたキーは消えない。

困ったときのQ&A

Q. .envファイルが見つからない / 開けない

A. エクスプローラーで隠しファイルを表示する エクスプローラーのアドレスバーに対象フォルダのパスを貼り付けて移動 → 「表示」タブ → 「隠しファイル」にチェック。ドット（.）で始まるファイルはデフォルトで非表示になっている。

Q. .env を保存したら「.env.txt」になってしまった

A. ファイル名を変更する エクスプローラーでファイルを右クリック → 「名前の変更」→ .env.txt を .env に変更。または削除して、方法B（Kaiに頼む）でやり直す。

Q. GROQ_API_KEY が見つからないというエラーが出る

A. 確認ポイント3つ
  1. .env ファイルが kai-tasks フォルダ直下にあるか（server.pyと同じ場所）
  2. ファイル名が正確に .env（.env.txt になっていないか）
  3. サーバーを再起動したか（.envの変更はサーバー再起動後に反映）

Q. キーを間違えて git commit してしまった

A. 即座にキーを削除・再発行する
  1. console.groq.com/keys を開く
  2. 該当キーを「Delete」で削除（即座に無効化）
  3. 「Create API Key」で新しいキーを発行
  4. 新しいキーを .env に書き直す
git の履歴からキーを削除するのは複雑な作業が必要。それよりキー自体を無効化する方が確実で早い。

Q. Groqの無料枠を使い切ってしまった

A. 翌日にリセットされる 制限は「1日あたり」なので、日付が変わると自動リセットされる。Kai Tasksは1日20〜50回程度の想定なので通常は使い切らない。もし頻繁に超える場合は llama-3.1-8b-instant（14,400回/日）に切り替えるか、有料プランを検討する。

管理ルールまとめ

やること ✅やってはいけないこと ❌
ファイル名を .env（ドットenvのみ）にする.env.txt や env.txt にしてしまう
UTF-8で保存するエンコード指定なしで保存（文字化けリスク）
.gitignore に .env を追加する.gitignore への追加を忘れてgit commitする
キーはアプリごとに分けて発行する1つのキーをすべてのアプリで使い回す
漏れたらすぐ削除・再発行する「たぶん大丈夫」でそのまま使い続ける
サーバーのcodeにキーを書かずos.environ.getで読むserver.pyの中に直接キーを書く
