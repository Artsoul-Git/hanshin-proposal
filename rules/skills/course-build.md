# /course-build スキル

**用途:** テーマと対象者を受け取り、受講者が気づいたらゴールにたどり着いているカリキュラムを設計する。
セミナー・オンライン講座・社内研修・ワークショップ等、あらゆる「教えるコンテンツ」に対応。

---

## 発動条件

ユーザーが `/course-build` を入力したとき、または「カリキュラムを設計して」「講座の構成を作って」と依頼があったとき。

---

## 基本哲学（Kai の設計原則）

> **受講者に与えた変化量こそがコンテンツの価値である。**
> 量でも情報密度でもなく、受講者が最短最速でゴールに到達できるかが唯一の品質基準。

- 網羅性より到達率：知っていることを全部詰め込むのは悪い設計
- 1コンテンツ = 1主張：消化不良を防ぐ
- 完成主義より完了主義：「正解は市場が決める」—まず届けて検証する

---

## フロー

### STEP 1: ヒアリング（1回で聞き切る）

以下の形式でまとめて質問する。

```
カリキュラムを設計します。以下を教えてください。

■ 基本情報
1. コンテンツのテーマ（例：ChatGPT業務活用、糖質制限ダイエット）
2. 想定受講者（例：中小企業の事務担当者、料理初心者の主婦層）
3. 受講形式（例：60分セミナー、10時間オンライン講座、半日ワークショップ）
4. 受講者の現状（知識・スキルレベル）
5. 到達してほしいゴール（具体的な行動・状態で）

■ 設計方針
6. 自分が「確実に約束できる」ゴールか？（YES/NO + 理由）
7. 参考にしたい既存の競合コンテンツ・書籍はあるか？（あれば）
8. 盛り込みたい必須コンテンツ・絶対に外したいコンテンツはあるか？
9. 成果物として何が欲しいか（例：セクション/レクチャー一覧、台本骨子、完全な設計書）
```

ユーザーの回答を受けたら STEP 2 へ。

---

### STEP 2: 受講者診断（スタート地点・ゴール地点の定義）

ヒアリング情報をもとに、以下の3軸で受講者の状態を言語化する。

```
[受講者診断]
■ 現状（スタート地点の背景）
 → 受講者が今いる状態・知識レベル・使っている言葉

■ 障壁（なぜ自力では前に進めないか）
 → Googleや書籍で調べても解決できない理由・よくある誤解

■ 理想（ゴール地点）
 → 受講後に取れるようになる行動・状態（動詞で表現）

[スタート地点の定義]
「〇〇の状態で悩んでおり解決したいが、△△という障壁があるため前に進めていない」

[ゴール地点の定義]
「〇〇ができる/〇〇の状態になる」

これで設計を進めます。よいですか？
```

> ⚠ ゴールが「約束できない範囲」の場合は、スコープを絞るか、先に準備が必要な旨を伝える。

承認を得たら STEP 3 へ。

---

### STEP 3: マイルストーン洗い出し

スタート地点からゴール地点の間を埋める「受講者に踏んでほしいステップ」を3軸で書き出す。

**3軸マイルストーン法：**

| 軸 | 問い | 役割 |
|----|------|------|
| **マインドセット** | 受講者が持つべき考え方・捨てるべき思い込みは何か | 行動の土台 |
| **ノウハウ** | ゴール到達に必要なスキル・知識をステップ順に並べると？ | 具体的手順 |
| **ツール** | ゴール達成を助ける道具・テンプレート・仕組みは何か | 実行補助 |

> ※ まず自分の頭から出し切る。その後に競合や外部情報で補完する（順番を守ること）。

---

### STEP 4: アウトライン構築（セクション設計）

マイルストーンをグルーピングしてセクションを作る。

**セクション順序の3チェック：**
1. マインドセットが先、ノウハウは後になっているか
2. 抽象・概念が先、具体・手順は後になっているか
3. スタートからゴールへ最短最速で到達できる順番か

**基本フレーム（カスタマイズ可）：**
```
Section 0: はじめに（モチベーション・概要・全体像）
Section 1〜N: 本編（マインドセット → ノウハウ → ツールの流れ）
Section Last: 終わりに（振り返り・次のアクション）
```

各セクション内のレクチャーは「1レクチャー = 1主張」の原則で設計する。

---

### STEP 5: レクチャー内容の設計

各レクチャーは以下の2層構造で組み立てる。

**レクチャー構造：**

```
【層1: 主張（シンプルで主観的な1文）】
  → 尖っていて、中立ではなく、特定の人に刺さる言葉で

【層2: 説明（4要素で組む）】
  ① Why（なぜ）   : 主張に至った理由（自分視点）＋ 受け入れるメリット（相手視点）
  ② What（根拠）  : データ・引用・メカニズム・事例など客観的証拠
  ③ How（方法）   : ステップ形式でやり方を提示（ノウハウ型レクチャーのみ）
  ④ 事例/たとえ話 : 理解を助ける具体例・メタファー・よくある失敗

【ファン化要素（任意・推奨）】
  → 著者自身のエピソード・価値観・ストーリーを組み込む
  → 感情が動く具体的なエピソード + 主張との接続
```

**伝達順序（結論サンドイッチ構造）：**
```
① 主張（結論）
② 説明（Why/What/How/事例 + ファン化要素）
③ 主張の再提示（結論の確認）
```

---

### STEP 6: タイトルの研ぎ澄まし

セクション名・レクチャー名は受講者の「見たい」を引き出す言葉に磨く。

**命名のポイント：**
- 受講者が使っている言葉をそのまま使う（講師側の言葉に翻訳しない）
- 結果・変化・気づきが伝わるタイトルにする
- 抽象的すぎず、具体的すぎず（「全体設計入門」より「知らないと迷子になる3つのルール」）

---

### STEP 7: 3視点レビュー（推敲）

完成したアウトラインを3つの視点で見直す。

| 視点 | 確認すること |
|------|-------------|
| **虫の目（細部）** | 各レクチャーの主張は明確か。1レクチャー1主張になっているか |
| **鳥の目（全体）** | セクションの順番は受講者目線で自然か。漏れ・重複はないか |
| **魚の目（流れ）** | スタート地点からゴール地点へ、滑らかにたどり着けるか |

> 修正は「成長の証拠」として前向きに繰り返す。最初の草稿はほぼ必ず荒削り。

---

### STEP 8: 成果物の出力

ブリーフィング承認後、以下の形式で設計書を出力する。

```markdown
# カリキュラム設計書

## 基本情報
- テーマ：〇〇
- 対象者：〇〇
- 形式・時間：〇〇

## 受講者診断
- スタート地点：〇〇
- 障壁：〇〇
- ゴール地点：〇〇

## カリキュラム構成

### Section 0: はじめに
- Lec 01: 〇〇（主張：〇〇）
- Lec 02: 〇〇（主張：〇〇）

### Section 1: 〇〇
- Lec 03: 〇〇（主張：〇〇）
  - Why：〇〇
  - What：〇〇
  - How：〇〇
  - 事例：〇〇
  - ファン化：〇〇（あれば）
...

### Section Last: 終わりに
- Lec XX: 〇〇
```

成果物レベルはヒアリング時の回答（セクション一覧のみ / 完全設計書）に合わせて調整する。

## 品質チェックリスト

### 設計チェック
- [ ] スタート地点・ゴール地点が「現状×障壁→理想」の3軸で定義されているか
- [ ] 約束できないゴールが設定されていないか
- [ ] マインドセットがノウハウより前に配置されているか
- [ ] 1レクチャー = 1主張の原則が守られているか
- [ ] 余分な「雑学」「自分語り」が削除されているか

### 受講者視点チェック
- [ ] 受講者の言葉がそのまま使われているか（講師語に翻訳していないか）
- [ ] スタートからゴールまで受講者目線で歩いてみたか
- [ ] 足りないセクション・レクチャーを追加したか
- [ ] 不要なセクション・レクチャーを削除したか

### 伝達チェック
- [ ] 各レクチャーに主張が存在するか
- [ ] Why/What/事例の3要素が最低限あるか
- [ ] ファン化要素（ストーリー・価値観）が少なくとも数箇所あるか
- [ ] タイトルが受講者の「見たい」を引き出す言葉になっているか
