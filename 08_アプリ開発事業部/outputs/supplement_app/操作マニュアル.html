1. アプリ概要

Nolia はサプリメント継続サポートを目的としたモバイルWebアプリです。利用者は毎日の体重・気分・サプリ服用を記録し、週次AIレポートやバイオリズム分析でモチベーションを維持します。

項目内容

フロントエンドHTML/CSS/JS（GitHub Pages）
バックエンドGoogle Apps Script（GAS）Web App
データベースGoogleスプレッドシート
AI機能Gemini API（AIフィードバック・週次レポート・占い）
認証トークン方式（UUIDをメールで送信）

3. 管理者操作
3-1. ユーザーの招待
  1. スプレッドシートを開く → 拡張機能 → Apps Script
  2. GASエディタの上部ドロップダウンから inviteUser 関数を探す（Admin.gs内）
  3. または管理者用URLから直接招待メールを送信する
💡 補足 招待するにはスプレッドシートの users シートに手動でメールアドレスを追加してから inviteUser を実行するか、管理者ページ（/admin/）から操作できます。
3-2. 週次レポートの送信

Reports.gs の sendWeeklyReports 関数を毎週月曜に手動または時間トリガーで実行します。

  1. GASエディタ → sendWeeklyReports を選択 → 実行
  2. またはGASの「トリガー」設定で毎週月曜 7:00 に自動実行を設定
3-3. コンテンツの追加（ヘルスガイド）

ヘルスガイドの「ヘルスコンテンツ」セクションに記事や体験談を追加できます。

  1. スプレッドシートの content シートを直接編集
  2. カラム：content_id / user_id / type / title / excerpt / external_url / status
  3. type は tip（健康Tips）/blog（ブログ）/promo（特別提案）/testimonial（体験談）
  4. status を active にすると表示される

6. GASの修正・デプロイ
⚠️ 重要：ローカルファイルとGASエディタは別物 gas/フォルダのファイルを編集しても自動でGASに反映されません。必ずGASエディタに手動でコピーペーストする必要があります。
6-1. GASコードを修正する手順
1
ローカルの .gs ファイルを編集（Claude Codeで依頼するか直接編集）
2
スプレッドシートを開く → 拡張機能 → Apps Script
3
左メニューから対象の .gs ファイルを選択 → Ctrl+A → Delete → 貼り付け（Ctrl+V）→ Ctrl+S
4
デプロイ → デプロイを管理 → 既存のデプロイを選択 → ✏️編集ボタン → 「新バージョン」を選択 → デプロイ
💡 新バージョン vs 既存バージョン 「新バージョン」を選ぶと URLが変わらずコードだけ更新されます。「既存バージョン」のままだと変更が反映されません。必ず「新バージョン」を選んでください。
6-2. GASのランタイム設定

このプロジェクトは V8ランタイム（Chrome V8）を使用しています。Rhinoモード（レガシー）では const/let/アロー関数などES6構文が使えず全関数が壊れます。

確認方法：GASエディタ → ⚙️ プロジェクトの設定 → 「Chrome V8 ランタイムを有効にする」にチェックが入っているか確認

6-3. 古いバージョンの削除

デプロイ → デプロイを管理 → 削除したいバージョンの 🗑️ アイコンをクリック。現在アクティブなバージョンは削除できません。

7. デモデータの管理

デモ用データの挿入・削除は DemoData.gs の関数で行います。

デモデータを入れる手順
1
既存のデモデータがある場合は先に削除：GASエディタで deleteDemoData を実行
2
ローカルファイルを最新版に更新してからGASエディタに貼り替え：
08_アプリ開発事業部\outputs\supplement_app\gas\DemoData.gs
3
insertDemoData を実行 → 「デモデータ挿入完了！」のトーストが出ればOK
関数内容
insertDemoData()スタート日・daily_log 74件・週次レポート12件を一括挿入。ユーザーIDは動的取得
deleteDemoData()LOG_DEMO・RPT_DEMOプレフィックスの行を全削除
📅 デモデータの日付について デモデータのSTART日（現在 2026-02-17）を変えると連続記録の日数が変わります。今日を最終日にするには「today − 87日」をSTARTに設定してください。変更後は deleteDemoData → insertDemoData の順で再実行します。
8. トラブルシューティング
GASで「不明なエラーが発生しました」
原因対処
V8ランタイムがOFFになっている ⚙️プロジェクトの設定 → 「Chrome V8 ランタイムを有効にする」にチェック
他のファイルに構文エラーがある（1ファイルのエラーで全関数が止まる） 各.gsファイルを順番に確認。ファイルを保存し直すとキャッシュがリフレッシュされることがある
スプレッドシートから開いていない script.google.comから直接開くと getActiveSpreadsheet() がnullになる。スプレッドシート → 拡張機能 → Apps Script から開くこと
GASキャッシュ問題（コード変更後も古い動作をする） 別の小さな関数を追加して保存・実行を繰り返すとキャッシュがリフレッシュされる
連続記録日数が0になる
原因対処
デモデータの最終日が今日より前 DemoData.gsのSTARTを「today − 87日」に更新してデモデータを再挿入
実際に最近ログが入っていない 正常動作。今日の記録を入れると streak が始まる
楽天・Amazonリンクが外部に飛ばない
原因対処
config.jsのURLが'#'のまま js/config.jsのRAKUTEN_URL/AMAZON_URLを実URLに変更してデプロイ
iOSのポップアップブロック 現在は<a target="_blank">タグを使用。ブラウザのポップアップ許可設定を確認
週次レポートが「まだレポートがありません」と表示される
原因対処
デモデータのuser_idと実際のログインユーザーのIDが違う deleteDemoData → insertDemoData を再実行（現バージョンはuser_idを動的取得）
weekly_reportsシートにデータがない insertDemoDataを実行してデータを挿入
エネルギー占いが0時に切り替わらない

現バージョンはJST基準（UTC+9）で日付を取得しています。ブラウザのlocalStorageに前日のキャッシュが残っている場合は、デベロッパーツール（F12）→ Application → Local Storage → nolia_fortune_YYYY-MM-DD のキーを手動削除してリロードしてください。

📞 困ったときは Claude Code（Kai）に「Noliaの〇〇が動かない」と伝えてください。セットアップ手順書・技術設計書・このマニュアルを参照しながら対処します。
