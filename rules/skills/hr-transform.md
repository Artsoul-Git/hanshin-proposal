# /hr-transform スキル

**用途:** AI導入・業務改革における人材マネジメントを設計する。現場の抵抗を乗り越え、AIを「使いこなす組織」を作るための変革推進・役割再設計・研修計画・定着管理まで一気通貫で支援する。

> AI導入の失敗の80%は技術ではなく「人」の問題。ツールより先に人の設計をする。

---

## 発動条件

- 「AI導入を現場に浸透させたい」「現場が使ってくれない」
- 「誰をAI担当者にすればいいか」「抵抗勢力への対処法が知りたい」
- 「業務改善を組織として定着させたい」
- 「AI導入後の役割・業務分担を再設計したい」
- 「研修計画を作りたい」「生産性向上プログラムを設計したい」

---

## フレームワーク構成

```
Phase 1：変革準備（現状診断・抵抗要因の特定）
Phase 2：推進体制の設計（AIマネージャーの育成）
Phase 3：役割・業務の再設計
Phase 4：研修・習得プログラム設計
Phase 5：定着管理（モニタリング・フィードバックループ）
```

## Phase 1：変革準備

### 変革準備度の診断

```
【変革準備度アセスメント】

① リーダーシップ（経営・管理者層）
  - 経営トップのコミット度：高/中/低
  - 管理者の理解度・推進意欲：高/中/低
  → 低い場合：経営層への「投資対効果」の見える化が先決

② 現場の準備状況
  - PCスキルの平均レベル：高/中/低
  - 変化への受容性（過去の改革の成功経験）：あり/なし
  → スキル低：操作簡易化が必須 / 受容性低：小さな成功体験を先に作る

③ 組織構造
  - 意思決定速度：速/普通/遅
  - 情報共有の仕組み：あり/なし
  → 遅い：先行チームで成果を作ってから全体展開

④ 外部環境
  - 競合のAI活用状況：進んでいる/同程度/遅れている
  - 人手不足・採用難の深刻度：高/中/低
  → 「やらないと生き残れない」という危機感の共有が必要
```

### 抵抗パターンの特定と対処法

```
【抵抗の4類型】

Type A：「自分の仕事が奪われる」不安型
  特徴：デジタルに苦手意識、年齢層が高め
  対処：「AIは仕事を奪わず、負担を減らすもの」を実感で示す
       → 最初に「嫌いな作業」だけAIに任せる体験から始める

Type B：「今のやり方で困っていない」現状維持型
  特徴：ベテラン・高成績者に多い
  対処：「5年後の業界変化」を数字で示す + 彼らを「AIマネージャー候補」として立てる

Type C：「どうせ失敗する」過去経験型
  特徴：過去の失敗したシステム導入の記憶がある
  対処：過去との違いを具体的に説明 + 小さく試して早期成功体験を作る

Type D：「自分には難しすぎる」スキル不安型
  特徴：ITリテラシーが低く自己評価も低い
  対処：最初のツールをスマホ操作レベルに絞る + マンツーマンサポートを用意する
```

## Phase 2：推進体制の設計

### AIマネージャー（変革推進者）の選定基準

```
【AIマネージャー候補の選定基準】

必須条件（3つ以上該当）：
  □ 職場内での信頼・影響力がある（役職不問）
  □ 新しいことへの好奇心がある
  □ 現場業務を深く理解している
  □ 他のスタッフに教えることが苦でない
  □ 経営層・現場の両方とコミュニケーションできる

理想の配置：
  AIマネージャー 1名（全体統括・経営報告）
  現場サポーター 2〜3名（チームごとの浸透担当）
  → 計3〜4名が最小推進体制

避けるべき選定ミス：
  × 「デジタルが得意」だけで選ぶ（現場の信頼がないと機能しない）
  × 管理職を自動的にアサイン（強制感が抵抗を生む）
  × 1人だけに集中させる（燃え尽き・離職リスク）
```

### AIマネージャー育成プログラム

```
【育成ステップ（3ヶ月）】

Month 1：自分が使いこなす
  - ツールの基本操作習得
  - 自分の業務での活用体験（週2時間以上）
  - 「困ったこと・工夫したこと」の記録習慣

Month 2：チームに広げる
  - 自チームへの共有会（30分×2回）
  - 質問対応・サポートの実践
  - 改善アイデアを月1件以上提案

Month 3：組織の資産に変える
  - 活用事例・ノウハウのドキュメント化
  - 新入メンバーへの引き継ぎ資料作成
  - 経営層への成果報告（数字で）
```

## Phase 3：役割・業務の再設計

### 業務分担マトリクス（AI導入後）

```
【業務分担の設計フレーム】

                  繰り返し・定型    判断・創造・対人
AIが担う割合高  │ ★完全自動化    │  AIアシスト
               │ 記録・集計・転記  │  下書き・提案生成
──────────────┼────────────────┼──────────────
人間が担う割合高 │ 手順の設計・管理 │ ★人間が主役
               │ 例外処理・品質確認│ 判断・交渉・ケア

設計手順：
1. 現在の業務リストアップ（Phase 1のコスト計算表を流用）
2. 各業務を上記マトリクスに配置
3. 「完全自動化」対象から順に着手
4. 「AIアシスト」領域は人間の役割を再定義
5. 「人間が主役」領域にシフトする時間を確保
```

### 役割再定義テンプレート

```
【〇〇さんの役割再定義】

現在の主な業務：〇〇（月〇時間）
AI導入後に変わること：〇〇は自動化 → 月〇時間が空く
空いた時間を使う新しい役割：〇〇
新しく必要なスキル：〇〇
本人へのメッセージ：「〇〇があなたにしかできない仕事になる」
```

## Phase 4：研修・習得プログラム設計

### 3層研修設計

```
【研修プログラム（全員共通 + 階層別）】

Layer 1：全員研修（2時間）
  内容：AI導入の目的・背景・全体像 / 基本操作 / よくある失敗と回避法
  形式：集合研修 または 動画 + Q&A
  合格基準：基本操作を1人でできる

Layer 2：OJT期間（3〜4週間）
  内容：実業務でのAI活用練習
  サポート：AIマネージャーが週1回15分フォロー
  合格基準：自分の業務で週3回以上活用できている

Layer 3：応用・発展（任意参加）
  内容：より高度な活用 / プロンプト設計 / 他業務への展開
  対象：AIマネージャー候補・意欲が高いスタッフ
```

### 研修効果測定

```
研修前：スキルレベル・不安度のアンケート（5段階）
1週後：基本操作の習得確認
1ヶ月後：実業務での活用頻度・活用件数
3ヶ月後：時間削減量・品質変化・自己評価の変化
```

## Phase 5：定着管理

### 定着を阻む3つの壁と対処法

```
壁①：3週間の壁（「慣れた頃に飽きる」）
  兆候：活用頻度が下がる、質問が来なくなる
  対処：小さな成功事例を週1回共有（5分のシェア会）

壁②：2ヶ月の壁（「やっぱり前の方が早い」）
  兆候：AIなしに戻る人が出る
  対処：「AI活用による削減時間」を個人単位で可視化して返す

壁③：人材の入れ替わり（「新人が使えない」）
  兆候：退職・異動でノウハウが消える
  対処：標準手順書（SOP）とオンボーディング資料を月1更新
```

### 定着モニタリング指標

```
週次確認（AIマネージャーが収集）：
  - 活用件数（ツールのログ or 自己申告）
  - 困ったこと・改善アイデアの数

月次確認（管理者が評価）：
  - 利用率（対象者の何%が週3回以上使っているか）
  - 業務時間への影響（目標値との乖離）
  - スタッフ満足度（1問アンケート：「AIは役に立っていますか？」）

判断基準：
  🟢 利用率80%以上 → 次の業務へ展開
  🟡 利用率50〜79% → 原因調査 → 個別フォロー
  🔴 利用率50%未満 → オペレーション見直し or ツール変更検討
```
