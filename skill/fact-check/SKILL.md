# fact-check スキル — 法務部

## 役割定義

**作り手（専門スキル）とは独立した批判的検証者として機能する。**

- 提案書・Brain記事を「承認者」の目で読む
- Kai が作ったものを Kai が検証することの限界を自覚し、可能な限り「別の文脈」で読み直す
- 合格を出すまで上村への提出を止める権限を持つ

---

## 起動条件

### 自動起動（クライアント向け成果物）
以下のスキルが完成報告を出した時点で、Kaiが自動的に本スキルを呼び出す：
- `/sme-ai-proposal` — 提案書HTML完成後
- `/write-brain-article` — Brain記事完成後
- `/company-setup` — AI組織設計完成後（CONSTITUTION・CLAUDE.md含む）

### 手動呼び出し（内部文書）
```
/fact-check [ファイルパス]
例：/fact-check 07_マニュアル/エージェント操作マニュアル.html
```
または「このドキュメントをファクトチェックして」と伝える。

---

## 起動前：チェック回数の確認（無限ループ防止）

**必ず最初に確認する。**

対象ファイルのヘッダー、または今セッションの会話履歴から `CHECK_COUNT` を取得する：

```
CHECK_COUNT = 0  → 通常チェックへ進む
CHECK_COUNT = 1  → 「前回差し戻し箇所のみ」の再チェックへ進む
CHECK_COUNT = 2  → Kai直接修正モードへ進む
CHECK_COUNT = 3  → エスカレーション（ループ停止）
```

CHECK_COUNTが不明な場合は 0 として扱う。

---

## チェック4軸

### F1. 数値・統計チェック
- **対象：** 数値・割合・金額・時間・件数・効果を示すあらゆる数字
- **確認内容：**
  - Knowledge内に出典があるか
  - 出典が明記されていない場合、WebSearchで照合する
  - 「約〜」「一般的に」「よく言われる」などの曖昧修飾語を検出する
  - シミュレーション値・推計値には「参考値」の注記があるか

```
検証アクション：
  出典あり  → ✅ 記録
  出典不明・WebSearch一致  → ✅（出典URL記録）
  出典不明・WebSearch不一致 → ⚠️ 要修正（差し戻し候補）
  確認不能  → ⚠️ 「参考値」明記を推奨
```

### F2. 固有名詞・法令チェック
- **対象：** サービス名・ツール名・制度名・法令名・行政名・企業名
- **確認内容：**
  - 正式名称が正確か（略称使用時は初出で正式名称を添えているか）
  - 法令名は現行の正式名称か（廃止・改正されていないか）
  - ツール・サービスの機能説明が最新の仕様と一致するか（WebSearch推奨）

```
検証アクション：
  正確  → ✅
  誤記・旧名称  → ⚠️ 要修正（正しい表記を明示して差し戻し）
  法令改正の疑い → WebSearchで確認 → 確認できなければ⚠️注記推奨
```

### F3. 主張の論拠チェック
- **対象：** 「〜だから〜になる」「〜により〜が改善する」などの因果関係
- **確認内容：**
  - 論理の飛躍がないか（前提→結論の間に説明不足の飛びがないか）
  - 断言している内容にKnowledge/外部根拠があるか
  - 「〜が可能です」「〜で解決できます」などの断言が実態に合っているか

```
検証アクション：
  根拠あり・論理一貫 → ✅
  飛躍あり・断言過剰 → ⚠️ 要修正（修正案を提示して差し戻し）
```

### F4. リスクワードチェック
- **対象：** 法的・倫理的・信頼損失リスクのある表現
- **確認内容：**
  - 個人情報・プライバシーに触れる記述（実名・連絡先・健康情報）
  - 著作権のある文章・画像の無断引用
  - 誇大広告・効果を保証する表現（「必ず」「確実に」「100%」）
  - 競合他社を不当に貶める表現

```
検証アクション：
  問題なし  → ✅
  要注意    → ⚠️ 具体的なリスクと修正案を明示して差し戻し
  即時削除  → 🚫 差し戻し（Kaiが代替表現を提案）
```

## 差し戻しフロー（無限ループ防止）

```
【1回目差し戻し（CHECK_COUNT: 0 → 1）】
  → 問題箇所を番号付きリストで明示
  → 「この箇所のみ修正後、/fact-check で再チェックを」と担当スキルに伝える
  → 再チェック時は指摘箇所のみ確認（全文再走査しない）

【2回目差し戻し（CHECK_COUNT: 1 → 2）】
  → Kaiが直接修正を試みる
  → 修正後、自ら再チェック（CHECK_COUNT: 2のまま）
  → 修正できた場合 → 合格として処理
  → 修正できない場合（情報不足など）→ エスカレーションへ

【3回目 = エスカレーション（CHECK_COUNT: 3）】
  → チェックループを停止する
  → 上村に以下を報告：
    「[成果物名] のファクトチェックで解決できない問題があります。
     問題箇所：[具体的に]
     解決に必要なこと：[情報 / 判断 / 外部確認]
     判断をお願いします。」
  → 上村の判断を待つ（推測で進まない）
```

## チェック完了後：判定と報告

### 判定区分

| 判定 | 条件 | 次のアクション |
|------|------|--------------|
| ✅ 合格 | 全F1〜F4が問題なし | persona-review へ進む（自動）または完了報告 |
| ⚠️ 要修正 | 修正可能な問題あり | 差し戻し（CHECK_COUNTをインクリメント） |
| 🚫 エスカレーション | 3回差し戻し または 即時削除レベル | 上村へ報告・ループ停止 |

### 報告フォーマット（合格時）

```
【fact-check 完了レポート】
対象：[ファイル名]
実行日時：[YYYY-MM-DD HH:MM]
CHECK_COUNT：[n]

F1. 数値・統計：✅ [確認件数]件確認 / WebSearch照合 [件数]件
F2. 固有名詞・法令：✅ [確認件数]件確認
F3. 主張の論拠：✅ 論理飛躍なし / ⚠️ [修正した内容]
F4. リスクワード：✅ 問題なし

判定：合格
次工程：persona-review へ進みます
```

### 報告フォーマット（差し戻し時）

```
【fact-check 差し戻しレポート】
対象：[ファイル名]
実行日時：[YYYY-MM-DD HH:MM]
CHECK_COUNT：[n] → [n+1]

要修正箇所：
  [1] F1 / 箇所：[引用] / 問題：出典不明 / 修正案：「参考値」明記または削除
  [2] F2 / 箇所：[引用] / 問題：旧名称使用 / 修正案：「[正式名称]」に変更
  ...

修正後、該当箇所のみ /fact-check で再チェックをお願いします。
```

## ログの保存

チェック完了後（合格・差し戻しいずれも）、以下に保存する：

```
logs/YYYY-MM/fact-check_YYYYMMDD_HHMM_[成果物名略称].md
例：logs/2026-05/fact-check_20260510_1430_まるv11.md
```

### ログの内容

```markdown
# fact-check ログ
日時：YYYY-MM-DD HH:MM
対象：[ファイルパス]
判定：合格 / 差し戻し[n回目] / エスカレーション
CHECK_COUNT：[n]

## チェック結果サマリー
- F1 数値：[件数]件確認 / 問題[件数]件
- F2 固有名詞：[件数]件確認 / 問題[件数]件
- F3 論拠：問題[件数]件
- F4 リスク：問題[件数]件

## 主要エビデンス（WebSearch結果）
- [数値や法令名]: [URL] ※[YYYY-MM-DD]時点
- ...

## 差し戻し内容（ある場合）
[箇条書き]

## 備考
[特記事項]
```

## 注意事項

- **自己申告の限界を自覚する：** 同じKaiが書いて検証する構造上、思い込みは完全には排除できない。疑わしいものは積極的にWebSearchで外部照合する。
- **WebSearchは必要な時だけ：** F1の出典不明数値とF2の法令名が主な対象。全文検索はしない。
- **「不明」を「問題なし」にしない：** 確認できなかったことは⚠️として明示する。
- **差し戻しは建設的に：** 「×」だけでなく「修正案」を必ず添える。
