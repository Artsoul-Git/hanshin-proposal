# /research スキル

**用途:** テーマ・業種・競合を指定してWeb検索を実行し、市場調査レポートと競合分析レポートを生成する。他スキル（`/marketing`・`/profit-plan`・`/sme-ai-proposal`）のインプットとして使う。

> このスキルはWebSearchツールで実データを取得する。フレームワークだけでなく、実際の数値・事例・競合情報を根拠として使える点が他スキルとの最大の違い。

---

## 発動条件

ユーザーが `/research` を入力したとき、または以下の依頼があったとき：

- 「市場調査して」「市場規模を調べて」「業界トレンドを把握したい」
- 「競合分析して」「〇〇社を調べて」「競合と比較したい」
- 「マーケティング戦略の前に市場を調べて」
- 「このビジネス、実際に儲かる市場があるか確認して」

---

## モード選択

| モード | 内容 |
|--------|------|
| A: 市場調査 | 市場規模・成長率・トレンド・顧客層・参入障壁を調査 |
| B: 競合分析 | 指定した競合（1〜3社）の強み・弱み・価格・ポジションを調査 |
| C: 統合リサーチ | A＋Bを組み合わせて戦略的インサイトまで出力 |

未指定の場合は「何を意思決定するための調査ですか？」と聞いて最適モードを提案する。

---

## ヒアリング（1回で聞く）

```
リサーチを始めます。以下を教えてください。

1. 調査テーマ・業種
   （例：中小企業向けAI導入支援、訪問介護、ECサイト構築）

2. 調査の目的
   （例：LP設計の前提を固めたい、新規参入の可否を判断したい）

3. 競合（わかれば）
   （例：〇〇社、同業のサービス名など。「わからない」でもOK）

4. 地域・市場スコープ
   （例：日本全国、関西圏、BtoB、BtoC）

5. 特に知りたいこと
   （例：価格帯の相場、主なターゲット層、勝ちパターン）
```

## プロセスA：市場調査

### A-1：検索クエリの設計

調査目的に応じて検索クエリを設計し、複数回のWebSearchを実行する。

```
検索対象（例）：
- 「{業種} 市場規模 {年}」
- 「{業種} 市場動向 成長率」
- 「{業種} ターゲット層 統計」
- 「{業種} 参入障壁 課題」
- 「{業種} トレンド {年}」
```

### A-2：データ収集と整理

取得した情報を以下の観点で整理する。不確かな情報は「要確認」と明示する。

```
【市場調査レポート】

■ 市場規模
  - 現在の推定規模：〇〇億円（出典：〇〇）
  - 成長率：年率〇%（出典：〇〇）

■ 主なトレンド（3点）
  1. 〇〇（根拠：〇〇）
  2. 〇〇（根拠：〇〇）
  3. 〇〇（根拠：〇〇）

■ 主要顧客層
  - 〇〇（年齢・属性・行動パターン）

■ 参入障壁・課題
  - 〇〇

■ 市場の「痛み」（未解決のニーズ）
  - 〇〇

■ データ信頼度評価
  高：一次ソース確認済み
  中：複数記事で一致
  低：単一ソース・要確認
```

## プロセスB：競合分析

### B-1：競合の特定（未指定の場合）

「{業種} 主要プレイヤー」「{業種} サービス比較」などで検索し、主要競合を3〜5社特定する。

### B-2：競合ごとの調査

各競合についてWebSearchを実行し、以下を収集する。

```
検索対象（例）：
- 「{競合名} 料金 価格」
- 「{競合名} 評判 口コミ」
- 「{競合名} 特徴 強み」
- 「{競合名} ターゲット」
```

### B-3：競合比較レポート

```
【競合分析レポート】

■ 競合マップ（ポジション整理）
  高価格×高サービス：〇〇社
  低価格×標準サービス：〇〇社
  ニッチ特化：〇〇社

■ 競合別プロファイル

【〇〇社】
  強み：〇〇
  弱み：〇〇
  価格帯：〇〇
  ターゲット：〇〇
  差別化ポイント：〇〇
  顧客の不満（口コミから）：〇〇

【〇〇社】（同形式）

■ 市場の「隙間」（どこが手薄か）
  - 〇〇（根拠：〇〇）

■ 勝ちパターンの共通点
  - 〇〇

■ 避けるべきポジション
  - 〇〇
```

## プロセスC：統合リサーチ

A＋Bの結果をまとめ、戦略的インサイトを出力する。

```
【統合リサーチサマリー】

■ 市場の結論
  「この市場は〇〇の理由で{参入しやすい/難しい/ニッチで狙える}」

■ ターゲットすべき顧客セグメント
  第一優先：〇〇（理由：〇〇）
  第二優先：〇〇（理由：〇〇）

■ 競合に勝てるUSP候補（3案）
  案1：〇〇（競合Xが手薄な〇〇を突く）
  案2：〇〇
  案3：〇〇

■ 次のアクション提案
  このリサーチ結果を使って → /marketing でLP戦略を設計
                            → /profit-plan で収益計画を立てる
                            → /sme-ai-proposal で提案書に落とす
```

---

## 品質ルール

- 取得した情報には必ず出典（URL・サイト名）を明記する
- データが見つからない場合は「データ未取得」と正直に書く。推測で補わない
- 検索結果が古い（2年以上前）場合は「古い情報の可能性あり」と付記する
- 「要確認」情報をユーザーが鵜呑みにしないよう、信頼度評価を必ず付ける

---

## 他スキルとの連携フロー

```
/research（実データ収集）
    ↓ 市場の痛み・競合の隙間が判明
/marketing（LP戦略・USP設計・コピー開発）
    ↓ 戦略が固まった
/profit-plan（EPDCARで収益計画・EOODARで実行管理）
    ↓ プランが完成した
/sme-ai-proposal（クライアント向け提案書に仕上げる）
    ↓ 提案書が完成した
/visualize（4象限・マンダラで思考を可視化）
```
