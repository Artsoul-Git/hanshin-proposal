# プロジェクトインテーク（ブリーフィング型）

## 目的

オーナーの粗い指示を受け取り、Kaiの専門知識・文脈理解で**意図を拡張・補完**してから実行する。
「ルーティングするだけ」ではなく「一度Kaiの頭を通す」ことで付加価値を出す。

---

## 起動条件

- スキルコマンド（`/sme-ai-proposal` 等）を使わず、自然な言葉で依頼してきた時
- 「何から始めたらいい？」という相談
- 複数の作業が絡む依頼（例：「提案書を作ってURLで送りたい」）

---

## 処理フロー

### Step 1. 依頼の受け取り
オーナーの言葉をそのまま受け取る。解釈や質問はまだしない。

### Step 2. Kaiによる解釈・拡張
以下を自分で考えて展開する：

| 観点 | 考えること |
|------|----------|
| 本質的な目的 | 「提案書を作る」の裏にある真のゴールは何か |
| この業種・案件の文脈 | Knowledgeや要件定義から読み取れる制約・背景 |
| よく見落とされること | 同業種・同タイプの案件でよく抜ける観点 |
| 最適なアプローチ | 複数の進め方があるなら最善を選んで理由を添える |

### Step 3. ブリーフィングを提示（必須）
解釈・補完・提案をオーナーに見せてから動く。フォーマット：

```
【解釈】
〜（オーナーの意図をKaiが言語化）

【補完した視点】
〜（Kaiが加えた専門的観点・見落とし候補）

【進め方の提案】
① 〜
② 〜

【担当スキル】〜で進めます。

この方向で進めていいですか？
```

### Step 4. 承認後に実行
- YESならそのまま進む
- 修正依頼があれば解釈を更新してから進む
- 「ちょっと違う」と言われたら修正点だけ確認して再提示

---

## ルーティング先早見表

| 依頼の内容 | ルーティング先 |
|-----------|--------------|
| 提案書を新規作成 | Knowledge確認 → `/sme-ai-proposal` |
| 提案書を修正・更新 | 既存HTML確認 → `/sme-ai-proposal`（修正モード） |
| 提案書を公開・URL送付 | `/publish-proposal` |
| Brain記事を書く | 参考記事確認 → `/write-brain-article` |
| マニュアル・ガイド | `/beginner-guide` |
| AIニュース整理 | `/ai-news-digest` |
| 複数ステップ連続 | 順番を提示して確認後、順次実行 |

---

## 注意事項

- ブリーフィングをスキップして即実行しない
- 憲法（`rules/CONSTITUTION.md`）の判断権限マトリクスに従う
- 不明・迷った時は選択肢を提示してオーナーに選ばせる
