# /seminar-dna スキル
**セミナー事業部 — セミナーの型を抽出・命名・ライブラリ化するメタスキル**

**用途:** セミナーの文字起こし・参照資料からセミナーの「スタイル型（DNA）」を抽出・命名・テンプレート化し、任意のテーマ・ゴール・ターゲットに対して同じスタイルのセミナーを再現できるパターンライブラリを構築する。

**保存先:**
- パターン定義: `rules/seminar-patterns/<パターン名>.md`
- 台本テンプレート: `rules/seminar-patterns/<パターン名>_template.md`
- パターン一覧: `rules/seminar-patterns/INDEX.md`

**台本の品質基準:** `rules/seminar-script-rules.md` を必ず参照する

---

## このスキルの設計哲学

> **セミナーの「うまさ」は偶然ではなく型に宿る。その型を言語化すれば、テーマが変わっても同じ熱量・説得力・体験が再現できる。**

- 文体・話し口調・流れは著作権の対象外。構造の抽出・再設計は合法
- 「何を話すか」ではなく「どう設計するか」を型として保存する
- パターンに名前がつくと呼び出せる。名前がない型は使われない
- 1つのパターンから複数のテーマ・ターゲット向けセミナーを量産できる

---

## 情報保護ルール（全モード・全ステップに適用）

**以下は素材を読み込んだ後、いかなるファイルにも記録しない：**

| 禁止事項 | 理由 |
|---------|------|
| 登壇者名・主催者名・運営会社名 | 情報元の特定につながる |
| セミナー名・シリーズ名・コース名 | 同上 |
| 開催日時・会場名 | 同上 |
| 登壇者固有のフレーズ・口癖・言い回し | 著作権的保護対象に近い表現 |
| 素材中に登場する固有事例・企業名・数値 | 転用元として特定される |
| 素材に出てくる参加者のコメント・反応 | 個人情報・特定リスク |

**記録してよいのは「構造・比率・設計パターン」のみ。**
「どう設計されているか」は記録する。「何が言われていたか」は記録しない。

## 3つのモード

| モード | 呼び出し方 | 用途 |
|--------|-----------|------|
| `browse` | `/seminar-dna`（引数なし）または「スタイル一覧」「どんなスタイルがある」等 | 蓄積済みパターンを一覧表示し、テーマ・ゴール・ターゲットに合わせて推薦 |
| `extract` | `/seminar-dna extract` または素材を渡したとき | 文字起こし・参照資料からDNAを抽出して命名・保存 |
| `apply` | `/seminar-dna apply <パターン名>` | 保存済みパターンを使って新しいセミナー台本を生成 |

---

## browseモード（スタイルを選んで始める）

**発動条件:**
- `/seminar-dna`（引数なし）
- 「スタイル一覧を見せて」「どんなスタイルがある？」「スタイルを選びたい」等の自然言語
- `apply` するパターン名が分からない場合

### STEP B1: パターン一覧の読み込みと表示

```bash
Read rules/seminar-patterns/INDEX.md
```

**表示フォーマット:**

```
[セミナースタイル一覧]

■ DNA型パターン（実際のセミナーから抽出した型）
  ※ まだ登録がない場合は「まだ型が登録されていません」と表示

  No. | パターン名      | 得意なテーマ        | 得意なターゲット
  ----|-----------------|--------------------|-----------------
   1  | ○○型           | ○○               | ○○
   2  | △△型           | △△               | △△

■ 構成パターン（ゴール×営業圧で選ぶ基本骨格）
  1. 情報提供型   ── 理解と気づき / 営業圧ゼロ
  2. 教育型       ── スキル習得 / 営業圧なし
  3. ストーリー型 ── 感情共感・ブランド記憶 / 営業圧低
  4. 製品紹介型   ── 認知・体験申込 / 営業圧中〜高
  5. 営業型       ── リード獲得・受注 / 営業圧高

─────────────────────────────────────────────────
どのスタイルで進めますか？
番号で選ぶか、以下を教えていただければ最適なスタイルを提案します。

・テーマ（例: AI活用、採用戦略、財務改善）
・ゴール（例: 相談申込、スキル習得、認知拡大）
・ターゲット（例: 中小企業経営者、現場担当者、20代女性）
```

### STEP B2: スタイル推薦

テーマ・ゴール・ターゲットを受け取ったら、以下の軸で推薦する：

| 軸 | 推薦ロジック |
|----|------------|
| ゴール | 営業圧の高低 → 構成パターンを絞る |
| ターゲット | 感情訴求 vs 論理訴求 → DNA型パターンを絞る |
| テーマ | 業種・専門性 → 両方の相性を確認 |

**推薦フォーマット:**

```
[スタイル推薦]

■ おすすめの組み合わせ
  構成パターン : ○○型（理由: ○○）
  DNA型スタイル: ○○型（理由: ○○）
  ※ DNA型がまだない場合は「構成パターンのみで進める」か「先にDNA抽出するか」を確認

■ 代替案
  A案: ○○型 × ○○型（よりコンサバ寄り）
  B案: ○○型 × ○○型（より感情訴求寄り）

この組み合わせで進めますか？
または別のパターンを選びますか？
```

承認されたら `apply` モード（STEP A1以降）へ進む。

## extractモード（型の抽出・命名）

### STEP 1: 素材の受け取り・読み込み

ユーザーからファイルパスまたはテキストを受け取る。

```
対応素材:
- セミナーの音声文字起こし
- セミナーの台本・レジュメ・スライド構成メモ
- 参加録・観察メモ
- 複数素材の組み合わせ
```

**読み込みルール:**
- 大きいファイルは `offset` / `limit` を使って分割読み込み
- 読み込み完了後、素材の種別（「文字起こし・約○○字」等）のみ確認。タイトルや登壇者名はこの時点で捨てる

---

### STEP 2: DNA 7軸分析

**分析前に必ず確認する禁止事項:**

```
【分析中・一切行わないこと】
- 登壇者名・セミナー名・社名・ブランド名の記録
- 素材中の具体的な数値・事例・エピソードの記録
- 登壇者の固有フレーズ・口癖・キャッチコピーの記録
- 「参加者Aが言った〇〇」など具体的な場面描写の記録

→ 抽出するのは「どう設計されているか（構造・比率・パターン）」のみ
```

**DNA分析フレーム（7軸）:**

```
① オープニングDNA
   - 冒頭フックの種類（問いかけ型・共感型・数字型・物語型・宣言型）
   - 信頼構築のプロセスと所要時間
   - 場のほぐし方の設計

② 構造DNA
   - セクション数と各セクションの役割
   - 論理フロー（問題→解決型 / 感情→理性型 / 体験→一般化型 等）
   - 転換点（話が切り替わるタイミングと手法）

③ エンゲージメントDNA
   - 聴衆参加の仕掛けの種類（質問・挙手・ワーク・対話）
   - 参加仕掛けの頻度と配置パターン
   - 感情開放のタイミング設計

④ 感情カーブDNA
   - 感情の設計フロー（例: 共感→不安→希望→確信→行動）
   - テンション上下のリズムパターン
   - 感情のピーク位置と回数

⑤ コンテンツ比率DNA
   - 理論：体験談：問いかけ：具体事例 の配分（10段階比率）
   - 事例の出し方のパターン（先出し・後出し・交互）
   - 専門性の見せ方（データ重視 / 体験談重視 / 実演重視）

⑥ クロージングDNA
   - CTAへの導き方（段階的 / 一発）
   - 「今すぐ動く理由」の作り方のパターン
   - 余韻・反芻の設計

⑦ 話法構造DNA
   - 口調・文体のパターン（断定型・問いかけ型・語りかけ型）
   - 話法の構造（反復の使い方・問いかけの組み方・文末の変化パターン）
   - テンポ設計（ゆっくり説得型・テンポよく熱血型・対話型）
   - 「間」の使い方のパターン

   ※ 具体フレーズ・口癖・言い回しは一切記録しない
   ※ 「どんな構造で話しているか」のみ抽出する
```

---

### STEP 3: パターン命名

**命名ルール:**
- 5〜15文字程度。「○○型」で終わる
- 「どう設計されているか」を体言止めで表す（何のセミナーかは表さない）
- 情報元が名前から特定できないようにする

**命名例（参考）:**
| 名前 | 特徴 |
|------|------|
| 共感ファースト型 | 課題共感から始めて解決策を積み上げる |
| 問題解体型 | 複合課題を細分化して1つずつ潰す |
| ストーリー旅型 | 物語の起承転結に沿って体験させる |
| 証拠積み上げ型 | 数字・事例・論理を重ねて確信に導く |
| 対話引き込み型 | 問いかけで聴衆を思考させながら展開 |
| 熱血実演型 | 実演・体験ワーク中心、即使えるを体感させる |

命名候補3つを提示し、ユーザーに選ばせる（または別名指定）。

### STEP 5: 台本テンプレート生成

**保存パス:** `rules/seminar-patterns/<パターン名>_template.md`

**テンプレートの作成ルール（厳守）:**
```
固定パーツのテキストはすべて完全新規作成で書く。
素材から引用・派生させたテキストは一切含めない。
「この型の設計原則を体現した新しい文章」として書く。
```

テンプレートは「構造の説明（コメント）」と「変数プレースホルダー」で構成する。

```
変数プレースホルダー:
  {{テーマ}}      ← セミナーのテーマ・業務領域
  {{ゴール}}      ← 参加者に達成してほしいこと
  {{ターゲット}}  ← ターゲット受講者の属性
  {{事例}}        ← 具体的な成功事例・数字（apply時に新規作成）
  {{CTA}}         ← 最終的なアクション
  {{あるある}}    ← ターゲットに刺さる共感ネタ（apply時に新規作成）
  {{ROI}}         ← 数字で表す価値・効果（apply時に新規作成）
```

## applyモード（パターンを使ってセミナーを生成）

### STEP A1: パターン確認

指定パターンの定義ファイルを読み込む。

```bash
Read rules/seminar-patterns/<パターン名>.md
```

パターンが存在しない場合は `browse` モードへ誘導する。

---

### STEP A2: ヒアリング（1回で聞き切る）

```
「<パターン名>」スタイルでセミナーを設計します。以下を教えてください。

■ 必須情報
1. テーマ: セミナーで扱う具体的なテーマ・業務領域
2. ゴール: 参加者にセミナー後に達成してほしいこと（1文で）
3. ターゲット: 誰に向けたセミナーか（職種・業種・知識レベル）

■ 任意情報
4. 所要時間（デフォルト: 60分）
5. 強調したいポイント（DNA定義の中で特に強めたい軸）
6. 使える具体事例・数値（なければKaiが設計）
7. CTA（最後に取ってほしいアクション）
```

---

### STEP A3: 台本生成

`rules/seminar-script-rules.md` のルールに従って台本を生成する。

**生成時の厳守事項:**
- 変数プレースホルダーは必ずすべて埋める（残さない）
- 事例・数値・あるある等の変数は、テーマ・ターゲットに合わせて完全新規作成
- 素材から借用したテキストは一切含めない

**出力形式:**
```
■ セクション構成（全体アウトライン）
■ 各セクションの台本（話し言葉）
■ エンゲージメント仕掛けの設計
■ CTA設計
```

台本完成後、連携オプションを提示：
```
→ スライド化しますか？（/seminar-slide に引き渡せます）
→ 台本のみ保存しますか？
```

---

### STEP A4: 適用実績の記録

パターンファイルの「適用実績」テーブルに1行追加する。

## 品質チェックリスト

### extractモード完了時（情報保護チェック）
- [ ] 登壇者名・セミナー名・主催者名がどのファイルにも含まれていないか
- [ ] 素材中の固有事例・数値・エピソードがパターン定義に含まれていないか
- [ ] 話法構造DNAに具体フレーズ・口癖が含まれていないか（構造のみか）
- [ ] 台本テンプレートの固定テキストが素材から派生していないか（完全新規か）
- [ ] パターン名から情報元が特定できないか（第三者が見ても分からないか）

### extractモード完了時（品質チェック）
- [ ] 7軸DNAがすべて記述されているか
- [ ] テンプレートの変数プレースホルダーが正しく設定されているか
- [ ] INDEX.mdが更新されているか

### applyモード完了時
- [ ] 変数プレースホルダーがすべて埋まっているか
- [ ] 7軸DNAが台本に反映されているか
- [ ] `rules/seminar-script-rules.md` のルールを満たしているか
- [ ] 適用実績テーブルが更新されているか
