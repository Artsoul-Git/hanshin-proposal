## ■ MODIFIED（修正が必要な項目）

### M-1：図解②「利用可否判断の自動下書き AIで論点整理10分」を削除

**修正前**：
```
B[利用可否判断の自動下書き\nAIで論点整理 10分]
```

**修正後**：
```
B[管理者・サビ管による利用可否判断\n※AI使用不可：法的責任判断]
```

**理由**：
利用可否判断は障害福祉法令に基づく法的判断行為。事業所の責任において人間が行う必要がある。
AIによる「論点整理」という形でも判断の外観を呈した記録が残ることはコンプライアンスリスク。
指定取消・監査での指摘対象となり得るため、完全に削除。

---

### M-2：図解②「本人面談 Google Meet録音」を削除

**修正前**：
```
E[本人面談\nGoogle Meet録音]
F[自動文字起こし 10分]
```

**修正後**：
```
E[本人面談\n管理者・サビ管が対面で実施]
```

**理由**：
1. 就労継続支援B型の利用者は精神・知的・発達等の障害をお持ちの方が多く、高齢の方も多い（実例：68歳・精神2級の利用者がいることをPDFで確認）。ビデオ通話での面談は機器操作・通信接続・心理的ハードルで実施困難なケースが多数。
2. 利用者と家族全員の書面による録音同意取得が必要。緊急の利用開始ケースでは対応不可。
3. AI文字起こしの対象は**内部カンファレンス**（職員のみの会議）に限定することが現実的かつ安全。

---

### M-3：図解②「共通フォームへ1回入力 約5分」を3系統に分離

**修正前**：
```
M[共通フォームへ1回入力\n約5分]
N[提供実績記録票 自動出力]
O[サービス提供記録 自動出力]
P[作業日報 自動出力]
```

**修正後**：
```
J{通所 or 施設外就労 or 在宅}
K[Googleフォーム_通所版]
L[Googleフォーム_外就版]
M[LINEで開始/終了 → Googleフォーム_在宅版]
N[スプレッドシートに自動蓄積]
O[様式17_通所版 自動出力]
P[様式17_在宅作業版 自動出力]
Q[作業日報・確認表 自動出力]
```

**理由**：
書類④「提供実績記録票」は通所版と在宅作業版で**様式が異なる**（PDFで2バージョンを確認）。在宅版には「クリーニング/探す/撮影/出品/コメント/梱包/発送/報告」の作業チェックボックスがある。これを1つのフォームで兼用することは不可能。また施設外就労（ホテル清掃）は記録内容が通所と異なるため、別フォームが現実的。

---

### M-4：事業所基本情報に複数拠点情報を追加

**修正前**：
```
所在: 岡山県内（架空拠点名）
```

**修正後**：
```
所在: 岡山県内・西市拠点（主）・早島拠点（副）
外部就労先: ベッセルホテル倉敷（施設外就労先）
```

**理由**：
書類③「作業日報」のPDFで、西市と早島の2拠点名が判明。外部就労先としてベッセルホテル倉敷でのホテル清掃が確認。このデュアル拠点構造はワークフロー設計に直接影響するため追加必須。

### M-5：作業種目マスターリストを実態に合わせて更新

**修正前（デモ内で曖昧だった作業種目）**：
「農作業系・軽作業系」等の概括的記述

**修正後（PDFから確認した実際の作業種目）**：

| 区分 | 作業種目 |
|------|---------|
| 内就（施設内） | チラシ封入、ひも作業、糸積み、フルーツネット、採寸 |
| 外就（施設外） | ホテル清掃（ベッセルホテル倉敷） |
| 在宅作業 | 探す、撮影、出品、コメント、梱包、発送、報告（メルカリ・ECサービス） |

**理由**：
書類②（確認表）と書類③（作業日報）のPDFで作業種目を直接確認。Googleフォームのプルダウン設計に使用する基本データとして必須。

### M-6：フェイスシートとアセスメントシートの統合提案を追記

**修正前**：
2書類を並列に管理するデータ構造のみ存在

**修正後**：
統合アセスメントシートの設計書を追加（Month 4の成果物として）

**理由**：
管理者ヒアリングで「実質同じ。一つにまとめてあげても」と明言。現場でも「なぜ2つなのかわからない」状態。PDF確認でも内容の重複を実際に確認。統合化は工数削減だけでなく、情報の一元化・転記ミス防止に直結。
