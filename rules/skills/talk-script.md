# /talk-script スキル

**用途:** 既存のスライド（PDF・HTML・画像）を読み込み、プレゼンテーション用トークスクリプトを生成する

---

## 発動条件

ユーザーが `/talk-script` を入力したとき、または以下の依頼があったとき：

- 「このスライドのトーク台本を作って」
- 「PDFからスクリプトを書いて」
- 「セミナーの話し方を作って」
- 「スライドがあるから話す内容を作りたい」

> `/seminar-slide` との違い：このスキルは **既存スライドから台本を作る**。
> スライドを白紙から作る場合は `/seminar-slide` を使う。

---

## フロー

### STEP 1：スライドの読み込みと構成解析

スライドファイル（PDF・HTMLなど）を読み込み、以下を抽出する：

- 全スライド数と各スライドの見出し・要点・ビジュアル要素
- 各スライドの役割分類（導入 / 課題提示 / 背景 / 提案 / データ / まとめ / Q&A）
- 全体の構成と論理の流れ

解析結果を出力した後、STEP 2 へ進む。

---

### STEP 2：台本タイプの仮説提示

スライド構成をもとに、以下のいずれが適しているか仮説を提示する：

| タイプ | 向いているスライド構成 |
|--------|----------------------|
| ストーリーテリング型 | 感情移入・共感重視、体験談が多い |
| 課題解決型 | 現状課題→解決策→効果の流れが明確 |
| 理論解説型 | 概念・データ・知識の習得が主目的 |

提示後、STEP 3 のヒアリングへ進む。

---

### STEP 3：ヒアリング（1回で聞き切る）

以下を一度にまとめて質問する。

```
トークスクリプトを最適化するために、以下を教えてください。

1. 話し手について
   役職・立場・専門性（例：代表者、営業担当、講師）

2. 聴衆について
   誰に向けたプレゼンか（例：社員、クライアント、経営層）
   前提知識レベルや主な関心事

3. プレゼンの目的
   何を達成したいか（例：提案承認、理解促進、行動喚起）

4. 話し方のトーン
   スタイルの希望（例：論理的・親しみやすく・熱意を込めて）

5. 冒頭の導入
   アイスブレイク・自己紹介・ストーリーなど、距離を縮める導入を入れるか

6. 人間味の度合い
   話者自身の経験談・感情・エピソードをどの程度含めるか

7. スライド外情報の補足
   スライドにない情報を加えてよいか
   （スライド内のみ / 一般常識レベルまで / 自由に補足OK）
```

回答を受けてから STEP 4 へ進む。

---

### STEP 4：生成ルールの設定

ヒアリング結果と構成情報を統合し、以下を定義する：

```
【生成ルール】
スライド数     : ○枚
台本タイプ     : ○○型
話者           : ○○
聴衆           : ○○（知識レベル：○）
目的           : ○○
トーン         : ○○
1スライドの目安: ○秒〜○秒
補足許容範囲   : ○○

これで進めてよいですか？
```

承認を得てから STEP 5 へ進む。

---

### STEP 5：スクリプト生成（スライドごと）

以下の形式でスライドごとに出力する。

```
---
# Slide [番号]：[タイトル]

スライド内容要約：〜〜〜

🎤 トークスクリプト：
「〜〜〜〜〜〜〜〜〜〜〜〜〜〜〜〜〜〜」

📝 設計メモ：
- 役割：[このスライドで伝えること]
- トーン：[例：やさしく共感を引き出す]
- 注意点：[例：数値は正確に、専門用語は注釈を添える]
---
```

---

## 台本の書き方ルール

`rules/seminar-talkscript-guide.md` の以下を適用する：

- **スライドの役割分類と話時間の目安**（§2）
- **1スライドの3要素構造**（フック→本題→接続）（§3）
- **特殊スライドの専用ルール**（§4）
- **レトリック**（§5）
- **禁則事項**（§7）

ヒアリング結果によってトーン・文体・聴衆呼称などを上書き適用する。

---

## 制約条件

- **ハルシネーション禁止：** 根拠はスライド内情報に限定する。補足情報はユーザーが「補足OK」と答えた場合のみ追加し、必ず「補足情報」と明示する。
- **要約・意訳しすぎない：** スライドの意図と論理順序を崩さない。
- **専門用語：** 聴衆のレベルに応じて注釈を調整する。
