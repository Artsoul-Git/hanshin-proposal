# /ai-readiness スキル

**用途:** AI導入支援の **初回接触フェーズ** で使うフロント装置。対象業種・最低限の課題・ゴールを入力すると、5つの成果物（①顧客提出用の現状整理シート、②コンサル用切り返しトーク、③Draw.io図解、④受注動線設計、⑤業種ナレッジ蓄積メモ）を一気通貫で生成する。シートを書かせて終わりにせず、**30分壁打ち→PoC→月額顧問** への受注動線まで設計する。

---

## 発動条件

- 「新規クライアントのヒアリングシート作って」「初回打診用の現状整理シート」
- 「{業種}向けのAI導入適性チェック」
- 「シート+切り返しトーク+図解、まとめて欲しい」
- `/sme-ai-proposal`（本提案）の前段ツールとして使う場合

**`/hearing-sheet` との違い：**
- `/hearing-sheet` = 既知の契約クライアント向けに業種×部門でExcel深掘りヒアリング
- `/ai-readiness` = **初回接触・営業フロント**向け。顧客が自力で書けるMarkdownシート+受注動線設計

---

## AS流の絶対遵守哲学（出力全体に通底させる）

1. **AIは魔法ではない。業務の棚卸しが先、ツールは後**
2. 「導入すれば全部解決」系の表現は禁止
3. コンサルタントは"上から教える存在"ではなく "一緒に整理する伴走者"
4. 顧客の言い訳・抵抗を **否定せず受け止めてから返す**
5. 数字は誇張せず、根拠ある範囲で出す

> CONSTITUTION.md §1「オペレーション改善が先、ツールは補助」をそのままトーンに反映する。

## 入力情報

ユーザーから以下3つを受け取る：

| 項目 | 例 |
|------|----|
| 対象業種 | 製造業（金属加工）／介護事業所／士業（税理士）／飲食店（個人経営） |
| 最低限の課題 | 見積作成に時間がかかる／シフト調整が属人化／報告書作成が深夜業務 |
| ゴール設定 | 月20時間の残業削減／属人業務をゼロにして退職リスク減／粗利+5% |

3つすべて揃わない場合は、揃ってから生成する（曖昧な入力で精度を落とさない）。

## 出力構造（6セクション）

### セクション 0：全体貫通トーン規定（出力冒頭に明示）

生成物の冒頭に、上記AS流哲学の5項目を明示し、コンサル本人にも顧客にも"通奏低音"として読ませる。

### セクション 1：【顧客向け】AI導入のための現状整理シート（Markdown形式）

- そのまま顧客に渡して記入してもらう。**専門用語禁止**（DX/SaaS/RPA/API/クラウド/リテラシー等）。中学生でもわかる言葉に翻訳。
- A4で3枚以内。設問数 **30問以下**（多すぎると返ってこない）。
- チェックボックス（[ ]）と記述式を織り交ぜる。
- 必須6項目：
  1. **会社のこと・決める人のこと**（最終決裁者、決定希望時期）
  2. **今使っている道具の確認**（具体例で書く：「インターネット経由で使っているシステム（GmailやZoomなど）」）
  3. **いま一番困っていること**（いつ・誰が・何に困っているか）
  4. **毎日の業務の棚卸し**（作業×時間）
  5. **AIに期待すること・予算感**（金額は**数字で書かせる**）
  6. **次のステップ希望**（30分無料壁打ちMTGの候補日3つ書く欄）

シート末尾に必ず以下の「提出後の流れ」を入れる：

```
▼ 提出後の流れ
① シートを書いて返信（所要時間：約20分）
② 30分の無料壁打ちMTG（オンライン可）
③ 一番効果が高そうな業務を1つ選んで、お試し改善プラン（PoC）をご提案
```

### セクション 2：【コンサル用】対象業界の「あるある」な壁と切り返しトーク

- 対象業種特有のAI導入ハードル"あるある"を **3〜5つ** 抽出。
- 各パターンを以下3点セットで出力：
  - **(a) 顧客の典型セリフ**（生々しく）
  - **(b) NG返し**（よくある的外れな返答 = 反面教師）
  - **(c) 切り返しトーク**（300字以内・否定せず受け止めて返す）
- 切り返しは「AIは魔法ではない。でも業務を整理すれば確実に時間が浮く」というロジックを軸にする。
- 具体的な業界事例 or 数字を **1つ以上** 含める（誇張禁止）。

### セクション 3：【顧客提示用】相談内容に完全最適化された図解（Draw.io用XML）

入力された業種・課題・ゴールを **図中のテキストに直接反映**（固定テンプレ禁止）。

構成：

**A. 顧客専用の全体フロー図**
```
[①今の状態を知る（このシート）]
  → [②{対象業種}特有の課題である〇〇をAIに任せる]
  → [③AIの使い方を学ぶ]
  → [④{ゴール設定}の達成]
```

**B. 4象限マトリクス**（縦軸：効果の大きさ／横軸：AIへの任せやすさ）

- 業種・課題から **3〜4つの具体業務をAIが推測** して配置（例：「{業種}の見積書作成」「{業種}の問い合わせ一次対応」）。
- 右上（効果大×任せやすい）= 即着手すべきもの。

**色指定：**
- 「①今の状態を知る」のボックス → **黄色 or オレンジ**（現在地を強調）
- マトリクス右上の象限 → **黄色 or オレンジ**（次の一手を強調）

出力は `<mxGraphModel>` から始まる有効XMLで、 ```xml コードブロックに入れる。

### セクション 4：【受注動線】シート回収後のジャーニー設計

以下3点をすべて出力：

#### (a) クライアントへのシート手渡しトーク（30秒・口頭用）

押し付けがましくない伴走者トーン。例：
> 「いきなり詳しい話を聞くより、まず御社の状況を整理させてください。私の方でも余計な提案をしないように、まず20分だけ時間を取って書いてもらえますか。書きながら『あ、ここがうちの本当の課題か』と気付くことが多いんです。」

#### (b) シート送付メール本文（200〜250字・締切1週間明示）

件名・本文・締切・返信先を含む完成形。テンプレ感を排し、業種向けに具体化。

#### (c) 回収後のネクストアクション設計

| ステップ | 内容 | 所要時間 | 費用感 |
|---------|------|---------|--------|
| 1 | 30分無料壁打ちMTG | 30分 | 無料 |
| 2 | マトリクス右上業務でPoC提案 | 1〜2週間 | 業種に合わせた金額帯を提示 |
| 3 | 月額顧問契約 or 単発支援 | 継続 | 業種に合わせた金額帯を提示 |

### セクション 5：【業種ナレッジ蓄積】今回の発見メモ

以下を構造化メモとして出力：

#### (a) {対象業種}で今回新たに見えた"あるある"パターン（3つ）
各パターンを「現象 → 背景 → 対策の方向性」の3点セットで記述。

#### (b) 既存業界知識との差分
「教科書的に語られる課題」と「今回の入力から見えた現実の課題」のギャップを明示。

#### (c) 次回以降の精度向上ヒント
同業種で次に使うとき、より精度を上げるための追加質問項目（3つ）。

> **保存先：** `rules/_internal_source_meta/` 配下に {日付}_{業種}_ai-readiness.md として配置することを推奨（業種ナレッジ蓄積の素材として）。

### セクション 6：【自己品質チェック】出力前セルフ検証

全成果物の生成後、Kai が自分で以下を○判定にしてから提出する：

**現状整理シート**
- [ ] 専門用語が1つも入っていないか
- [ ] 60代の事務員が読んで意味が通じるか
- [ ] 設問数が30問以下か
- [ ] 「予算感」を数字で書かせる構造か
- [ ] 「30分壁打ち希望」欄が末尾にあるか

**切り返しトーク**
- [ ] 顧客の言い訳を否定せず受け止めているか
- [ ] 「AIで全部解決」を1度も使っていないか
- [ ] 具体的な業界事例 or 数字が1つ以上入っているか

**Draw.io図解**
- [ ] フロー4ステップに業種名・課題・ゴールが固有名詞で入っているか
- [ ] マトリクス右上の業務が「即着手して効果が出る」ものか
- [ ] 色で「いまここ」が一目でわかるか

**受注動線**
- [ ] 手渡しトークが伴走者トーンか
- [ ] メールに締切が明示されているか
- [ ] 次のステップの費用感が数字で出ているか

## 実行プロトコル（Kai 用）

1. **入力チェック** — 業種・課題・ゴールの3つが揃っているか確認。曖昧なら聞き直す。
2. **生成** — 6セクション一気通貫で出力（途中で止めない）。
3. **セルフ検証** — セクション6のチェックリストで自己採点。×は即書き換え。
4. **保存** — 顧客名がある場合は `06_セミナー事業部/outputs/ai-readiness/{日付}_{顧客名 or 業種}/` に保存。
5. **ナレッジ蓄積** — セクション5の発見メモを `rules/_internal_source_meta/` 配下に格納（業種別蓄積）。
6. **Kai Tasks ログ** — 生成完了を `log-action --type output` で記録。

## 既存スキルとの連携

- **`/sme-ai-proposal`** — 本スキルでシート回収 → 壁打ち → 本提案へ繋ぐ前段装置
- **`/hearing-sheet`** — 契約後の深掘りヒアリングで使う後段装置
- **`/fact-check`** — 生成物の数字・固有名詞を公開前に検証
