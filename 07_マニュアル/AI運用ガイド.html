1. 使い始める前に：はじめの一歩チェックリスト

Kaiを使い始める前に、以下の3つが揃っているか確認してください。どれも5〜10分でできます。

  • Gitがインストールされている
    ターミナルで git --version と打って数字が出ればOK。→ インストール手順

    一度だけ必要な設定。→ 設定手順
  • 作業フォルダがDropboxなどクラウド同期フォルダ内にある
    外付けドライブより速く、自動バックアップになるので安心。推奨パス：C:\Users\kei\Dropbox\00_Antigravity\

Claude Code内では先頭に ! を付けて打てばそのまま実行できます。例：! git --version

2. Gitとは？タイムマシンの仕組みを理解する

「Git（ギット）」は、ファイルの変更履歴をずっと記録し続けてくれるツールです。ゲームで言えば「セーブデータ」、家で言えば「防犯カメラ付きの金庫」のイメージです。

Gitでできること

  • 「セーブ」（コミット）：今の状態に名前をつけて保存する
  • 「巻き戻し」（リストア）：過去のセーブ地点にいつでも戻れる
  • 「履歴確認」（ログ）：いつ・何を・どう変えたかを一覧で見られる
  • 「差分確認」（diff）：変更前と変更後の違いを比較できる

AIを使うときに特にGitが重要な理由

AIの特性：大量・高速・不可逆 Kaiは1回の指示で数十〜数百のファイルを一度に変更できます。指示の解釈が少しズレると、意図しない変更が大量に発生することも。「元に戻す」ボタンは存在しないので、Gitが唯一の安全網になります。
Gitがあれば 「Kaiに頼んだら全部おかしくなった！」という事態でも、コマンド1行で作業前の状態に完全復元できます。
→ これが整っていれば、Kaiへの指示を躊躇なく出せるようになります。

3. Gitのセットアップ（初回のみ）

ステップ① Gitのインストール確認

ターミナルで以下を実行してください：

git --version

バージョン番号（例：git version 2.54.0.windows.1）が表示されればOKです。

表示されない場合のインストール方法（Windows） 1. Git for Windows の公式サイトからダウンロード
2. インストーラーを起動し、すべて「Next（次へ）」で進む
3. インストール後、PCを一度再起動する

ステップ② 名前・メールの登録（最初の1回だけ）

「誰がセーブしたか」をGitに覚えさせます。以下を1行ずつ実行してください：

# 名前を登録（自分の名前でOK）
git config --global user.name "Kei Uemura"

# メールを登録（自分のメールでOK）
git config --global user.email "uemura@artsoul.jp"

ステップ③ フォルダをGit管理下に置く（新規フォルダの場合のみ）

既存フォルダをコピーしてきた場合はすでにGit管理済みのことが多いので、まず以下で確認：

git status

「On branch master」のように表示されれば管理済みです。「fatal: not a git repository」が出た場合は初期化します：

# Git管理を開始する（フォルダの中で実行）
git init
git add .
git commit -m "初回セーブ"

4. 自動コミットの仕組み：Kaiが自動でセーブする

このプロジェクトには「自動コミット」の仕組みがすでに組み込まれています。Kaiが作業を完了するたびに、自動的にGitへセーブが行われます。

自動コミットとは何か

自動コミットの動き Kaiがファイルを変更するたびに、以下のような名前でセーブが記録されます：

auto: 20260515_081729 ["ファイル名1", "ファイル名2", ...]

日時 + 変更したファイル名が自動で記録されるので、「いつ何を変えたか」が後からすぐわかります。

自動コミットを確認する方法

ターミナルで以下を実行すると、最近のセーブ履歴が一覧で見られます：

# 最新10件の履歴を表示
git log --oneline -10

以下のように表示されます：

e8ac368 引越し作業前バックアップ（パス書き換え前）
c142007 auto: 20260515_081729 ["server.py"]
64f47b4 auto: 20260515_074257 ["state.json"]
283ff58 auto: 20260515_073510 ["AI運用ガイド.html"]
確認ポイント auto: で始まるコミットが積み重なっていれば、自動コミットが正常に動作しています。

5. 手動コミット vs Kaiに任せる：使い分けガイド

✅ Kaiが自動でやること AUTO

  • 通常の作業中のセーブ（auto: コミット）
  • ファイル作成・編集ごとの記録
  • セッション終了時のまとめコミット

→ 普段はこれで十分。何もしなくてOK。

🖐 あなたが手動でやること MANUAL

  • 「大きな変更をKaiに頼む直前」のセーブ
  • 「これが完成版」というマイルストーン保存
  • 万が一の備えとして自分でセーブしたい時

→ 大きな作業の前だけ意識すればOK。

手動コミットのコマンド（コピペで使えます）

1 作業前のセーブ これが一番大事

git add .
git commit -m "作業前バックアップ"

Kaiに大きな作業を頼む直前に実行。万が一失敗しても確実に戻せます。

2 マイルストーンのセーブ

git add .
git commit -m "〇〇提案書v2 完成"

「この状態は完璧」と思ったタイミングで名前をつけて保存。

3 Kaiに頼む場合

「今の状態をGitでセーブしてから、〇〇をやって」

この一言を添えるだけでKaiが自動でコミットしてから作業を開始します。

6. 緊急時の復元方法

【緊急事態！】Kaiが失敗してファイルがおかしくなったら？ 落ち着いて以下のどれかを実行してください。

パターンA：直前のセーブ地点に戻す（一番よく使う）

# 全ファイルを最後のコミット時点に戻す
git restore .

コミット後に変更したものが全てなかったことになります。一瞬で完了します。

パターンB：特定のコミットまで丸ごと戻す

# まず履歴を見て、戻りたいコミットのIDを確認
git log --oneline -10

# 特定のコミット時点のファイルを取り出す（例：e8ac368 のとき）
git restore --source=e8ac368 .

パターンC：何が変わったか確認してから判断する

# 変更されたファイルの一覧を見る
git status

# 特定ファイルの変更前後の差分を見る
git diff ファイル名.md
安心のポイント Gitに記録されたコミットは、上書きや削除しない限りずっと残り続けます。「あの時の状態」にはいつでも戻れます。

7. 既存作業の引越し手順（フォルダ移動）

作業環境を別の場所（例：外付けドライブ→Dropbox）に移動する場合の手順です。Kaiに丸ごと任せることができます。

なぜDropboxが推奨なのか

  • 外付けSSD（Dドライブ）より読み書きが速い
  • Dropboxが自動でクラウドにバックアップしてくれる
  • PCが壊れてもデータが残る

引越しの全手順

1 Kaiを終了する
Claude Codeのウィンドウをすべて閉じます。

2 フォルダを「コピー」する（切り取りはNG）
旧フォルダを新しい場所へコピー。切り取りは失敗時にデータが消えるリスクがあるので必ずコピーで。
例：D:\Google Antigravity\AS_AI導入支援事業_cc → C:\Users\kei\Dropbox\00_Antigravity\AS_AI導入支援事業_cc

3 新しい場所でKaiを起動する
Dropbox内のフォルダをClaude Codeで開いて起動します。

4 ファイルの完全性をKaiに確認してもらう
Kaiに以下のように伝えてください： 

「旧フォルダと新フォルダのファイル数・サイズを比較して、コピーが完全かどうか確認して」

5 内部リンク（パス）の一括書き換えをKaiに頼む
ファイルの中に旧フォルダのパスが書かれているものを、Kaiが一括で新パスに書き換えます： 

「フォルダの引越しをしたので、全ファイル内の旧パスを新パスに一括書き換えして。作業前にGitでセーブしてから進めて」

6 動作確認してOKなら旧フォルダを削除
数日使って問題なければ旧フォルダを削除してOKです。迷ったらそのまま残しておいても構いません。

注意：Gitフォルダ（.git）も一緒にコピーする フォルダをコピーするとGitの履歴（.git フォルダ）もそのまま引き継がれます。コピー後も「あの時の状態に戻す」ができます。

8. 日々の運用ノウハウ

① 大きな作業の前は必ず一言添える

Kaiに大きな変更を頼むときは「作業前にGitでセーブしてから進めて」と添えるだけで安心度が格段に上がります。

② Dropboxの「同期完了」を待ってから閉じる

Dropboxのアイコンが「青いぐるぐる」→「緑のチェック」になったのを確認してからPCを閉じましょう。同期中に閉じると、次回起動時にファイルが古いままのことがあります。

③ 「迷ったら聞いて」と伝える習慣

指示の最後に「やり方が複数ある場合は一旦確認して」と添えると、Kaiが勝手に解釈して進むのを防げます。特に削除・大幅変更・公開系の作業では有効です。

④ 大量ファイル生成後は少し待つ

100個以上のファイルを一気に作成した後は、Dropboxの同期に数分かかることがあります。次の指示を出す前に少し待つとスムーズです。

⑤ パスワードとアクセスキーは安全に

DropboxやGitHubなど重要ツールのパスワードは使い回さず、パスワードマネージャーで管理しましょう。Kaiにパスワードを直接伝える必要はありません。
