# /knowledge-craft スキル
**コンサル知識事業部 — 外部資料をコンサル知識資産に変換するメタスキル**

**用途:** 文字起こし・記事・セミナー資料・体験談などの外部素材を受け取り、
① 著作権セーフな概念抽出 → ② 外部公開可能なknowledge MD生成 →
③ Kai評価・内部メモ付きHTMLマニュアル生成 → ④ 総合マニュアル連携
まで一気通貫で自動実行する。

**保存先:**
- knowledge MD（外部公開可）: `knowledge/指標/<テーマ名>.md`
- HTMLマニュアル（内部メモ付き）: `07_マニュアル/<テーマ名>マニュアル.html`

---

## このスキルの設計哲学

> **事例の具体性こそが提案を動かす。しかし他者の情報を無断で使わない。**
> 外部資料から「概念・構造・フロー」だけを抽出し、自社の言葉で再構築する。
> 原本の識別可能性をゼロにした上で、内部メモにオリジナルを保管する。

- **外部公開版**（知識MD）: 一般化・抽象化済み。ブログ・提案書・セミナーに転用OK
- **内部参照版**（HTMLマニュアルのPART 9）: 元の数値・業種・エピソードを保持。外部非公開
- 事例の価値を捨てない。しかし使い方を分ける。

---

## 主要顧客層（提案設計時に意識すること）

| 層 | 特徴 | このスキルでの活用 |
|----|------|-----------------|
| 中小企業 経営者 | 「うちでも使える？」と確認する | 業種・規模感を内部メモで保持し、類似案件で応用 |
| 現場担当者（AI推進担当） | 自分一人で推進する孤独感 | 「同じ立場の人が成功した」事例として語れる形に変換 |
| コンサルタント（上村） | 提案説得力の根拠が必要 | 外部公開版でフレームワーク語り・内部版で数字根拠 |

## フロー

### STEP 1: 素材の受け取り・読み込み

ユーザーからファイルパスまたはテキストを受け取る。

```
対応素材:
- テキストファイル（音声文字起こし・書き起こし）
- Markdown / HTML ドキュメント
- セミナー記録・体験談
- 記事・ブログの貼り付けテキスト
```

**読み込みルール:**
- ファイルサイズが大きい場合は `offset` / `limit` で分割読み込みする
- 読み込み完了後、素材の「テーマ」「出所（公開セミナー / 非公開資料 / 社内資料）」をKai自身が確認・明示する

---

### STEP 2: コンサル価値の事前判断

素材を読んだ後、以下の4軸でコンサル支援への価値を判定し、ユーザーに簡潔に報告する。
**価値が低いと判断した場合はスキップの選択肢をユーザーに提示してよい。**

```
判定軸:
① 再現性: 他のクライアントが同じ手順で実施できるか？
② 汎用性: 業種・規模を問わず適用できるか？
③ 差別化: 一般論ではなく具体性・実証性があるか？
④ 提案価値: ヒアリング・提案書・セミナーで使える場面があるか？

判定レベル:
- A（高価値）: 4軸全て満たす → フルフロー実行
- B（中価値）: 2〜3軸 → MDのみ作成（HTMLマニュアルはスキップ）
- C（低価値）: 1軸以下 → スキップを提案
```

---

### STEP 3: 著作権セーフな概念抽出

`rules/third-party-adaptation.md` の変換チェックリストを自動適用する。

**抽出するもの（概念・構造のみ）:**
```
① What（何を教えているか）  → フレームワーク・ステップ・チェックリストの構造
② Why（なぜ重要か）         → 問題・障壁・課題の本質
③ How（どうやるか）         → 手順・判断基準・優先順位の考え方
④ 結果・成果パターン        → 何が変わったか（数値は内部メモへ、外部版は一般化）
```

**認識テスト（必須）:**
> 「原作者がこのファイルを見て、自分の作品の転用だと特定できる要素が残っているか？」

特定できる要素がひとつでもあれば変換不完全。再抽象化する。

---

### STEP 4: 外部公開可能なknowledge MD生成

**保存先:** `knowledge/指標/<テーマ名>.md`

**必須構成:**
```markdown
# [テーマ名] フレームワーク

作成：Kai（YYYY-MM-DD）
用途：コンサルティング支援・提案設計・ヒアリング設計の参照知識

---

## 1. このフレームワークの前提
[適用フェーズ・推進主体・適用規模]

## 2. [診断 / 原因分析]
[問題の構造化・分類表]

## 3. [推進プロセス / ステップ]
[フェーズ or ステップ構造]

## 4. [介入パターン / 手法集]
[具体的な施策・手順]

## 5. [定着原則 / 成功条件]
[本質的な原則リスト]

## 6. [抵抗パターンと対処法]
[よくある障壁と切り返し]

## 7. コンサルティング提案への活用
[ヒアリング項目・提案設計の要点]
```

**チェック:**
- [ ] 固有の数値（特定組織の実績値）が入っていないか
- [ ] 特定業種・組織規模を固定していないか
- [ ] 著者固有のエピソード・命名が残っていないか

---

### STEP 5: HTMLマニュアル生成（Kai評価・内部メモ付き）

**保存先:** `07_マニュアル/<テーマ名>マニュアル.html`

**デザイン仕様（既存マニュアルと統一）:**
```
カラー:
  - サイドバー背景: #1A365D（navy）
  - アクセント・見出し下線: #ED8936（orange）
  - 本文背景: #FAFBFC
  - カード背景: white
  - 内部メモ背景: #FFF8E1（amber）・border: 2px dashed #F6AD55

レイアウト:
  - サイドバー: fixed, 220px, #1A365D
  - メインコンテンツ: margin-left: 220px
  - コンテナ: max-width 920px, white card, box-shadow
  - フォント: "Yu Gothic UI", "Hiragino Sans", "Meiryo"

必須サイドバー要素:
  - ロゴ（会社名）
  - 総合マニュアルへの戻りリンク: href="総合マニュアル.html"
  - 目次リンク（セクションアンカー）
  - 「Kaiの評価」セクションリンク
  - 「内部メモ」セクションリンク
```

**必須コンテンツ構成（9パート標準）:**
```
PART 1: フレームワーク概要
PART 2: 原因診断 / 適用判断
PART 3〜6: 推進プロセス・介入パターン・原則・抵抗対処法
PART 7: コンサルティング提案への活用
PART 8: Kaiの評価・成功ポイント・注意点・改善提案 ←必須
PART 9: 内部メモ（参照事例の詳細）🔒 ←必須
```

**PART 8（Kai評価）の必須要素:**
```
・総合評価スコア（実践性・汎用性・スケーラビリティ・コンサル転用可能性の4軸）
・特に有効な成功ポイント（箇条書き）
・注意点・リスク（warn ボックス）
・改善・追加提案（表形式）
```

**PART 9（内部メモ）の必須要素:**
```
・「このセクションは外部非公開」の明示
・元素材の組織属性（業種・規模・導入状況など）
・実施施策と結果の数値
・記憶に残るエピソード（定着を加速したエピソード等）
・Kaiの利用判断基準（どう使っていいか / いけないか）
```

**内部メモのHTMLスタイル（必ず使う）:**
```html
<div class="internal">
<span class="label">内容タイトル</span>
...
</div>
```
```css
.internal {
  background: #FFF8E1;
  padding: 22px 28px;
  border-radius: 8px;
  margin: 22px 0;
  border: 2px dashed #F6AD55;
  position: relative;
}
.internal::before {
  content: "🔒 内部参照用";
  position: absolute;
  top: -12px; left: 16px;
  background: #F6AD55;
  color: white;
  font-size: 11px; font-weight: bold;
  padding: 2px 10px; border-radius: 10px;
}
```

---

### STEP 6: 総合マニュアル連携

**対象ファイル:** `07_マニュアル/総合マニュアル.html`

**3箇所を必ず編集する:**

#### 編集箇所1: サイドバー（「📚 コンサル知識・事例」セクション）
```html
<a class="sb-link" href="<テーマ名>マニュアル.html" target="_blank">[テーマ表示名]↗</a>
```
※「📚 コンサル知識・事例」セクションが存在しない場合は新設する

#### 編集箇所2: 変更履歴テーブル
```html
<tr>
  <td>v[N+1]</td>
  <td>[YYYY-MM-DD]</td>
  <td>[テーマ名]マニュアル新設（knowledge MD + HTML + 内部メモ）。サイドバー「コンサル知識・事例」セクション追加。</td>
</tr>
```

#### 編集箇所3: knowledge MDのfrontmatterに連携先を記録
```markdown
**総合マニュアル連携:** `07_マニュアル/<テーマ名>マニュアル.html`
```

## 品質チェックリスト

### 著作権・識別可能性チェック
- [ ] 認識テスト通過（原作者が特定できない）
- [ ] verbatim copy がない
- [ ] 固有数値（特定組織の実績値）が外部公開版に混入していない
- [ ] 著者固有の命名・用語が外部公開版に残っていない

### knowledge MDチェック
- [ ] 7セクション構成が揃っているか
- [ ] 外部転用可能レベルで一般化されているか
- [ ] コンサル提案への活用セクションがあるか

### HTMLマニュアルチェック
- [ ] PART 8（Kai評価）が4軸スコア + 成功ポイント + 注意点 + 改善提案の構成になっているか
- [ ] PART 9（内部メモ）が `🔒 内部参照用` のスタイルで明示されているか
- [ ] 内部メモに「Kaiの利用判断基準」が書かれているか
- [ ] デザインが既存マニュアルと統一されているか（navy/#1A365D・orange/#ED8936）
- [ ] 総合マニュアルへの戻りリンクがサイドバーにあるか

### 連携チェック
- [ ] 総合マニュアルのサイドバーに追加したか
- [ ] 変更履歴に記録したか
- [ ] CLAUDE.mdのスキルテーブルに記録が必要か確認したか
