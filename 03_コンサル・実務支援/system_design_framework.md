# 制度設計支援フレームワーク

Ver 1.0 ／ 2026年5月作成
担当AI社員：策（さく）・改（かい）・渉（わたる）・律（りつ）

> AI導入・業務改善後に「誰が何をどう管理するか」を設計する。
> 仕組みを入れても「制度」がなければ定着しない。本フレームワークで制度を設計し、持続する組織を作る。

---

## 制度設計が必要なタイミング

```
以下に1つでも当てはまる場合、制度設計支援を提案する：

□ AI・ツールを導入したが、使う人と使わない人が分かれている
□ 誰がどの業務のオーナーか曖昧で、責任の所在が不明確
□ 同じ業務で担当者によってやり方がバラバラ
□ 改善策を入れても3ヶ月後には元に戻っている
□ 社員が「これは自分の仕事ではない」と言いやすい環境がある
□ 評価・フィードバックの仕組みがなく、改善行動が承認されない
```

## MODULE 1：役割・責任の明確化

### 1-A. 業務オーナー設計

各業務に「責任者（オーナー）」を1人だけ決める。

```
【業務オーナー設計表】

業務名      ：
オーナー    ：（役職・氏名）
オーナーの責務：
  ・この業務の品質に最終責任を持つ
  ・AIツール・マニュアルの更新を判断する
  ・問題発生時の一次対応を行う
  ・月次でKPIを報告する
副担当      ：（オーナー不在時の代理）
承認ライン  ：（誰が最終承認するか）
```

### 1-B. RACI マトリクス

各業務に対する関与の種類を明確化する。

```
R = Responsible（実行責任：実際にやる人）
A = Accountable（説明責任：最終的に責任を持つ人）
C = Consulted  （相談先：事前に意見を求める人）
I = Informed   （報告先：事後に情報共有する人）

業務名        担当者A 担当者B 管理職C 社長D AIツール
────────────────────────────────────────────
【業務1】       R       C       A       I      R（補助）
【業務2】       C       R       A       I      R（補助）
【業務3】       I       R       C       A      R（主体）
```

### 1-C. AIと人間の役割分担設計

```
【AI担当領域（自動化・補助）】
  ・定型フォーマットへの入力・作成
  ・情報の検索・要約・翻訳
  ・チェックリストの自動確認
  ・データ集計・グラフ化
  ・文章の下書き作成

【人間担当領域（判断・創造・関係）】
  ・最終承認・意思決定
  ・顧客・取引先との関係構築
  ・例外・イレギュラー対応
  ・倫理・法的判断
  ・チームのモチベーション管理

【境界線の設計ルール】
  「このアウトプットをそのまま使ってよいか、人間の目視確認が必要か」
  → 金銭・法律・顧客対応が絡む場合は必ず人間が確認する
```

```
【品質チェックポイント】
  □ ___
  □ ___

【よくあるミスと対処法】
  Q：___が上手くいかない時は？

【関連ドキュメント】

  日付      更新内容      更新者

```

### 2-B. SOPの優先作成順

```
以下の順で整備していく（改・教が担当）：

Priority 1：最も工数が多い業務のSOP
Priority 2：最も属人化が激しい業務のSOP
Priority 3：AIが主体的に担う業務のSOP（AIの使い方を標準化）
Priority 4：新人でも即対応できる必要がある業務のSOP
```

## MODULE 3：KPI・評価制度設計

### 3-A. KPI設計の4層モデル

```
Layer 1：経営KPI（社長が見る数字）
  → 売上、利益率、残業時間、外注費

Layer 2：部門KPI（管理職が見る数字）
  → 部門の業務時間、ミス件数、顧客満足度

Layer 3：業務KPI（担当者が見る数字）
  → 特定業務の所要時間、完了件数、品質スコア

Layer 4：AI活用KPI（AIマネージャーが見る数字）
  → AI使用頻度、自動化率、プロンプト精度（使用回数/成功回数）
```

### 3-B. KPI設定シート

```
【KPI設定シート】

対象業務/部門：
設定日      ：
次回見直し  ：（3ヶ月後）

No.  指標名          現状値  目標値  計測方法      計測頻度  担当者
──────────────────────────────────────────────────
1    月間業務時間     ___時間  ___時間  タイム記録   週次      ___
2    ミス・手戻り件数 ___件   ___件以下 ログ確認     月次      ___
3    AI活用率         0%      ____%    利用ログ     月次      ___
4    SOP遵守率        ____%   100%     チェックリスト 週次    ___
5    ___              ___     ___      ___          ___       ___
```

### 3-C. AI活用を「評価される行動」にする仕組み

```
【推奨：月次表彰制度（例）】

「AI活用改善賞」：AIを使って業務改善を提案・実行した社員を毎月1名表彰
→ 目的：「AIを使うことが評価される」文化を作る

【AIマネージャーの評価項目（例）】
  ・新しいAI活用ユースケースの提案数（月___件以上）
  ・他のスタッフへのAI活用サポート件数
  ・月次KPIレポートの提出（期日厳守）
  ・プロンプトの改善・標準化への貢献
```

## MODULE 4：ガバナンス・意思決定ルール

### 4-A. AI関連の意思決定権限表

| 意思決定の種類 | 決定者 | 相談先 | 期限 |
|-------------|--------|--------|------|
| 新しいAIツールの導入 | 経営者 | AIマネージャー | 要見積もり後 |
| 既存プロンプトの微調整 | AIマネージャー | — | 即日 |
| 業務フローの変更 | 業務オーナー | 関係者 | 1週間以内 |
| 外部データのAI入力 | 経営者 | 律（法務確認） | 要判断 |
| セキュリティ・個人情報の取扱変更 | 経営者 | 律 | 弁護士確認後 |
| AIアウトプットのそのままの使用 | 担当者（内容確認後） | — | 即日 |

### 4-B. エスカレーションルール

```
【AIトラブル時のエスカレーション】

Level 1：AIが期待通りの出力をしない
  → AIマネージャーがプロンプトを修正して対応
  → 解決しない場合：AS株式会社に相談（チャット）

Level 2：AIが明らかに誤った情報を出力した
  → 即座に使用中止
  → AIマネージャーが事実確認・修正
  → AS株式会社に報告

Level 3：AIを通じて機密情報が漏洩した可能性
  → 使用中止・AS株式会社と律（法務）に即連絡
  → リスク管理マニュアル（risk_management_manual.md）に従い対応

Level 4：法的・コンプライアンス上の問題が疑われる
  → AS株式会社・外部弁護士へ即エスカレーション
```

## MODULE 5：定着・持続化の仕組み

### 5-A. 月次ルーティン設計

```
【AI活用 月次ルーティン】

毎週月曜（AIマネージャー）：
  □ 今週の業務でAIを使う予定を確認
  □ 先週の課題・改善点を1つピックアップ

毎月第1週（AIマネージャー）：
  □ 月次KPIを集計してレポート作成
  □ 「今月のAI活用ハイライト」を1件記録

毎月第2週（経営者 + AIマネージャー）：
  □ 月次レポートのレビュー（30分）
  □ 翌月の重点テーマを決定

毎月第4週（AS株式会社との面談）：
  □ 進捗確認・改善提案
  □ 新しいAI活用アイデアの共有

四半期（経営者 + AS株式会社）：
  □ ROI確認・KPI見直し
  □ 次の3ヶ月計画の策定
```

### 5-B. ナレッジ資産の蓄積ルール

```
【蓄積すべきナレッジ】
  1. 使えたプロンプト（業務名・効果・コメント付きで保存）
  2. よくあるミス・失敗パターンと解決法
  3. 業務改善の成功事例（数値付き）
  4. スタッフの「AIを使ったアイデア」提案ログ

【保存場所と管理ルール】
  保存先：（Googleドライブ/Notion/共有フォルダ等 → 顧客環境に合わせて決定）
  更新担当：AIマネージャー
  更新頻度：週1回
  整理担当：月1回、教（きょう）が棚卸し支援

【廃棄・アーカイブルール】
  3ヶ月以上使われていないプロンプトはアーカイブへ移動
  ツール廃止時は関連ドキュメントを全てアーカイブ
```

## 制度設計 完了チェックリスト

```
【MODULE 1：役割・責任】
□ 主要業務（5業務以上）の業務オーナーが決定済み
□ RACIマトリクスが作成済み
□ AI担当領域と人間担当領域の境界線が合意済み

【MODULE 2：SOP】
□ Priority 1の業務のSOPが完成・共有済み
□ SOP更新の運用ルールが決まっている

【MODULE 3：KPI・評価】
□ 経営KPI・業務KPIが設定済み
□ AI活用KPIが設定済み
□ 月次計測の担当者と方法が決まっている

【MODULE 4：ガバナンス】
□ AI意思決定権限表が承認済み
□ エスカレーションルールが全スタッフに共有済み

【MODULE 5：定着】
□ 月次ルーティンが組み込まれている
□ ナレッジ蓄積の場所・ルールが決まっている
```

| M4 ガバナンス設計 | 律 | 策・守 | 意思決定権限表・エスカレルール |
