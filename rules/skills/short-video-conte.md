# /short-video-conte スキル
**ショート動画（60〜180秒・縦型）の型を抽出・命名・ライブラリ化／適用するメタスキル**

**用途：** 既存のショート動画（mp4等）から「コンテのDNA（構造・比率・設計）」を抽出してパターン化し、任意のテーマ・ターゲットで同じ型のショート動画コンテプロットを再現する。

**保存先：**
- パターン定義：`rules/short-video-patterns/<パターン名>.md`
- パターン一覧：`rules/short-video-patterns/INDEX.md`
- 抽出時の中間成果物：`08_アプリ開発事業部/outputs/short-video-conte/<元動画名>/`

---

## 設計哲学

> **ショート動画の「効き」は偶然ではなく型に宿る。型を言語化すれば、テーマが変わっても同じ吸引力・証明力・回遊導線が再現できる。**

- 文体・構成・比率は著作権の対象外。構造の抽出・再設計は合法
- 「何を話すか」ではなく「どう設計するか」を型として保存する
- 1つのパターンから複数のテーマ・ターゲット向けショート動画を量産できる
- 動画は **音声OFF＋途中入り** でも理解できる設計が必須

---

## 情報保護ルール（全モード共通）

**素材を読み込んだ後、パターンファイルに以下を記録しない：**

| 禁止事項 | 理由 |
|---|---|
| 出演者名・運営者名 | 情報元の特定リスク |
| 元動画のタイトル・URL | 同上 |
| 出演者の口癖・固有の言い回し（一字一句） | 著作権的保護対象に近い |
| 元動画の具体的事例・企業名・数値 | 転用元として特定される |

**記録してよいのは：** 構造・比率・配分・テンプレ的言葉のパターン・画面レイアウトの設計原則のみ。

---

## 3つのモード

| モード | 呼び出し方 | 用途 |
|---|---|---|
| `browse` | `/short-video-conte`（引数なし）／「パターン一覧」「どんな型がある」等 | 蓄積パターンを一覧表示し推薦 |
| `extract` | `/short-video-conte extract <動画パス>` | 動画からDNAを抽出して命名・保存 |
| `apply` | `/short-video-conte apply <パターン名>` | 保存パターンで新コンテプロットを生成 |

### STEP B1：パターン一覧を読み込み

```
Read rules/short-video-patterns/INDEX.md
```

### STEP B2：表示と推薦

```
[ショート動画パターン一覧]

■ DNA型パターン
  No. | パターン名               | 得意テーマ       | 得意ターゲット   | 動画長
  ----|-------------------------|-----------------|-----------------|-------
   1  | 逆説フック・実演証明型   | ツール訴求      | 時間追われ層    | 60-90秒
```

## extractモード（型を抽出して保存）

### 前提：必要な環境

| ツール | 用途 | 入れ方 |
|---|---|---|
| **ffmpeg** | フレーム抽出・音声抽出 | `winget install Gyan.FFmpeg`（無料・OSS） |
| **faster-whisper** | ナレーション文字起こし | `pip install faster-whisper`（無料・OSS） |

※ Python 3.14 では httpx の問題で faster-whisper のモデルDLが失敗する場合がある。Python 3.11 を別途用意するのが安全。

### STEP E0：重複チェック（必須 — extract開始前に毎回実行）

> **背景：** 情報保護ルールでパターンファイルに登壇者名・固有事例を記録しないため、**ファイル名や登壇者名でGrepしても重複は見つからない**。必ずメタ情報＋構造特徴で照合する。

**手順：**

1. `rules/short-video-patterns/INDEX.md` を Read する
2. 動画について以下のメタ情報を取得：
   - ファイルmtime（素材の作成日）
   - 動画長（ffprobeで秒数）
   - 縦型／横型
   - 想定プラットフォーム（Reels／Shorts／TikTok）
   - テーマ領域
3. INDEX.md各行と **目視で順次照合**
4. 候補がヒットした場合、該当パターンファイルのメタ情報も確認

**判定と対応：**

| 状況 | 対応 |
|---|---|
| **完全一致** | extract中止。「既に『〇〇型』として登録済みです」と案内 |
| **同じ素材だが別観点**で抽出可能 | ユーザーに「既存パターンへの追記」vs「別パターンとして新規登録」を選択させる |
| **似ているが別素材** | extract 続行。命名時に既存との差分明記 |
| **完全に新規** | 通常通り extract 続行 |

**他スキルとの相互チェック：** 同じ素材から `/long-video-conte` や `/seminar-dna` でも抽出されている可能性を必ず確認する。それぞれのINDEX.mdも照合する。

このSTEP E0を経ずにSTEP E1へ進むことは禁止。

### STEP E-final：内部メタ記録（必須）

extract完了後、必ず以下を実行：

1. `rules/_internal_source_meta/PROTOCOL.md` に従ってメタファイル作成（タイプA：動画／音声テンプレ使用）
2. `rules/_internal_source_meta/INDEX.md` の横断一覧表に新行追加
3. 自己チェック：パターンファイル等の外部配布層から内部メタへの参照が含まれていないこと

詳細は CLAUDE.md「外部素材取り込み時の内部メタ記録プロトコル」セクション参照。

---

### STEP E1：動画情報の取得とフレーム抽出

```bash
# 1. メタ情報取得
ffprobe -v error -show_entries stream=codec_type,width,height,r_frame_rate \
  -show_entries format=duration -of default=noprint_wrappers=0 "<動画パス>"

# 2. 作業ディレクトリ作成
mkdir -p "08_アプリ開発事業部/outputs/short-video-conte/<元動画名>/{frames,audio,transcript}"

# 3. 音声抽出（16kHz mono / whisper用）
ffmpeg -y -i "<動画パス>" -vn -ac 1 -ar 16000 -acodec pcm_s16le \
  "08_アプリ開発事業部/outputs/short-video-conte/<元動画名>/audio/audio.wav"

# 4. フレーム抽出（2秒に1枚・縦540pxスケール）
ffmpeg -y -i "<動画パス>" -vf "fps=1/2,scale=540:-1" \
  "08_アプリ開発事業部/outputs/short-video-conte/<元動画名>/frames/t%03d.png"
```

**フレーム粒度の判断：**
- 60〜180秒のショート動画 → 2秒/枚（30〜90枚）が標準
- ナレ字幕が1秒ごとに切り替わる動画 → 1秒/枚に細粒化

### STEP E2：ナレーション書き起こし

```bash
py 08_アプリ開発事業部/outputs/short-video-conte/transcribe.py
```

スクリプトは `transcript/transcript.md`・`transcript.json`・`transcript.srt` を出力する（テンプレ：`08_アプリ開発事業部/outputs/short-video-conte/transcribe.py`）。

**Whisperが使えない時のフォールバック：**
画像内の白字キャプション（ナレ字幕）を視覚的に読み取って代用する。元動画によっては全ナレが字幕化されているので、この方法でも十分に構造把握できる。

### STEP E3：シーン別タイムライン作成

各フレームを順番に読んで、以下の表を作る：

| # | 秒 | フレーム | 画（メインビジュアル） | 字（キャプション） | 役（ストーリー上の役割） |
|---|---|---|---|---|---|

### STEP E4：構造分析（DNA抽出）

以下の観点で分析する：

1. **マクロ構造**：何パートに分かれているか？各パートの秒数と割合は？
2. **画面構成**：固定UI層は何層か？テキスト帯はどう配置されているか？
3. **言葉のDNA**：フック／キラーワード／CTAのテンプレ型は何か？
4. **ビジュアル配分**：顔出し／PC画面／図解／トランジションの比率は？
5. **カット切替リズム**：平均何秒／カットか？
6. **ハッシュタグDNA**：どの順番で並んでいるか？

### STEP E5：パターン命名と保存

パターン名は **「効き方」が一目で分かる4〜10文字** にする。
- 例：「逆説フック・実演証明型」「ストーリー共感型」「データドリブン解説型」「失敗談カミングアウト型」

保存：
```
rules/short-video-patterns/<パターン名>.md
```

`rules/short-video-patterns/INDEX.md` のテーブルに1行追加する。

### STEP E6：パターンの再現スイッチ定義

`apply` 時にユーザーに尋ねるべきスロットを明示する：
- 必須：対象ツール／対象機能／Before業務／Before所要時間／After所要時間／ターゲット層
- 任意：動画長／キラーワード候補

## applyモード（型で新コンテプロットを生成）

### STEP A1：パターン読み込み

```
Read rules/short-video-patterns/<パターン名>.md
```

### STEP A2：再現スイッチのヒアリング

パターンの「再現スイッチ」セクションに従って、必須スロットを順番にヒアリング。

```
[applyモード：<パターン名>]

このパターンを動かすために、以下を教えてください：

1. 対象ツール／機能（例：Claude Code Skills機能）
2. Before業務（例：月次レポート作成）
3. Before所要時間（例：2時間）
4. After所要時間（例：30秒）
5. ターゲット層（例：中小企業の経理担当者）

任意：
6. 動画長（既定：77秒）
7. キラーワード（既定：「全部自動です」「これで回るようになったら」）
```

### STEP A3：コンテプロット生成

パターンの **マクロ構造（パート配分）× 画面構成（5層UI）× 言葉のDNA × ビジュアル配分** をテンプレ的に適用して、以下を生成：

1. **シーン別タイムライン**：各2秒ごとに「画／字／役」を埋めた表
2. **撮影指示書**：顔出し撮影が必要なカット／PC画面録画が必要なカット／図解作成が必要なカット
3. **テロップ原稿**：固定タイトル／固定要約／固定CTA／ナレ字幕（時間軸付き）
4. **ナレ台本**：各シーンで話すべき内容（です・ます調・Kaiの文体ルール準拠）
5. **ハッシュタグ案**：パターンDNAに沿った並び

出力先：`08_アプリ開発事業部/outputs/short-video-conte/<新企画名>/conte_plot.md`

### STEP A4：撮影前チェックリスト

- [ ] フックは **3秒以内** に強烈否定or数値対比を提示できているか
- [ ] Before痛みパートで **共感ポイント** が明確か
- [ ] After実演で **数値や画面変化** が一目で分かるか
- [ ] **音声OFF＋途中入り** でも理解できるテロップ設計か
- [ ] CTAが **最終10秒** に確実に入っているか
