# /stakeholder スキル

**用途:** 意思決定に関わるステークホルダーを「影響力×関心度」マトリクスで整理し、誰を・いつ・どう動かすかの攻略シナリオを設計する。

> 提案が論理的に正しくても、動かすべき人を間違えると通らない。このスキルは「誰に何をどう伝えるか」を設計する。

---

## 発動条件

ユーザーが `/stakeholder` を入力したとき、または以下の依頼があったとき：

- 「誰を説得すればいいか整理したい」
- 「社内のキーパーソンを特定したい」
- 「提案を通すための根回し順序を考えたい」
- 「反対しそうな人を想定したい」「抵抗勢力への対応策が欲しい」
- 「クライアント側の意思決定構造を整理したい」

---

## 入力情報（1回で聞く）

```
ステークホルダー分析を行います。以下を教えてください。

1. 何を通したい・決めたいか
   （例：AI導入の承認、新規予算の獲得、組織変更の実施）

2. 関係する人物・部署（わかる範囲で）
   （例：社長、経理部長、現場リーダー、IT担当、外部顧客）

3. 各人の立場・役割（わかれば）

4. 現時点での各人の反応（支持・中立・反対・未確認）

5. 意思決定のプロセス
   （例：最終決裁は社長、稟議は部長承認が必要）
```

---

## フロー

### STEP 1：ステークホルダーマップの作成

```
【ステークホルダーマップ】

         影響力：高
              │
      A象限   │   B象限
  （懐柔型）  │  （最重要）
─────────────┼─────────────
  （無視型）  │  （情報提供型）
      D象限   │   C象限
              │
         影響力：低
     関心度：低      関心度：高

【配置結果】
B（最重要・高影響力×高関心度）：〇〇さん、〇〇部長
A（懐柔型・高影響力×低関心度）：〇〇さん
C（情報提供型・低影響力×高関心度）：〇〇さん
D（モニタリング・低影響力×低関心度）：〇〇さん
```

---

### STEP 2：個人別プロファイル

主要ステークホルダー（B象限・A象限）について詳細プロファイルを作成する。

```
【〇〇さんのプロファイル】

立場・役割：〇〇
現在のスタンス：支持 / 中立 / 反対 / 未確認
影響力の源泉：決裁権 / 予算権 / 情報網 / 現場信頼
関心事項：〇〇（何が実現されると喜ぶか）
懸念事項：〇〇（何を不安・嫌だと思っているか）
動機づけのポイント：〇〇（この言葉・数字が刺さる）
リスク：この人が反対に回った場合の影響
```

---

### STEP 3：抵抗シナリオの想定

```
【抵抗シナリオ】

抵抗源①：〇〇さん（部門：〇〇）
  想定される反対理由：〇〇
  反論の形：「〇〇という懸念がある」
  対応策：〇〇を先に解消する / 〇〇の実績を先に示す
  放置した場合のリスク：〇〇

抵抗源②：〇〇さん
  （同形式）
```

---

### STEP 4：攻略シナリオ（動かす順序と方法）

```
【攻略シナリオ】

フェーズ1（〇週間前）：地ならし
  対象：C象限の支持者
  アクション：情報共有・共感の醸成
  目的：味方を増やして「空気」を作る

フェーズ2（〇週間前）：根回し
  対象：A象限のキーパーソン
  アクション：1対1での個別説明・懸念の先取り
  ポイント：「決定の場」で初めて話さない

フェーズ3（決定の場）：B象限の意思決定者へ提案
  対象：B象限の最終決裁者
  アクション：根回し済みの空気の中で提案
  準備：反対意見への回答を事前に用意

フェーズ4（承認後）：D象限への周知
  対象：D象限（広報・周知）
  アクション：決定事項の共有・協力依頼
```

---

### STEP 5：コミュニケーション設計

```
【ステークホルダー別メッセージ設計】

〇〇さん（最重要・決裁者）へのメッセージ：
  刺さるフレーミング：「コスト削減」ではなく「競争力強化」
  使う数字：〇〇万円/年の効果、ROI〇ヶ月
  避ける言葉：〇〇（この人が嫌う表現）

〇〇さん（反対派）へのメッセージ：
  先取りする懸念：「〇〇が心配だと思いますが…」
  提示する安心材料：〇〇の実績・段階的導入の提案
```

## 他スキルとの連携

- **`/marketing`** — BtoB営業・提案時の意思決定者分析に使える
- **`/talk-script`** — ステークホルダーごとにトーンを変えたトーク台本を作る
