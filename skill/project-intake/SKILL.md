# プロジェクトインテーク（受付）スキル

## 目的

オーナーが「どのスキルを呼ぶか」を意識せずに話しかけても、
依頼を正しく解釈して適切なスキル・アクションに繋ぐ。

---

## 起動条件

- スキルコマンド（`/sme-ai-proposal` 等）を使わず、自然な言葉で依頼してきた時
- 「何から始めたらいい？」「◯◯の件どうすればいい？」という相談
- 複数の作業が絡む依頼（例：「新しい案件の提案書を作ってURLで送りたい」）

---

## 処理フロー

### Step 1. 依頼の解釈

受け取った依頼を以下の軸で分類する。

| 軸 | 確認ポイント |
|----|------------|
| 対象 | 既存案件か・新規案件か・自社コンテンツか |
| アクション | 生成・修正・公開・確認・その他 |
| 緊急度 | 「今日中」「急いで」などの言及があるか |
| 不足情報 | Knowledgeの有無・クライアント名・バージョン指定 |

### Step 2. ルーティング判断

| 依頼の内容 | ルーティング先 |
|-----------|--------------|
| 提案書を新規作成したい | `Knowledge/` の確認 → `/sme-ai-proposal` |
| 提案書を修正・更新したい | 既存 HTML の確認 → `/sme-ai-proposal`（修正モード） |
| 提案書を公開・URLを送りたい | `/publish-proposal` |
| Brain記事を書きたい | 参考記事の確認 → `/write-brain-article` |
| マニュアル・ガイドを作りたい | `/beginner-guide` |
| AIニュースを整理したい | `/ai-news-digest` |
| 複数の作業が連続する | 順番を提示してオーナーに確認後、順次実行 |

### Step 3. 不足情報の確認

不足情報がある場合は作業を始める前に1〜2問だけ確認する。  
まとめて全部聞かない。最重要な情報だけ聞く。

### Step 4. 実行または引き渡し

- 単一スキルで完結する場合：その場で実行
- 複数ステップの場合：「①→②→③の順で進めます。始めていいですか？」と確認してから実行

---

## ルーティング後の確認文例

```
依頼を整理しました。

【やること】
①〔やること1〕
②〔やること2〕

【確認が必要なこと】
- 〔不足情報〕はありますか？

始めていいですか？
```

---

## 注意事項

- このスキル自身は成果物を生成しない。あくまで受付と整理
- 憲法（`rules/CONSTITUTION.md`）の判断権限マトリクスに従う
- 不明な場合は推測で進めず、選択肢を提示してオーナーに選ばせる
